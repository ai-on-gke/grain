# Shared capability broker protocol

**Status:** proposed, normative documentation; not implemented. No runtime, permission, deployment, configuration, automatic proposal or task migration is authorized.

**Specifies:** [shared capability interactions](../../design/capability-broker.design.md). BCP 14 keywords apply. `CB-*` requirements are stable. Validate [wire.schema.json](wire.schema.json) and [operations.schema.json](operations.schema.json), then the semantic rules below. A shape-valid message is not authority.

## CB-1: Binding, discovery and exact names {#CB-1}

1. The single orchestration MCP tool name is **`grain_handle_v1`**. Its `tools/list` entry MUST have `inputSchema["x-grain-broker"]` validating as `$defs.discovery`. The annotation contains protocol `grain.broker/1.0`, transport `grain_rounds`, catalogue revision/digest and named operation descriptors. There is no `handle`, reverse `tools/call`, provider-to-Grain connection or callback endpoint. Grain calls this tool over the configured capability session and placement, repeatedly if required. Existing `servers.Registry.CallTool` is the intended caller boundary.
2. A descriptor has `name,version,profile,args_schema,input_schema,output_schema,back_calls,replay_safe`. Each schema is a locally resolved object plus its SHA-256 digest. Profile is `general`, `gate`, `resource`, or `trigger`. Names match the schema grammar and MUST be unique by name/version. Named operations remain discoverable even though their execution uses a shared handle. Grain MUST generate/validate the handle's request `oneOf` branches for the finite catalogue, binding each operation name/version to its typed args, input and final output schemas. An untyped `args:{}` dispatcher MUST NOT be admitted. Arguments use the capability argument-schema subset/defaulting; the envelope uses JSON Schema 2020-12. No remote schema resolution or provider-selected dispatch target.
3. The catalogue is server-wide, not a grant. Descriptor `back_calls` lists operation/version pairs from the Grain-owned registry. Effective authority is the intersection of caller/delegation, profile, installed server policy, invocation scope, operation adapter and current resource policy. Unknown name/version/schema/pin MUST fail closed before invocation or execution. Discovery never attaches a requirement, subscribes, mints a grant or approves work. Descriptor and registry digests MUST cover resolved local schemas, adapter/artifact/configuration pins and authorization rules using RFC 8785 canonical JSON and SHA-256. Verify artifacts against the approved installation, not a provider-claimed hash.
4. `mint_<method>`, `release_<method>` and `configure` retain their exact existing capability meanings and wire forms. They MUST NOT be run through this broker or interpreted as back-call operations. Adding `grain_handle_v1` does not add a mint method or per-attempt endpoint. Existing agent MCP tools remain named, typed tools, optionally wrapped by SDK `grain.call(name,args)` using an authorized controller entry point. This document adds no public entry point or credential.
5. Proposed named operations reuse `gate_<method>` for gate evaluation, `resource_<method>_{resolve,observe,watch}_v1` for resource profiles, and `event_{open,read,reconcile,close}` for event acquisition when wrapped. On a negotiated broker installation those are catalogue names carried in `operation`, not recursively called MCP tools. Direct resource/event v1 acquisition can continue unchanged; advertising a broker does not silently reroute it. Each direct-to-broker adapter MUST pin domain input/output schema versions. A server can also advertise a specific general operation such as `change_prepare_v1`, with a registered typed descriptor; names alone grant nothing.
6. MCP `tools/call.arguments` is `$defs.request`. Successful MCP results carry `$defs.response` in `structuredContent`; for compatibility with the current client a single text content item MAY carry exactly that JSON when structured content is absent. If both exist they MUST be equal JSON values. No additional text/image/resource block is authoritative. JSON-RPC/HTTP/parse/`isError` failures are transport failures, never broker finals. Bound before parsing. MCP JSON-RPC IDs are transport-local and may change on retransmission; they are not invocation/call IDs.

## CB-2: Context, authority and lifecycle {#CB-2}

1. Grain MUST generate `invocation_id` and opaque `context` (at least 128 random bits); the latter is a lookup token only on the authenticated selected server connection, never a standalone bearer credential or externally dereferenced URL. Contexts are server-wide in protocol availability and invocation-scoped in authority. Provider replies MUST echo context and invocation identity; no response may replace them. Grain MUST derive the actor, task, attempt and policy from authenticated entry/binding state, never provider arguments or headers copied from a response.
2. The private durable context record MUST bind: deployment/installation and recovery epoch; canonical configured server ID, approved artifact/catalogue/registry digests, configuration/credential epochs and placement/process generation; invocation/name/version/profile and canonical args/input digest; acting task/attempt or explicit taskless purpose; actor, on-behalf-of identity and exact delegation chain; operation/resource/repository/field scope; policy, contract, binding and authorization revisions; creation/expiry/deadline; effective limits, counters and cancellation state; owner lease/fence and evidence context. Scope selectors are registry-validated bounded IDs/sets, never arbitrary expressions. The provider receives only opaque context plus authorized typed input and effective limits; the private record MUST NOT be serialized as credentials.
3. Task-relevant calls default to their acting task. Related-task reads need an explicit permitted relationship/target and current read authority, including existence/status. Providers cannot select another acting task, principal, grant, placement, adapter, endpoint or permission set. A read argument's `task_id` is a constrained target expectation, not an acting identity. Agent-wide grants MUST NOT be inherited wholesale. Delegation is non-transitive by default; further delegation requires an explicit narrowed chain and expiry, with no self-grants or approval escalation. This protocol does not implement a grant-management operation.
4. Authority MUST be rechecked before every outbound delivery and every back-call, at mutation commit/dispatch, and at final acceptance. Revocation, expiry, task/attempt termination where applicable, server/pin removal, or changed policy fences cancel the invocation and all unstarted intents. Previously delivered bytes cannot be recalled. Providers MUST discard invocation evidence/continuation at expiry/cancel and MUST NOT reuse it across contexts. Required gates remain required and unknown when reads are unavailable. Restored authority requires a new context, not resurrection of an old one.
5. Default task general contexts expire with the attempt or invocation, whichever is earlier. Taskless action guards bind the canonical action/resource through AGB-3, not a synthetic task. Resource Resolve/Observe/Watch contexts derive from the independently authorized TDS controller grant/lease, partition, recovery epoch and generation. Closing an attempt MUST NOT release a still-authorized standing controller; keeping the MCP process alive MUST NOT renew its lease. Trigger contexts bind event identity, match/filing identity, binding/template revision, owner/service and current standing filing authority; task may be absent. Acquisition authorization and filing authorization remain distinct.
6. Owner leases are five seconds, renewed every second and fenced by a monotonically increasing epoch. All invocation checkpoint/final writes check owner/fence/DB expiry. No network call holds a database transaction. Server restart/placement handoff requires installed identity/pin verification and a new process generation. Grain may rebind the same durable invocation only through an audited fenced handoff with unchanged approved artifact/config/authority and replay-safe descriptor. Context bytes remain unchanged for exact replay; the private record records both generations. Pin/config/credential changes abort; placement is never an implicit grant. Backup restore changes recovery epoch, holds effects, reauthorizes and reconciles surviving receipts before replay.

[registry.json](registry.json) is the documentation catalogue, including explicit unimplemented adapter blockers; it is not a deployed allowlist. Admission MUST replace pending adapters with verified installed pins and registered rules, not treat nulls as wildcard values. There MUST be one registry shared with the AGB action registry, not an alternate path for protected effects.

## CB-4: Exact interaction state machine {#CB-4}

`wire.schema.json` defines closed request, non-final, final, result, error, discovery, receipt and context-record shapes. Its request root is the common structural envelope; catalogue schema validation is additionally mandatory. All nullable fields are present. Byte/depth limits are independent of character-count schema limits.

1. Grain durably creates context and canonical round 0 request before sending. `operation`, version, typed `args` and profile `input` remain identical throughout. Round 0 has null continuation/previous-response digest and empty results. Each request has fixed `now`/deadline and `request_digest = SHA256(RFC8785(request without request_digest))`. The response echoes protocol, invocation/context, round and request digest. `previous_response_digest` hashes the entire prior accepted response. Opaque continuation is transient bounded provider data, echoed exactly into the next request, never authority/evidence or durable gate state.
2. `kind=requests` has 1..8 calls and continuation, with no output/state/actions. Every call has invocation-unique `call_id`, operation/version, exact typed args, `depends_on` and nullable `idempotency_key`. Read keys MUST be null; mutation keys MUST be non-null. A mutation key is a provider-proposed stable logical slot only: Grain namespaces it to authority/operation/target and verifies it against any domain key. Reusing a key with different canonical inputs is `conflict`, never a fresh effect. Cross-invocation mutation recovery is only through a controller-retained domain intent/receipt, not arbitrary provider key reuse.
3. Dependency IDs MUST reference earlier calls in that batch or previous completed calls, forming a DAG; reject unknown/forward/cyclic/duplicate IDs before executing any batch member. No implicit array-order dependency. Execute independent reads concurrently if useful; serialize mutations in listed order under deterministic target locks. Calls depending on a failed/uncertain call receive `dependency_failed`. Typed args cannot contain JSONPath/result substitutions. If an attachment needs a returned-resource handle, it must wait for a later round. Batches are not atomic transactions: each committed mutation survives another member's failure.
4. Grain validates the **whole batch's structure, declared operations and budget reservations** before effects. Then authorize each call immediately before its execution; an individually denied read returns a safe error, while unrelated valid reads can proceed. Persist requests, execution intents and exact results/dependencies before next transmission. Results are in request order and echo the entire call. All requests receive exactly one terminal result or the invocation aborts with outstanding intent reconciliation; final acceptance requires no outstanding/uncertain calls. Partial results MUST NOT be invented after a crash.
5. One response per round wins a unique insertion. Exact retransmission returns the same response for the same canonical request. Provider replay safety is mandatory for admission: handle execution itself cannot perform unreceipted side effects. General effects run through broker mutation calls, not hidden provider external writes. A provider that creates PRs privately without the durable effect adapter cannot advertise replay safety. Differing duplicate replies abort with `invalid_result`; late conflicting replies after acceptance quarantine future use, retain committed receipts and follow explicit regression policy, never silently undo history.
6. A structurally valid final has either `outcome=ok,output=<typed output>,error=null` or `outcome=error,output=null,error=<error>`, plus ordered `acknowledged_calls` containing exactly all delivered call IDs and `evidence_receipt` echoing the current Grain-generated dependency-ledger digest from the request. Provider citations cannot narrow the ledger. Grain revalidates context/deadline/owner/pins, typed output, acknowledgments, complete mandatory evidence, current read dependencies and profile preconditions before unique final commit. Final error has no gate state/lifecycle effect; mutation receipts remain. A successful general final records output/receipts, not task completion.
7. Error codes are enumerated in the schema. Denial uses `denied` with generic safe message, no existence/private-data distinction. `revoked` terminates and prevents further delivery. `stale_evidence` or `conflict` requires a fresh authorized decision/precondition, not a blind same-round write retry. `uncertain` exposes an effect intent awaiting reconciliation, never a failure assertion that authorizes duplication. Transport failures are recorded separately as `unavailable`/`timeout`; only eligible exact replay is allowed. Explanations are bounded/redacted; no raw upstream response, secrets or inaccessible IDs.

## CB-5: Effects, guards and durable receipts {#CB-5}

1. Registry mutation admission MUST bind current preconditions (task/contract/reference version, exact head/resource version, policy and authorization epochs), effect classification, confirmation/human-only rails and lock domains. Grain derives targets from context plus validated args/returned-resource handle. Gate/profile read-only checks are enforced in Grain and the adapter credentials/path, regardless of MCP hints.
2. Use the existing authorized domain service below the API/MCP presentation where practical, with an authenticated narrowed actor/delegation context. Never call a privileged model function solely because it is in-process. Preserve route/agent rails explicitly; `arguments.expect` in current MCP is a useful expectation check but is not a transactional write fence. Add CAS/resource locks and current authority checks in the actual committing service.
3. Before external writes, persist a unique intent keyed by context/domain identity, canonical args digest, actor and expected versions; acquire shared resource/effect locks and fenced lease. Revalidate permission/policy/resource state before dispatch. Persist outbox state and eventual immutable receipt. Do not hold a DB transaction across a provider call. Use upstream idempotency/conditional writes where available; otherwise reconcile by stable resource identity/open-or-find semantics before retry. If an upstream cannot support safe conditional execution or bounded reconciliation, keep the effect unsupported or held unknown. A local lock alone cannot enforce remote exact-head semantics.
4. Before a successful result is sent, persist a receipt with server/artifact/invocation/call, actor/delegation, task/attempt or binding/event, operation/version, canonical request digest, preconditions/policy, resource identity/versions, disposition/time and immutable evidence. This receipt and local evidence invalidation/outbox must commit atomically. Provider failure after commit does not roll back success. Do not repeat or compensate an external operation merely because final fails; compensation needs separate explicit authority. Receipt reads still require current read authorization.
5. `resource.attach` creates a relation using exactly the agent/UI TDS authority and expected-contract checks. A returned handle is minted only by Grain from an authenticated committed result or validated resource-profile Resolve output and is bound to context/installation/partition/expiry. It is not an arbitrary URL. Resolve under the explicit read grant, validate reference and tracking, and record task-local relation/observation obligations separately. A role such as `output` or `evidence` is not `required`. Attaching a PR/workspace/bug neither expands access nor modifies completion gates. When the existing opener already links the PR, attach must reconcile/upsert the same relation under its own key, not duplicate it or infer a new required outcome.
6. `task.create_from_trigger` delegates to the TTS filing transaction, not a second broker receipt transaction around a public POST. The TTS filing key remains authoritative across invocation/round/restart/binding versions. With Task #49's terminology: `(binding_id,dedup_lineage,E,slot_id,replay_epoch)` identifies F. Under a fenced match and binding/repeat/quota locks, recheck enabled/current authority, pinned template/security envelope, head/request freshness, allowed repo/capabilities/admission, quota and loop budget; compose once, insert/CAS task then filing receipt then immutable origin/attachment and dispatch outbox in one transaction. The broker result references that receipt. Retrieval of an existing receipt after disable/revoke is read-only and authorized; it never grants dispatch.
7. Protected actions, including merge/submit/deploy/publish, MUST traverse the AGB-1/2/4/5 central executor regardless of caller/tool spelling. A broker operation cannot bypass inherited policy lookup, explicit unguarded coverage, exact-head guard/approval applicability, current authorization, shared locks, execution permits, conditional source write or reconciliation. Initial registry includes no such executor operation. Gate `action_requests` are proposals only, passed to arbitration after accepted final, never executed from non-final requests.

## CB-6: Evidence and decision consistency {#CB-6}

1. Grain creates an invocation evidence context with core fences (task/contract/authority/policy, server/config/credential/recovery/permission revisions, bound action resource/head, relevant message watermarks/journal cursor). Predicate/guard registry computes mandatory input requirements from approved args/policy before invocation. It MUST NOT require all task data by default or rely on provider-selected citations. Missing required input is unknown, not false/met.
2. Each read uses a bounded committed projection in a short store transaction, capturing record versions, collection membership generation, normalized scope/ordering, subject/head, dirty/covered generations, authorization/source pins, collection time and validity. Grain automatically records these dependencies, including successful empty/negative reads and controller inline prerequisites, before delivery. Adapters must capture version metadata with values, not by an unprotected later lookup. Versions must change on ABA, additions/removals, applicability and permission changes. A generic `version` string is equality-only unless explicitly specified otherwise.
3. The first read latches each collection generation. All later pages/repeated reads of that scope must match or return stale; mixed live reads cannot silently replace older values. Cursor binds context/server/partition/operation/scope args excluding cursor/limit, ordering, generation and expiry. Complete/empty coverage is explicit; empty records alone prove nothing. Cursor expiry or upstream inability to establish membership invalidates negative claims. Required set completeness comes from trusted adapter/predicate validation, not provider `complete=true`. One collection's next page per round; independent collections may batch. No truncation interpreted as success.
4. Read pages use Task #56's typed `read_page`, with read_id equal to shared call_id. Registry checks each record's typed data and operation-specific kind. Generic record data is never an unvalidated extension. Source scope and authorization must match context, and pagination covers fixed collection membership/order. A bounded immutable capture is allowed for an adapter unable to supply stable generations, with documented transaction/coverage/byte/freshness bounds and live invalidation dependencies; universal full task snapshots are not required.
5. Grain MUST validate the union of every captured dependency plus mandatory requirements in a single decision transaction before accepting a gate/decision, including all required guard evaluators. No changed version, dirty>covered source, expiry, denied prerequisite, head/policy/authority change or incomplete required set may authorize met/action/closure. Immediately before action or closure, revalidate the stored dependency receipt and relevant current fences. Closure also settles/fences writers/operations and CASes incoming/processed message watermarks and required child outcomes. Only Grain advances processed-message watermark from actual delivery/disposition; reading messages does not process them.
6. General mutation invocations may advance evidence revisions. Their already committed receipts and mutations remain valid history; dependent reads/decisions are invalidated and must be refreshed under new generations. A new read phase in that invocation can replace a superseded read only with an explicit controller-recorded evidence epoch transition, invalidating *all* prior decision dependencies/results for affected scopes; it cannot retroactively make an old gate final current. If this cannot be proved within bounds, end stale and start a new authorized invocation. Gates themselves cannot mutate to reach a preferred answer.
7. Dependency validation provides a consistent **Grain-recorded** cut, not an atomic view of independent external services. Record actual source collection time, min(provider validity, policy age budget), remote gaps and source limitations. A hint never extends freshness. A live source read without trustworthy versions/freshness can be advisory or explicitly unavailable for a required predicate. Negative evidence requires collection coverage and freshness. Keep remote conditional writes and current authorization even after all local checks pass. Later-discovered regressions follow explicit notification/reopen policy, never an invented zero-race guarantee.

## CB-7: Limits, cancellation, retries and crash recovery {#CB-7}

All limits are finite per invocation across rounds/retries, except per-message/per-call bounds. Effective values are the minimum of these ceilings, profile and installation policy; lowering limits cannot justify accepting incomplete evidence. JSON byte counts use canonical uncompressed UTF-8. Reject duplicate object keys, non-finite numbers, depth >32 for whole messages and >16 for args/input/output/continuation/record data. Schemas/declarations are at most 64 KiB each, 1 MiB catalogue, 64 named operations and 64 admitted back-call descriptors. Schema strings count characters; also enforce byte bounds.

| Budget | Ceiling |
| --- | --- |
| Invocation deadline | 30 seconds for gates; 120 seconds for general/resource/trigger rounds, never beyond context/parent lease expiry |
| Provider rounds | 8 total, round indices 0..7, including final; a requests reply at round 7 aborts |
| Calls | 8 per batch, 64 total including denied/repeated calls; at most 8 mutation requests |
| Adapter call | 10 seconds or remaining invocation deadline, whichever is smaller |
| Whole request / response | 2 MiB / 256 KiB |
| Read page / records | 128 KiB / 100; 8192 records and 8 MiB read-page bytes total |
| Aggregate request+response wire bytes | 24 MiB including retransmissions, invalid replies and repeated inputs/results |
| Args / input / final output | 64 KiB / 256 KiB / 128 KiB; profile state and continuation each 16 KiB |
| Retransmission | At most 1 per round, 2 total, only exact saved requests |
| Retained read payload | 60 seconds from capture or authority expiry if earlier; no extension from continuation |

Reserve worst-case send/response bytes, calls, mutation intent and retry slot **durably before** sending/executing. Settle to actual size after response; uncertain sends retain conservative charge. All parser, body, counter, retry and timeout bounds apply before unbounded allocations. Outbox reconciliation may outlive the invocation but cannot dispatch a new effect after its authorization expires; it uses a separately authorized controller reconciliation lease to determine history/finish a committed intent.

Canonical duplicate read selection is `(operation,version,scope_args_digest,cursor)`; changing call ID cannot evade it. Return `request_loop`, charge the request and do not redeliver data. A retryable unavailable read may be retried in a later round once using a new call ID with `depends_on` the failed call and identical selection, only if the adapter reports no delivered data and current pins remain valid; this explicit retry edge is exempt from dependency_failed. It consumes all normal limits. There are no read retries for denied/stale/revoked/invalid requests.

Grain MUST persist context/pins/owner/counters, exact request, accepted response/hash, all read dependencies/deliveries, mutation intents/receipts and next-round checkpoint before transmission. On controller crash, takeover fences old owner, checks deadline/authority/pins and resumes the exact saved request or advances from a complete checkpoint. A completed read reuses retained bytes only after dependency revalidation. An uncertain read may repeat under the same call identity only when its adapter proves read-only. An uncertain mutation reconciles its stable intent/domain key; it never becomes a fresh call. Final receipt plus gate state/result/subscriptions commit under unique invocation ID and CAS; crash after commit returns the existing receipt. Durable mutation reconciliation remains discoverable even if invocation recovery is impossible.

Cancel locally on authorized cancellation, applicable task pause/attempt end, owner fencing, revocation, expiry or invalidated contract/pin. Cancel the MCP call context where supported; no provider cancel back-call is required. Provider must observe declared deadline regardless of transport cancellation support. Reject late replies. Cancellation is not task cancellation/completion. Cancel unstarted outbox effects; a possibly dispatched effect becomes uncertain and must reconcile. Never report it rolled back because a deadline elapsed.

Pure gate evaluations retain MGS persisted bounded restart/backoff policy: at most three starts/task/rolling 60 seconds, coalesced active bundle plus dirty marker; ten churn windows hold for authorized resume. Transient failures use 30-second to 30-minute persisted exponential backoff with jitter, blocker at five failures and hold at ten. Other profiles use their domain persisted retry/quota policy within the same no-spin bounds. A broker checkpoint, continuation, heartbeat, result or final is never a trigger source event or useful-progress credit.

## CB-8: Extension profiles {#CB-8}

**Gate.** Catalogue operations `gate_<method>` use typed args, `$defs.gate_input` and `$defs.gate_output`. Input contains mode, binding/authority revisions, expected state revision, prior gate_state, and nullable bound action context reference. Concrete required input requirements are Grain-owned. Output preserves MGS statuses, summary, blockers, work, action proposals, waits and buttons; domain item schemas reuse MGS. Only accepted non-error final updates state (exactly +1 under CAS) and atomically stores result/dependencies/waits. Non-final rounds have no state, action, wait, lifecycle or dispatch effects. Error finals are diagnostics only. Read-only applies to evaluate/migrate/recover and taskless guard profiles alike. Task #50's binding/effective-policy/context/decision/override/receipt semantics remain normative; shared opaque context and gate action_context_ref replace its special outer envelope, not its guards. A reference resolves to the approved canonical AGB context with digest under Grain control and authorized input scope. A provider needing its content must receive it as authorized typed input/read, not an unrestricted lookup.

**General.** A descriptor supplies exact args/input/output schemas and allowed back-call subset. Explicitly delegated mutations may update evidence and return durable receipts before final. Provider output is not proof of task completion, approval or success of an unreceipted effect. General operations do not inherit gate evaluation authority.

**Resource.** TDS Resolve/Observe/Watch semantics remain: canonical identity, equality-only upstream revisions, actual collection times, inline immutable evidence, Observe generation/dirty fences, Watch describe/ensure/read/renew/cancel, fence-before-baseline, independent consumer cursor and authorized sharing partitions. A wrapping broker operation pins its TDS input/output; no domain reply is accepted before final, no source cursor advances on a non-final round, and controller registration/cleanup intents precede provider changes. Watch registration effects are domain-controller reconciled, not an excuse for hidden handle side effects. Direct v1 acquisition remains available under its own contract. Long-lived leases must be renewed under TDS authority independently of 120-second broker invocations. Attachment is the separate general mutation in CB-5.

**Trigger.** A trigger matching operation takes empty provider-selectable args and Grain-bound event input reference; `trigger.event.read` returns only that authenticated journal event. It can request `task.create_from_trigger` only within its binding. Source detection/authentication, subscriptions, cursor commit/renewal, schedules, deduplication, replay/catch-up, age/coverage gaps, loop prevention and quota are TTS controller responsibilities. Event adapter open/read/reconcile/close use separately authorized acquisition contexts. Broker request/continuation/result churn must never enter the source journal as an occurrence. A committed task effect may yield a separately registered authenticated domain event under explicit binding and causation-depth limits; it is not synthesized from broker telemetry. Default filing remains proposed/approval-required unless the standing binding explicitly authorizes approval within existing rails.

## CB-9: Compatibility, validation and remaining blockers {#CB-9}

This is a new shared application protocol version, not an MCP version change. Unimplemented gate snapshot profiles 2.0/3.0 and Task #56 completion/action broker profiles 4.0/5.0 are historical design envelopes, not parallel new-admission protocols. Their retained schemas/fixtures document history; shared `grain.broker/1.0` is authoritative for new broker admission.
