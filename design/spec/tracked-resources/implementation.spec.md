# Tracked-resource implementation contracts

**Owner:** @ai-on-gke/ai-factory-root-owners

**Status:** normative completion of the proposed, unimplemented resource protocol 1.0. Documentation/schema only.

This document extends [TDS-1–10](tracked-resources.spec.md); it does not define a second gate or trigger protocol. [wire.schema.json](wire.schema.json) defines the closed JSON shapes. Both schema and the semantic checks below are required. Named schema definitions for public API projections/results are separate from internal task_reference records; internal shared view IDs are not exposed in public API responses. RFC 8785 canonicalization and SHA-256 use UTF-8 bytes; all byte limits apply after encoding, in addition to schema character limits. Digest placeholders in prose are illustrative; admission computes real digests.

## 11. Registry, discovery and hosting {#TDS-11}

The registration unit is a configured capability ID plus resource method and immutable pin, not a locator URL. Proposed configuration is an additive `grain_config.resource_providers` JSON array of `$defs.registration` records, exported through grain/config. It is **not** a new field inside an existing mcpServers entry and is not accepted by current code. Operator configuration changes use that repository's approval process. This PR creates no configuration.

Each registration has `identity,pin,descriptor,evidence_schemas,access_scope_schema,credential_binding,enabled`. Pin.identity must equal identity; release/protocol match descriptor. Kinds are unique. Every kind additionally has a reviewed human contract describing normalization and source fact meanings, linked from the registration documentation. The registry stores every schema locally, validates boundedness and the capability supported argument subset, and computes these pin digests:

- identifier_schema: canonical sorted array of each kind's kind, identifier_schema, candidate_schema, selector_schema, facets and supports_pinned.
- details_schema: canonical sorted array of each kind's kind, details_schema and fact_version.
- fact_schema: canonical object with keys `facts` (the common Facts schema from wire.schema.json), `evidence_schemas` (sorted by kind), and `access_scope_schema`.
- config_revision: SHA-256 of canonical {registration: <registration excluding enabled and pin>, mcp_server: <the referenced nonsecret mcpServers entry>} with secret **names**, not values. Resolved secret rotation separately increments credential/authorization epochs and fences old calls.

The descriptor release is an immutable build/artifact digest approved by the operator. Registration admission MUST compare the actual tools/list trio, raw inputSchema/outputSchema and descriptor to the local registration. The per-tool schemas MUST resolve to the corresponding closed wire definitions, with local provider-specific schema validation layered on top; comparing only tool names is insufficient. Pin protocol is exactly 1.0. Remote provider schemas cannot add executable validators or remote references. Reusing a release with different schemas is a configuration error. Unsupported/malformed registrations are held; do not damage existing references.

`credential_binding` is a nonsecret operator name for the principal of this exact mcpServers connection; it is not an evidence or credential retrieval handle. Its only resolver is the registered capability configuration's env/headers/config and encrypted secret lookup, as specified in [capabilities §3–4](../capabilities/capabilities.spec.md). One connection has one configured credential binding. The registration's credential_binding names that whole configured principal; it never selects a token by task input. A different upstream principal requires a distinct configured capability ID/registration; sharing a process does not equate authorities. Provider configuration MUST bind that principal to permitted upstream installations, services, resource scope and fields. No secret is supplied by a task or selected by a candidate. The built-in task provider has binding `grain-local`, uses Grain's scoped model projection and needs no network secret.

Actual invocation is `servers.Registry.CallTool(ctx, capability_id, tool, arguments, timeout)` over the attached capability control-plane session. [client.go](../../../pkg/capability/protocol/client.go) currently supports newline-delimited JSON-RPC stdio and Streamable HTTP requests, MCP revision 2025-06-18. It sends `tools/call` with `{name,arguments}`; the result is structuredContent, or the first text content parsed as one JSON record. Resource tools MUST return structuredContent and MAY mirror the same JSON in one text block; differing mirrors are invalid. isError/JSON-RPC errors are transport failures, never accepted observations/checkpoints. MCP request ID and application request_id have separate namespaces. Request/result byte bounds must be enforced before full allocation, including tools/list (1 MiB total, 1000 tools maximum).

Hosting/configuration follows the existing capability spec without duplicating its authentication protocol:

| Hosting | Grain connection and authentication | Required prerequisite |
|---|---|---|
| In-process Grain | Configured built-in grain capability; trusted direct Caller boundary | Extend built-in server with resource trio; retain read policy checks |
| Local stdio/plugin | command/args/env, config and $secret references; private spawned pipes authenticate the selected process | Operator-approved immutable binary/config; no credentials in command args |
| Host stdio | run:host/hostd plus existing hostd selector/allowlist and authenticated host tunnel | Explicit allowed host placement and connectivity; never inherit an agent sandbox's pass |
| External HTTP | Configured serverUrl and secret-backed headers over existing Streamable HTTP | TLS-verified reachable endpoint; loopback HTTP only under existing trusted local-host policy; redirects refused |

No reverse callback, notification handling, resource fetch URL, provider-to-Grain API credential or new listener is required. Current `protocol.Tool` drops outputSchema/_meta and current discovery recognizes mint/release: implementation must add resource descriptor parsing and validation before these tools are callable by the resource driver. Raw control tool availability today is not protocol admission. Server connection authentication identifies the trusted controller, not an arbitrary agent. These tools MUST NOT appear in attempt MCP endpoints or agent-callable generic control-tool proxies.

## 12. Controller grants, bounded access and sharing {#TDS-12}

The proposed runtime `resource_access_grant` record (not an attempt capability pass) has:
`grant_id, task_id, registration_pin_digest, credential_binding, resource_scope, fields, operations, revision, authorization_epoch, recovery_epoch, expires_at, revoked_at, approved_by, approved_reason, share_group`.
Operations is a subset of resolve/observe/watch. Grain stores/hashes it in bytewise sorted order; input order carries no authority. Each task needs its own independently approved grant. Task edit authority alone cannot create one. The grant-management route is described in TDS-15; authorization uses the existing principal/Acting-Task middleware and an explicit resource-access management permission.

resource_scope validates against the registration's bounded access_scope_schema. fields is a sorted unique list of registered field selectors; operations/scope/fields are ceilings, never hints. Durable subscriptions, including poll-only timers, require both observe and watch in every recipient's grant; observe alone permits a bounded requested collection, not background subscription membership. A denied Watch MUST NOT be bypassed by starting a poll timer. Resolve first requires the candidate to match exactly one registered kind candidate_schema; zero/ambiguous matches fail invalid_request without lookup. It validates the candidate and its requested scope **before lookup**, under that schema. Each admitted kind MUST supply tested deterministic candidate-scope and canonical-identifier-scope validators and a field projection; schema shape alone is not a permission predicate. Locator lookup is restricted to the approved scope, never an unscoped existence probe followed by redaction. Observe and Watch validate the resolved identifier/scope against the grant before contacting the provider. Providers must implement this scope/field contract; a schema with no enforceable resource predicate cannot be admitted. All source requests/projections MUST be bounded, including provider pagination, returned details and evidence. Returning inaccessible fields and expecting the UI to hide them is forbidden. A grant with an upstream principal broader than its scope is permitted only because the trusted provider enforces the approved restriction. Grain validates that the response uses the requested identity and schema, then redacts again before persistence.

Every wire request carries `access:{partition_id,grant_id,grant_revision,resource_scope,fields}` and authorization_epoch. This is a **nonsecret restriction**, authenticated by the configured control-plane connection, not a bearer credential or a provider-generated authority claim. The provider trusts only that configured Grain controller as its policy enforcement point and intersects the restriction with its own configured principal's ceilings. It MUST NOT expand scope, choose a stronger credential, or infer authority from grant_id/partition_id alone. Grain must authorize before every outbound call and again before commit/delivery. A provider without this enforcement cannot host the protocol. Cleanup may use only the locally recorded subscription's cancel authority after revocation, with the original pin/identity; it cannot read/renew.

Controller lease records default to 15 minutes, max 1 hour, independently bounded by the grant expiry. Renewal rechecks current task, grant, registration, secret epoch and provider policy; no mint_<method> call or released attempt_id is reused. authorization_epoch includes task/grant/credential changes and is monotonic; credential rotation invalidates all affected grants/views until freshly leased. A singleton resource_runtime_epoch stores a random UUID generated at first enable and preserved on ordinary restart. A deliberate DB restore requires stopping all old writers and replacing that UUID before serving evidence. The recovery UUID is part of partition keys and every local lease/snapshot fence; restored views are audit-only, and new views, request IDs and subscription IDs are allocated in the new namespace. Never resume a restored cursor against an old remote subscription: reauthorize, establish a new fence and perform gap recovery. Retain old cursors and expiry/cleanup intents for audit; old remote registrations expire within one hour. This avoids relying on a restored numeric epoch being greater than a lost pre-backup value. Approval stamps the current recovery UUID on each resource_access_grant. After restore, every old grant is held because that stamp mismatches, even if its restored revoked_at is null. A fresh person-approved grant revision under the current UUID is required before Resolve/Observe/Watch or lease renewal; do not infer reauthorization from restored approval/delegation rows. This explicitly handles revocations lost by rolling back the database. Old subscription cancel cleanup remains narrowly permitted. Ordinary restart preserves the UUID and instead rechecks live policy/config/secrets and reobserves before use. Historical private evidence still requires current read permission.

Keys are:

- resource_key = sha256(canonical {provider,resource_kind,identifier}), excluding tracking/release/display.
- tracked_key = sha256(canonical TrackedResourceReference), including tracking. Watch reference_key equals tracked_key.
- partition_key = sha256(canonical {registration pin,credential_binding,scope,fields,operations,policy_epoch,recovery_epoch,share_group}). Default share_group is task_id plus grant_id and authorization_epoch, so grants do not share accidentally.
- view key = (tracked_key, partition_key, shard_id), where shard_id defaults to 0 and only splits an otherwise equivalent group at its recipient quota. Different pins, fields, snapshots, scopes or credentials never share decision evidence or subscriptions.

Sharing requires an explicit operator-approved share_group, **equal** operations/scope/fields/credential binding/pin/policy/recovery epoch and a live independent grant for every recipient. Before each fan-out/read, check each recipient's grant revision/epoch; sharing does not let A authorize B. The physical collector may use only a live equivalent member whose grant authorizes the actual operation; if its grant is revoked, fence the lease and reacquire under an independently authorized member before another read. Revoking A invalidates A's evidence/buttons and removes only A's membership; B may retain an existing immutable observation only if B independently authorized it at collection and still authorizes it now. New members require a fresh read under their membership epoch. Group-wide policy/credential changes invalidate all members.

Cache lookups are private to a view, never keyed just by URL. API responses contain no shared counts, cache age attributable to another task, membership, hit headers or error variants exposing existence. Cache-hit and cache-miss API reads both read only the task-local persisted projection and return the same accepted/queued shape; no synchronous remote fetch on resource_get. Global token bucket/circuit details are operator-only. A read cannot acquire another task's credential or compare cross-partition tokens.

## 13. Identity, facts and evidence registry {#TDS-13}

Normalization happens only in authorized Resolve. The kind's registered contract MUST specify each identifier field's case/Unicode treatment, authority/installation boundary, stable ID lookup, aliases and rejected ambiguous forms. Core applies RFC 8785 after that normalization, never global lowercasing. Two normalized candidates for one stable ID collapse to one resource row per partition; tracking scopes remain distinct views. Unknown schemas/kinds are unavailable records, not arbitrary JSON for a gate to interpret.

A same-authority rename/move with a stable ID updates only separately authorized display/location details; resource identity stays unchanged. Cross-authority moves or service-created replacement IDs require a separately authorized explicit retarget transaction and fresh Resolve/Observe. Observe cannot redirect identity. Deleted requires current authority to confirm a tombstone; lack of access yields the same generic access_unavailable projection as nonexistent. Confirmed deletion/closed-unmerged/failed are facts, never success. Old immutable observations remain audit evidence but cannot fill a current unavailable response.

Common Facts is only the envelope of provider-specific meanings. Each registration MUST publish fact_version mappings and evidence-kind schemas stating the source authority and exact meaning of lifecycle/disposition/subject_revision. Unknown lifecycle/disposition is legal; unrecognized values are invalid, never coerced to success. Required predicates declare the exact fact/details/evidence schemas they accept. Built-in task v1 mappings are:

| Source | Fact | Evidence/limit |
|---|---|---|
| derived closed task | lifecycle=terminal | Closure only; no synthesized success |
| trustworthy persisted task outcome | disposition=succeeded/failed/canceled | Explicit task outcome/closure receipt, not run exit |
| legacy closed without proven outcome | disposition=closed | Success remains unknown |
| merged integration | disposition=merged on integration facet | Existing integration collector's exact head/merge receipt |
| delivered report | provider-specific report evidence | Grain authenticated delivery receipt and subject; text is insufficient |
| rollover/supersede | details successor reference | Never silently follow or transfer success |

The built-in tasks method uses capability_id=https://grain.dev/capabilities/grain and kind=grain.task. Its exact candidate/identifier/details/evidence shapes are the builtin_task_* definitions in wire.schema.json. Resolve accepts only {installation_id,task_id}; installation_id must equal this deployment's immutable ID (case-sensitive), and task_id must already be NormalizeTaskID's canonical positive decimal form. No title, repository alias, remote installation lookup or automatic successor resolution. Facets lifecycle and outcome are supported; follow_latest only in v1. An immutable closure receipt is evidence, not a pinned retrievable task history; pinned requests fail unsupported_selector. Integration and report facts remain supplied by existing authenticated collectors to gates; generic tasks v1 does not advertise those facets until their registered schemas/authority mappings exist. Observation subject_revision is the current persisted task revision; revision token additionally covers every returned fact/detail/evidence field. The details successor is nullable stable identity only and is subject to the same read authorization. The evidence kind grain.task_observation/v1 is registered only to the built-in trusted model collector, not external providers; gate registry admission verifies its source and receipt provenance. Closed tasks without trustworthy outcomes emit outcome=unknown and disposition=closed.

Pinned selection must identify an immutable retrievable subject under the registered facet, not merely an equality token. Follow-latest changes subject_revision on content change and invalidates old subject evidence, even if lifecycle is still active. An unavailable old snapshot remains unknown. Revision comparison is equality only within view+pin; accepted_sequence orders Grain commits, not external history. A-B-A observations may produce token A again: each accepted material change still has a new sequence.

Inline Evidence is `{evidence_id,version,kind,schema_digest,digest,data}`. kind/schema_digest resolve only in registration.evidence_schemas; data validates there. digest = sha256(RFC8785(data)). Grain stores the authenticated provider/pin/partition, receipt and redacted immutable data, assigns an internal evidence ID and never fetches evidence_id. At most 100 records, 32 KiB total evidence data, within the 256 KiB response bound. Observations must be gathered under the same grant/field projection as their evidence. Redaction precedes persistence; the schema must support the authorized projection or evidence is unavailable. A provider cannot mint Grain approvals/action/report receipts; those use the gate registry's existing authenticated collectors.

## 14. Records and transactions {#TDS-14}

These are logical records; implement in additive Store migrations for SQLite and PostgreSQL. All IDs are installation-qualified where externally visible. Foreign keys restrict deletion of referenced audit evidence. Runtime records are not settings imports.

| Record | Primary/unique keys and durable contents |
|---|---|
| resource_runtime_epoch | Singleton key; recovery UUID, created_at and restore audit reason/actor. Every worker captures/checks this UUID; ordinary restart preserves it, explicit restore replaces it before admission |
| resource | PK resource_id; unique (resource_key,partition_key). Canonical identity, provenance; encrypted/private identifier; display is in observation |
| resource_view | PK view_id; unique (tracked_key,partition_key,shard_id). resource_id, scope/pin, authorization epoch, accepted_sequence, current_observation_id, dirty_generation, covered_generation, freshness deadline, lease_owner, lease_fence, lease_until, next_due, circuit counters |
| task_resource | PK (task_id,reference_id); reference_id never reused, including tombstones. view_id, reference_revision, contract_revision, grant_id/revision/epoch, relation/child_role/gate binding, candidate/tracking/resolution state, membership_epoch, removed_at, migration provenance |
| resource_observation | PK observation_id; unique (view_id,accepted_sequence). Request/generation/pin/access/lease fences, source/receipt times, availability/token, full redacted immutable payload/digest, inline evidence IDs, material-change flag |
| resource_subscription | PK subscription_id; unique live (view_id). Remote generation/fence cursor, expiry, desired state, last ensure/renew/cancel request+digest, checkpoint, lease fence, coverage status (initializing/current/gap_recovery), recovery_reads_remaining, initial_drain_complete, retry/cleanup timers |
| resource_receipt | unique (subscription_id,generation,event_id). Immutable hint digest/page receipt, received time; duplicates do not advance twice |
| resource_outbox | unique (view_id,accepted_sequence,recipient task/reference,membership_epoch,event_type), or dirty_generation for invalidations. Recipient/grant fence, delivery state/attempt/next_due |
| resource_wait | PK wait_id; unique active (task,reference,owner_key), with a non-null server-derived owner_key identifying the suspension or authenticated actor's long-poll slot (no nullable-UNIQUE loophole). after_sequence, reference/grant epochs, deadline, result, suspension ownership |
| resource_access_grant / controller_lease | Keys/ceilings TDS-12; unique active lease per grant/pin; expiry and revocation never cleared by retry |
| resource_mutation / audit | unique (actor,task,idempotency_key); canonical request digest, result/status, expected revisions, before/after epochs, reason, safe change record |

Unresolved task_resource rows have null view_id and reference, with candidate/tracking/pin persisted; they create no canonical resource/view/subscription until authorized resolution. Resolved rows have a non-null canonical reference/view_id and named grant; removed rows retain audit data without live membership. The task_reference wire definition describes resolved domain records, not the entire SQL row. Public resource_projection includes tracking and grant_id explicitly (nullable only for unresolved/redacted views).

Every worker transaction MUST first compare its captured recovery UUID with resource_runtime_epoch, rejecting any old-namespace write. Every write changing evidence also increments the affected task's evidence version/dirty marker in the **same transaction**. Task #47 owns the evidence vector/bundle/close transaction, not a later outbox consumer. Outbox drives eventual reevaluation/notification only; it cannot be the consistency fence. At most 256 active recipients per shared view; exceed that by a separately numbered view/subscription shard with the same authorization rules, never unbounded fan-out. A transaction enumerates and locks that bounded membership set.

Lock order is the installation graph-edit mutex (only graph edits), view IDs sorted bytewise, subscription, then affected task IDs sorted, then their reference/grant/result rows. All lifecycle writers must follow the same order or use optimistic CAS plus retry of the whole transaction. SQLite uses Store.write serialized writes; PostgreSQL uses row locks and a transactional advisory installation graph lock for graph edits. Reads for snapshot publication use Task #47's short coherent read transaction. No transaction remains open over a provider call.

Required transitions:

1. **Attach/edit/remove:** authorize task and any gate relaxation, resolve outside a transaction under grant when needed, then lock and recheck expected task contract/reference/grant revisions and the resolved pin. Check full blocking graph under the installation graph mutex. Insert/replace reference and membership, bump contract/reference/evidence revisions, invalidate gate bundles/actions/waivers and append audit/idempotent result together. No partially installed required binding. External Resolve calls use a temporary read lease recorded against the approved grant before attach; failed CAS discards that resolution rather than installing it into a new contract. Removal tombstones reference, cancels only its waits, removes membership and enqueues last-recipient cleanup. Unresolved attachment cannot bind a met gate.
2. **Claim collector:** transactionally CAS lease_until or matching owner, increment lease_fence, capture accepted_sequence/dirty_generation/pin/auth/membership. Lease default 45 seconds, at most 60 seconds, renewed only after current authorization; provider deadline ≤30 seconds. Fencing is monotonic, not wall-clock owner identity. Expired or replaced owners cannot commit. There is one outstanding Observe per view.
3. **Ensure/recovery:** persist remote generation/intent and canonical request before sending. After reply, commit only under current lease/pin/grant; install original fence and dirty generation, then baseline Observe. Keep coverage=initializing until a full first drain reaches has_more=false and covered_generation equals dirty_generation. Baseline observations are staged/immutable but cannot authorize gates during initializing. Any initial hints require a fresh Observe followed by another bounded drain before marking current. For poll/lost history use gap_recovery with two required source reads: the first after ensure and the second after draining or the next allowed poll; persist the remaining-read counter. A crash before acknowledgement retries the same ensure key/request. Renew replies may echo the current read checkpoint but cannot advance it locally; only read commits advance it. Remote generations are monotonic and never reused; a canceled/expired generation cannot be revived by ensure or renew. Exact old retries may return cached receipts but cannot recreate delivery. Provider ensure/renew/cancel request digests and replies are retained through remote expiry plus 24 hours (including absent-generation cancel tombstones). Lost remote history never restarts from a claimed empty cursor without a coverage gap.
4. **Read/checkpoint:** fetch from persisted checkpoint outside transaction. In one transaction recheck lease, generation, old checkpoint, pin/access and membership, validate every hint, insert dedup receipts, advance checkpoint, increment dirty_generation once if any new hint, mark all authorized recipient task vectors dirty and invalidate bundles/actions. Commit an outbox/timer with dirty work even for a gap. Ack is only this commit; a crash earlier replays the page. Empty success may advance checkpoint without implying freshness. Bounded coalescing may discard redundant hint payloads only after committing dirty and checkpoint together.
5. **Observe accept:** after schema, digest and scope validation, one transaction checks captured accepted_sequence/dirty_generation/lease_fence/pin/auth and current membership. Insert observation and inline evidence, increment accepted_sequence, set covered_generation to captured dirty_generation, update availability/freshness and the persisted coverage barrier, insert per-recipient outbox and invalidate task evidence vectors/bundles in that same commit. If a hint raced, reject decision acceptance and retain dirty; schedule fresh read. Same-token refresh still creates immutable collection evidence and a new sequence but no material-change trigger. Between two available observations, any relevant payload change with the same non-null token is invalid_result, except collection/display-only fields. Nonavailable null tokens make no equality claim.
6. **Freshness/revocation:** expiry can be detected by durable timer, but every gate acceptance/action/close also checks current time directly. Revocation transaction increments authorization/membership/task evidence epochs, fences leases, cancels waits with redacted access_unavailable, invalidates results/actions/waivers and records cleanup. Late replies cannot restore access. Per-recipient revocation does not clear another grant.
7. **Fan-out:** a bounded outbox worker reauthorizes each recipient and CASes its membership epoch before marking delivered/waking. Crash after wake before ack repeats harmlessly; one task dirty marker coalesces repeats. No automatic task filing. Gate consumers only read committed immutable observation IDs/versions, never a mutable view behind an old ID.
8. **Gate publication/close:** use [BG-4/5](../gates/gates.spec.md#BG-4). Capture task/reference revision, observation ID/sequence, view dirty/covered generation, schema pins, grant/membership epochs and freshness as focused read dependencies. Dirty!=covered, incomplete initializing/gap recovery, unavailable schema or expiry yields unknown required evidence. Decision/action/closure revalidate the union and current authorization atomically with local fences. A hint transaction ordered first invalidates close; later discovery follows regression policy. This fences recorded knowledge, not unobserved external truth; no universal snapshot/pages are required.
9. **Watch-change:** atomically compare after_sequence to current accepted_sequence and install a wait if unchanged, under task/reference/grant epochs. Observation acceptance or access/freshness loss resolves matching waits and suspension dirty state in its transaction. Long-poll timeout returns unchanged; park persistence uses existing suspension ownership and sandbox-loss checks. Resume removes only holds the suspension owns. A callback to an agent is unnecessary.

Retention/quotas are enforceable defaults: 100 references/200 bindings and 20 active resource waits per task; concurrent long polls from the same actor/reference share one slot, while excess slots return resource_limit; 256 recipients per view; 10,000 active subscriptions per installation; 1000 per provider; 3000 accepted observations per view per 24 hours then coalesce time-only refreshes by collecting no faster than necessary for the configured budget. If a gate requests a budget exceeding collection quota, hold resource_limit rather than silently lengthen freshness. Material changes still consume quota and hold unknown when exhausted. Remote state changes must never be discarded into a positive result.

Keep uncited observation payloads 7 days and at most 1000 per view; keep receipts 24 hours, at most 10,000 per subscription. At that limit, persist a dirty/gap marker before pruning; replay outside dedup retention can cause an extra Observe only. Keep completed outbox/idempotency results 7 days; older reused mutation keys return idempotency_expired using a retained digest/tombstone, never replay a destructive edit. Mutation-key tombstones, cited decision evidence, closure receipts, reference histories and audit live for the task audit lifetime (until an authorized retention/purge operation). Bound non-audit transient storage at 1 GiB per provider: pause collection and expose resource_limit before writes exceed it, preserving current decision audit and fencing freshness. Operators can narrow limits; increases require audited sizing policy. Remote subscription expiry ≤1 hour bounds abandoned registrations. Purge must invalidate any still-live decision first and return evidence_expired for purged history; it cannot rewrite a past receipt as a different decision.

## 15. API, tools, errors and migration {#TDS-15}

All routes/tools here are proposed. Reuse current authenticated API/Acting-Task checks; require both task repository scope and the named permission. Register additive API scopes `resources:read`, `resources:edit`, `resources:watch`, `resources:access:manage`, bounded to task/repository as existing task API grants are. Default resource-access management is person/deployment-administrator authority; an agent requires an explicitly approved delegated ceiling and cannot approve its own expansion. External access additionally requires TDS-12 grants; gate weakening uses the gate contract's person approval/preauthorization, not resources:edit.

| Operation | Wire input and preconditions | Result / audit |
|---|---|---|
| POST /api/tasks/{task}/resources/resolve; resource_resolve | $defs.resolve_preview_request; resources:read and named task-local resolve grant | 200 $defs.resolve_result for a bounded read-only preview; no task/link/subscription mutation or access grant |
| POST /api/tasks/{task}/resources; resource_attach | $defs.attach_request; resources:edit; expected_contract_revision; exact pin; authorized candidate or explicit unresolved=true | 201 $defs.resource_projection (resolved or redacted unresolved); no inferred gate/grant |
| GET collection/item; resource_list/get | resources:read plus current source/evidence authority; $defs.list_request query limit/cursor | 200 $defs.resource_page or $defs.resource_projection; historical evidence same ACL; no synchronous provider fetch |
| PATCH item; resource_edit | $defs.edit_request (attach input plus expected_reference_revision), resources:edit, expected reference+contract revisions, full replacement candidate/tracking/relation/grant; relaxation approval if applicable | 200 $defs.resource_projection; all-or-nothing retarget/pin/tracking/relation change |
| DELETE item; resource_remove | $defs.remove_request, same CAS and approval policy; reject live required bindings unless atomic gate edit removes/rebinds them | 200 $defs.mutation_receipt; no dangling gate |
| POST item/watch-change; resource_watch_change | $defs.wait_request; resources:watch and source watch grant; after_sequence, max_wait_seconds≤30 or explicit park; same-task agent only; resource park refuses unpushed or uncommitted work, with no new discard override | $defs.wait_result (changed/unchanged/unavailable plus accepted_sequence); permission loss redacted, independent declared links preserved |
| POST /api/tasks/{task}/resource-access; resource_access_grant | $defs.access_grant_request; resources:access:manage, operator/person source access authority, exact registration/scope/fields/operations/expiry (at most 30 days from approval; renewal is a fresh approved grant revision) | 201 $defs.grant_result; this is the only grant resolver, never attach or discovery |
| DELETE /api/tasks/{task}/resource-access/{grant}; resource_access_revoke | $defs.revoke_request; resources:access:manage, expected_grant_revision | 200 $defs.mutation_receipt; immediately fence all affected views |

Attach/edit requests explicitly name grant_id; Grain MUST NOT choose another task grant or broaden to a different credential when it fails. With unresolved=true, persist only the submitted candidate/tracking/pin and do not invoke the provider, even if a grant was named. With unresolved=false, require a non-null current task-local grant permitting Resolve, resolve outside the write transaction and install only after the full CAS recheck. If resolution fails, return the typed failure without modifying the reference. Observe and durable Watch additionally require their own operation bits. Editing a pending reference uses this same candidate flow; a preview is not authority or a substitute for resolution/auth rechecks at mutation time. A change of grant invalidates membership/evidence epochs. Public projections return the selected grant ID and requested tracking, or null where redaction requires it; they never return shared view IDs.

Resolve preview uses the same bounded invocation, pin/identity/scope validation and token buckets as attachment. Authorization/schema failures use the API error status rules; a completed provider result (including invalid/unavailable) returns the typed resolve_result at HTTP 200 with a Grain-generated request_id. Audit actor, grant/recovery epoch, request ID, result digest and safe status; never copy credentials or private payloads into general activity text.

Contract/grant mutation requests carry expected_contract_revision, idempotency_key, reason, and expected_reference_revision for existing records. Gate-authorized atomic edits use the gate API's attachment transaction and these same reference invariants; resource routes do not accept inline invented gate definitions. Same idempotency key+digest returns the saved authorized result after current read checks; differing digest returns 409 idempotency_conflict. Version conflict is 409 revision_conflict; required binding/cycle/unsupported selector 422; malformed schema 400; quota 429 with Retry-After; provider outage does not turn a persisted unresolved reference into success. Unauthorized reads return the same 404 access_unavailable as missing, without titles, link counts or timing from a remote lookup. A permitted task reference may show a generic unavailable blocker without confirming source existence.

Provider Error.code is closed: invalid_request, invalid_result, unsupported_version, unsupported_kind, unsupported_selector, access_unavailable, cursor_expired, subscription_expired, stale_generation, rate_limited, unavailable, resource_limit, canceled. Retryability must match policy: only rate_limited/unavailable retry automatically; cursor/subscription expiry require new-fence recovery; other codes hold until corrected. Error summaries are inert untrusted text. API failures use $defs.api_error; API error codes add revision_conflict, idempotency_conflict, idempotency_expired, required_binding, cycle and evidence_expired. Retry-After is nonnegative seconds and bounded to 86400; no busy retry on zero. Audit stores actor, reason, authority epoch, before/after revisions, request digest and safe error, never secrets or inaccessible summaries.

Agent resource tools derive task_id from their authenticated acting-task context; UI/API callers name it in the path and pass the same repository/task checks. resource_list uses the named list_request; HTTP query decoding supplies limit=100 when absent and cursor=null when absent/empty, while a nonempty cursor is an opaque URL-encoded string; JSON tool callers supply both fields explicitly; resource_get has reference_id from the route/tool argument and no arbitrary fetch selector. API request/reply bodies are at most 256 KiB. List pages stop before either limit or that byte bound, returning next_cursor without truncating an item; an individually oversized projection returns resource_limit. List snapshot materialization is bounded to 100 live references and 8 MiB of redacted records, or fails resource_limit without partial publication. List pagination orders reference_id bytewise and freezes authorized task-local membership/revisions for 60 seconds in a bounded page set; cursor binds actor, task, permission epoch, filter, offset and expiry. Revocation invalidates it, and expiration/change returns 409 revision_conflict requiring a fresh list. Removed references are excluded from the normal list and remain available only through authorized audit reads. The 100-reference quota counts live references, not audit tombstones.

Angular UI actions use these routes and actual authorized scopes; display advisory observation separately from required gate outcome, dispatch prerequisites and wait state. Edit previews show exact pin/scope/selector changes and invalidated gate bindings. Unknown schema is an unavailable indicator, not a generic property editor. Existing classic consumers and task-goal APIs remain compatible.

Migration is per task and transactional with explicit completion_authority/epoch handoff under BG-8. The mapping must persist these exact source fields; it cannot merely rename depends_on:

Import the actual WaitTarget.Settled pairs, not an intuitive meaning of “closed”: with until_merged=false, Closed OR StateFailed returns (true,true), otherwise (false,false). With until_merged=true, Merged returns (true,true); otherwise return (Closed AND NOT PullRequestOpen,false). The legacy met=true on failed means its wait predicate ended, never new task success evidence. Explicit depends-on dispatch still uses target closure, not StateFailed. Preserve this difference between polling wait and declared dispatch projection.

The built-in provider MUST preserve WaitTargetFor/MayReadTaskOf redaction. Existing minimal cross-repository ordering reads stay confined to their legacy route; generic resource reads need source authority even for status/existence. Required children default to a separately authorized success gate: failed/canceled/unknown legacy outcome stays unmet/unknown. Advisory/independent children have no closure hold.

Cycle checking locks the installation graph across edits, migrations, retargets and reopen, and inspects the union of current dispatch edges and required child/gate task edges. The traversal is bounded to 10,000 nodes, 50,000 edges and 16 MiB of projected IDs per edit; exceeding any bound returns resource_limit and leaves the edit uncommitted, never assumes acyclicity. Reject self/cycles; concurrent A→B and B→A cannot both commit. Current closed targets may satisfy edges, but reopening must revalidate; corrupt/unverifiable graphs hold and escalate with redacted diagnostics. External graphs need bounded patience (default 24 hours without material progress, then deduplicated escalation and held retries pending authorized resume), never assumed acyclic or auto-relaxed.

During reader-first rollout keep legacy fields and Go/SQL task-state parity. Shadow observations have no dispatch/closure effects. Rollback fences workers and reverses handoff only for representable exact predicates; otherwise a compatible daemon must hold the task. Old binaries must be prevented from writing migrated tasks before rollout (version admission guard), not trusted to ignore new columns safely. Disablement retains pins/history/cursors and makes required evidence unknown. No configuration/deployment change or task filing is part of this document.

Resource evidence is a registered immutable observation consumed by authorized internal helpers, not a callback or lazy remote page fetch. Removing a reference, completing/deleting a task or revoking its observation grant MUST NOT retire resource guard policy. Either preserve its independent index entry or require the AGB policy owner's explicit retirement; resources:edit is insufficient. The action executor uses committed redacted observations with current vector checks; it cannot call a provider from a historical observation payload or turn a Watch hint into approval.

Optional state-transition integration requires an explicit reviewed adapter registration pinning both protocols and schemas, mapping installation-qualified event provider.id bijectively to ResourceProviderIdentity/pin/partition, and mapping resource kind/ID/subject revision without losing scope. Unmappable data holds. The adapter consumes only committed **material** observation outbox entries and normalizes a registered state-edge kind under TTS-3.
