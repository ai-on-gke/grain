# Brokered read operations and evidence consistency

**Status:** operator-selected transport for the proposed gate architecture (Task #56); normative documentation, not implemented. Completion profile 4.0 and action profile 5.0 supersede snapshot-page-only profiles 2.0/3.0. No runtime, deployment, permission increase or follow-up task filing is authorized.

**Contracts:** [MGS-11](mcp-gates.spec.md#MGS-11), [read-operation schemas](read-operations.schema.json), [initial registry/digests](read-operations.registry.json), [wire schema](wire.schema.json), [action bindings](action-bindings.spec.md#AGB-3). BCP 14 keywords apply. BR IDs are stable.

## Operation registry and admission {#BR-1}

A brokered read is an application-level read-operation request carried in a gate result. It is not native MCP server-to-client `tools/call`. Grain MUST validate and execute it, then send the result in its next ordinary `tools/call` to the same pinned gate. Every network call to a capability provider remains Grain initiated. No callback listener, provider-to-Grain credential, hostd requirement or colocation is introduced. Existing hostd placement may relay existing Grain-to-provider calls.

The controller registry MUST bind each operation ID/version to an immutable adapter release, resolved argument/result/record-schema digests, effect=read, deterministic scope/field validators, authorization rule, source/collection version strategy, bounded execution and predicate coverage semantics. [read-operations.registry.json](read-operations.registry.json) pins the proposed initial schema identities; actual adapter releases and authorization rules remain implementation blockers, not deployed tools. The discovery and evaluator pin read_registry digest covers the complete canonical admitted operation-entry list, including adapter release/configuration pins, schema digests, authorization rule and read-only requirement. Fixture adapter releases are illustrative, not deployed admission. Registry changes require a reviewed revision, new declaration/registry pin and invalidation; an operation cannot be retargeted at the same pin. Extension registration requires a bounded typed operation, never executable provider-authored selectors.

Discovery's `read_operations` is a subset of the admitted registry and does not grant access. Each input domain lists supported kinds/operations and required status. Grain resolves exact scope and mandatory read requirements from its registered predicate, attachment arguments and effective policy; the provider cannot expand them. `evidence_context.requirements` lists domain, operation/version and SHA-256 of canonical **scope arguments excluding cursor and limit**. Every required read must have complete acknowledged coverage before met, including policy prerequisites not requested/cited by the provider. Required inline controller facts may satisfy their own domain without a broker call only under the registered validator. Discovery/predicate mismatch is unsupported_version, never a weaker interpretation.

The schemas are closed JSON Schema 2020-12. Every string/array is bounded; additional fields are rejected. Finite byte/depth limits apply independently. `read-operations.schema.json` defines exact args for all nine initial IDs; all versions are `1.0`:

These are logical proposed MCP read-operation identities, not claims that those tool names or safe endpoint equivalents exist. Reuse existing API/tool argument/schema components where they fit, then apply these exact adapter projections and ordinary current authorization. Raw route invocation by provider-supplied method/path is forbidden. If an in-process authorized model read implements an operation, no synthetic MCP network hop is needed; a configured remote adapter is invoked through the ordinary capability caller with a controller-assigned application request ID. Both use the same registry/scope/error contract.

Message reads require after_watermark <= through_watermark and never advance processed watermark. Every subject is canonical `{authority,repository_id,kind,id,head}`. Display names/URLs are not identities. Checks/reviews MUST have non-null exact head; taskless policy/guard reads use AGB's bound resource. Task reads require the current task or an explicitly authorized relationship/policy target. `evidence.events.list` requires at least task_id or resource, and both when supplied mean their intersection. `reference_ids` is a fixed admitted list, not arbitrary object lookup. Arguments cannot choose credentials, adapters, tools, servers or endpoints. No shell, URL fetch, SQL/JSONPath, filesystem, general namespace, token, mutation or arbitrary tool invocation is allowlisted. Read hints do not enforce read-only execution; the adapter's actual credentials/code path must do so.

## Envelopes, pages and errors {#BR-2}

A `read_request` is exactly `{read_id,operation,operation_version,args}` with the operation-specific closed args above. Gate `kind=read_requests` carries 1–8 ordered requests and ≤16 KiB credential-free continuation, with all MGS identity/context/hash echoes. It contains no verdict, durable state update, waits, buttons, action requests or lifecycle proposals. Grain validates the entire envelope/unique IDs before executing any operation. It MUST authorize each request separately before execution and before result delivery/acceptance.

A successful `read_result` is `{request,status:"ok",page}`. `page` is exactly `{protocol_version:"1.0",evidence_context_id,read_id,operation,operation_version,args_digest,subject,collection_revision,coverage,records,next_cursor,dependencies,observed_at,valid_until}`. Correlation MUST match the request/evaluation context, exact operation/version and canonical full-args digest. Records use MGS `{id,kind,version,data}`; kind/data MUST match the registry for that operation. `coverage={complete,empty}` describes this scoped collection: complete is true only on a successfully exhausted collection; empty is true only for an authenticated complete empty collection, with records=[] and next_cursor=null. Nonempty collections never assert empty. Missing/unavailable data has no page; it cannot prove absence. Singleton reads return complete coverage and null cursor.

A negative/zero-row result MUST depend on the **collection membership generation**, not just versions of returned records. Required suites, child membership, messages through the requested watermark, review assignments/findings/dismissals, policy coverage, matching approval/waiver revocation and operation state need explicit completeness. A page's subject revision alone cannot prove any of these sets complete. For provider-specific predicates, the registered adapter and validator must specify the exact finite collection semantics; a generic summary cannot substitute.

A failure is `{request,status:"unavailable",error:{code,retryable,message}}`, with no page, records or cursor advance. Safe codes are unauthorized, unsupported_version, resource_limit, request_loop, unavailable, cursor_expired, stale_context and invalid_request. Denied and nonexistent out-of-scope subjects MUST be indistinguishable. Syntactically invalid whole gate envelopes abort invalid_result; well-formed denied reads can be returned in order alongside successful reads so the evaluator can conclude unknown. Required denial/partial data latches insufficiency even if the evaluator omits it from citations. Core revocation/context loss aborts the evaluation without another call. Unknown/error never becomes empty/false or met.

For transient unavailable errors Grain MAY execute one exact same logical read retry before producing a delivery, under the original time/call/byte budget. The read ID/args remain identical. Once delivered, a failed selection cannot be retried within this evaluation: conclude unknown/error or abort; a later evaluation may retry under backoff. `stale_context` and `cursor_expired` abort rather than continuing with live replacement pages. Successful deliveries and failures are checkpointed before sending the next gate request.

List args use cursor=null initially and limit 1–100; adapters may return fewer records within byte limits. Cursor is an opaque controller-bound token of ≤4096 bytes, authenticating context/evaluation, provider/audience/permission epochs, operation/version, normalized scope args, fixed ordering, collection generation and expiry. Only the exact next_cursor previously delivered for that selection may be used. No offsets, guessed future cursors, page-size expansion, new traversal edges or scope changes. Adapters use bounded keyset scans over a versioned committed projection; before/after scan generation checks reject concurrent mutation. If a source cannot supply a stable generation, collect/normalize it first or return unavailable. Pinning a live URL does not supply historical access.

One next page per collection can be requested per round; unrelated allowed reads may be batched. Results appear in request order even if execution is parallel. Parallel reads must use the same authority context and dependency-ledger insertion CAS. One logical selection `(operation,version,scope-args-digest,cursor)` is delivered once; changing read ID/limit cannot reset its budget. First later repeat produces request_loop without data; repeating/continuing the loop aborts. MCP JSON-RPC request IDs are independent transport IDs, never read IDs or effect idempotency keys.

## Minimum consistency mechanism {#BR-3}

The operator selected the transport. **Engineering consistency choice:** a dependency-validated observation context, with retained delivered bytes and set generations, replaces mandatory full immutable task materialization. This requires concrete versioned projection/transaction work below; it is not an assertion that current stores already supply it.

1. Grain creates one bundle/evidence_context ID, fixed now/deadline and core fences: task/contract/authority/policy/provider/config/credential/permission revisions, resolved action resource/head when present, relevant message watermarks and journal cursor. It computes mandatory requirements from attached predicates/effective policy before calling any gate. All gates for a decision share this context, with separately redacted authorized views and ledgers. Context inline metadata/records is ≤256 KiB; context is not a URL, credential, frozen whole-database view or promise of upstream simultaneity.
2. Each operation reads a bounded committed projection in a short SQLite transaction or PostgreSQL repeatable-read transaction, capturing record revisions AND collection membership/coverage generation, subject/head, pin/auth/recovery epochs, dirty/covered generation, observed_at and valid_until with the page. No DB transaction spans an MCP/external call. An authorized collector may refresh outside that transaction using its ordinary grants and CAS; a material refresh that invalidates the core/current dependency context aborts this attempt and starts a bounded fresh evaluation. Do not silently rebase a running context. Stale uncollected sources return unavailable/refresh-needed, not fresh timestamps on cached facts.
3. Grain automatically inserts all dependencies from each adapter, including successful empty reads and available inline prerequisites, into its private durable ledger. It MUST derive them from trusted adapter/model metadata, never provider citations. First access latches a collection generation. A later page/read of the same collection must match; changed head, record/set generation, ACL/pin or dirty coverage aborts stale_context. Retain only delivered redacted records/pages and exact round payloads for 60 seconds; do not preallocate the whole backing collection. Persistence/retention is bounded across all reads. Unrequested data is not materialized solely for the evaluator.
4. Before final acceptance Grain MUST validate the union of core and every read dependency for every required gate in one decision transaction: all versions/current grants/pins match, no dirty>covered source, no expired source/evidence/deadline, all required scoped collections have acknowledged complete coverage, no unavailable prerequisite, all citations match delivered immutable versions, expected state revisions/owner leases match. A set insertion, deletion, dismissal or revocation must advance the relevant generation in the same transaction as the fact change. A relevant child edit/outcome must bump the parent dependency fence transactionally. A source that cannot participate in this validation is unsupported for authoritative decisions, not silently trusted.
5. This optimistic validation yields a consistent **Grain-recorded** cut at acceptance: all values read must still be current together. Mutating a fact and reverting it still changes monotonic generations (ABA cannot resurrect a result). It does not prove an atomic state of independent external systems. Freshness uses actual collection time, min(provider validity, predicate age budget), and direct clock checks even if a timer has not run. Missing upstream history, pending authenticated hints, non-versioned sources and incomplete pagination are unknown. Observations may need a collector refresh before a fresh attempt.
6. Acceptance stores a dependency receipt with the result/state/subscriptions and copied cited evidence, once. Immediately before action or closure, revalidate that receipt and the current core/collection/authorization/freshness fences. Closure additionally locks/CASes incoming/processed watermarks, required child outcomes and settled/fenced live operations. Protected actions use AGB's resource locks, exact-head conditional execution/exclusion, intent and reconciliation. A Grain lease or expected SHA cannot freeze every external review/policy/base race; adapters lacking adequate source-side conditions/exclusion must refuse enforced admission. An external human action remains observed/attributed, not claimed prevented.

Full snapshot materialization is optional only for a **specific adapter** whose source has no stable page generations and whose bounded captured immutable projection is required to supply them. Such an adapter must document the capture transaction, fixed membership/order, byte/record limits, freshness and expiry, and still register dependencies on current source versions; it cannot make a stale captured set acceptable. The default operations above require versioned committed projections, not a universal snapshot service. An unbounded or unversionable source stays unknown until a suitable bounded collector/adapter exists.

## Recovery, authority and implementation blockers {#BR-4}

Gate execution remains a pure replayable function of its request, fixed now, original durable state and bounded request-carried continuation. No external read, callback, server session, filesystem cache or affinity is required. Continuation is transient, not evidence or durable gate_state. A provider needing an unbounded accumulator returns resource_limit/unknown. No read result can execute a mutation; protected action requests remain the separate MGS/AGB path.

Grain persists owner lease/counters, accepted read request, adapter attempt intent, dependency ledger and exact result bytes before advancing. After a crash, a completed read reuses its saved bytes only if its dependencies/context remain valid. An uncertain read can be repeated under the same identity because registry admission proves read-only execution; nevertheless revalidate its newly returned versions and never splice conflicting pages. No reads may create Watch subscriptions, advance a consumer checkpoint, mark a message processed, refresh credentials or take a protected action. A collector's independently authorized refresh/CAS is its own idempotent collection path, not evaluator authority. If an allegedly read-only endpoint has effects (including wait-credit/state writes), it needs a side-effect-free adapter and cannot be forwarded raw.

Adapter transport errors/JSON-RPC errors/isError are failures, never successful domain data. Gate-call lost replies use exact retransmission and digest chaining from MGS-11, not another read execution. Crash after final commit reuses the unique receipt; no second state CAS/action/dispatch. Explicit pause/revocation/contract change cancels locally; no cancel callback is required, and late replies cannot commit. Read/round checkpoints, heartbeats and retries do not advance evidence generations or feed triggers.

Before implementation admission: build the registry/predicate coverage validators and bounded adapters; versioned collection projections/parent invalidation and dirty/freshness fences in SQLite/Postgres; scoped read-only provider execution and discovery parsing; durable dependency/read/checkpoint/lease/receipt transactions; byte/depth/aggregate/concurrency limits at ingress; current-head review/check mappings; taskless action-profile support; and crash/retry/revocation conformance scenarios. Existing generic CallTool support alone supplies none of these. TDS Observe/Watch and TTS event collection remain separate proposed protocols with separate grants/checkpoints; their data can populate these committed projections. This document files or deploys none of that work.
