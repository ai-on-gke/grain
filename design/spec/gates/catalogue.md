# Initial compiled gate catalogue

This is the exact version-1 catalogue for [BG-1–4](gates.spec.md). All thirteen types have `version=1` and closed configuration in [contracts.schema.json](contracts.schema.json). Every field is required; creation applies the listed defaults **before** canonical hashing/materialization, never by silently defaulting an old stored contract. Legacy modes are admitted only by the controller's explicit import path with source/provenance; new tasks use the recommended mode. Subjects and purposes are semantic admission constraints.

Common subject selectors: `task` (explicit task ID, `self` resolved at filing), `change` (authority, repository, PR/CL kind and stable ID, `*` for every matching change in an authorized repository/resource policy, or `task_changes` for the acting task's versioned link set), `repository` (repository/ref). An action guard is rebound by Grain to the exact executing resource/head. A task-wide change set cannot be narrowed by the agent to omit an inconvenient change. All types can be optional monitors; only types expressly listed as guards can gate actions. `freshness_seconds` defaults to 300 on every attachment, range 0..3600. No type writes private state.

`legacy_*` profiles preserve predicate interpretation, not permission to bypass the new message/child/authority closure fences or credential admission. Complete-set limitations must be displayed. A result used by enforced action admission must meet current-head/current-policy/complete-collection rules even if an older cohort's monitoring uses a legacy reading. No passing check gate can waive a different failing review/approval or outcome.
