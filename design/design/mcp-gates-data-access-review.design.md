## Decision and engineering recommendation

A gate returns a structured **non-final read request** naming an allowlisted read-operation/version and typed arguments. Grain validates current authorization/scope/schema, executes the ordinary authorized read path and calls the same pinned gate with ordered results and bounded continuation. This application convention uses ordinary MCP calls in the existing Grain→provider direction. It does not use native reverse tools/call, provider callbacks, a new listener or credentials for provider→Grain access. Existing hostd placement can relay calls; hostd/colocation are not prerequisites.

The operator selected this transport. The engineering recommendation for consistency is **lazy dependency tracking and validation**, not mandatory full immutable task materialization: capture core fences, derive record/set/negative-evidence dependencies automatically on each read, retain delivered bytes and validate all dependencies together at final acceptance and again at action/closure. Exact mechanisms and limits are normative in [MGS-11](../spec/mcp-gates/mcp-gates.spec.md#MGS-11) and [BR-1–4](../spec/mcp-gates/brokered-reads.spec.md). This choice requires new versioned bounded projections/transactions; a logical context ID alone proves nothing.

Complete declared input remains the simplest driver when inputs are small. Brokered reads deliberately retain a round/checkpoint/continuation driver in exchange for demand-driven bounded data delivery and reusable typed read contracts. They simplify the *selection interface*, not all state management. No general query language or broad data platform is needed.

## Alternatives and tradeoffs

External collection calls are additional in every option; round-trip counts below concern evaluation/data delivery.

| Dimension | Complete required inputs up front, one call | Capability-wide read service | Original page-only protocol | Selected brokered reads |
|---|---|---|---|---|
| Protocol/driver/schema | Simplest: one request/final and exact retry; no transient continuation. | Common schema only helps after direction/auth/snapshot semantics are defined; risks a platform. | Catalog/ref/cursor/page/delivery, loops, prefetch, chained rounds and accumulators. | Fixed typed operation/args/result registry replaces catalogs; retains rounds/continuation, read intents/results/dependency ledger. |
| Round trips/large input | One evaluation call; bounded multi-MiB request and provider parse memory. Missing/oversized input requires unknown or approved projection. | Evaluation + N callback reads; more service/session availability dependencies. A controller-driven variant becomes brokered reads. | One with prefetch, up to eight rounds; controller already retains all input. One long serial reference may exceed rounds before aggregate budget. | Up to 16 rounds, batches ≤8; lazy bounded source scans, 64 total read calls/requests and 8 MiB pages. Serial pagination can still exhaust limits. |
| Memory/time | Controller/request/provider memory explicitly bounded; streaming advantage lost. | Must bound backing store and consumer as well as each page. | Bounded complete backing cut, ≤2 MiB requests and ≤16 KiB accumulator. | Retain only delivered bytes; same bounded request/accumulator and fixed 30s deadline; decoded memory/concurrency need admission limits. |
| Reuse/ergonomics | Ordinary pure function over complete records; shared collectors/registry helpers suffice. | No current second consumer needing the same immutable snapshot-read wire service. | Specialized selection SDK and replay discipline. | Reusable operation schemas/ordinary read authorization, explicit adapters where current endpoints are oversized or have effects; more adapter contracts than eager input. |
| Evolving predicates | New declaration/schema/pin and authorized scope; bounded raw provider-specific facts avoid hardcoding predicate in Grain. | A generic endpoint cannot authorize new facts automatically. | Cannot request undeclared domains/IDs; pin/migration still required. | Same explicit admission, with registered exact operations and namespaced bounded record kinds; no dynamic tool/query expansion. |
| Consistency | One committed observation cut plus current fences; no upstream simultaneity. | Live callbacks alone mix versions; need equivalent dependency or snapshot mechanism. | Full immutable local cut and current vector fencing. | Optimistic record+set-generation validation yields a consistent current Grain-recorded cut; unknown when stable coverage/source freshness cannot be established. |
| Auth/privacy | Scope/redact before send; may overdeliver optional facts; revocation fences acceptance but cannot recall bytes. | New authenticated access direction, service scopes/tokens and privacy partitions. | Reauthorization per retained page; reference existence/counts also sensitive. | Reauthorize each operation/delivery/final; args are restrictions, not grants. Separate per-task/provider/purpose views, no cross-audience cache/count leakage. Delivered bytes remain irretrievable after revocation. |
| Missing data/retries | Complete coverage markers; exact replay and one final state CAS. | Read failure cannot mean empty; callback dedup/recovery added. | Denied/partial/repeated/expired selections plus exact round replay. | Complete-empty requires membership generation; denial/stale/oversize stays unknown/error. Separate bounded adapter retry and exact gate replay; unique final receipt/state CAS. |

Provider-specific predicates continue to run in the pinned evaluator. Grain's registered adapter proves what facts a bounded collection represents, not arbitrary predicate code. A controller-generated all-passed summary is valid only with exact registered coverage/semantics/provenance. If the predicate needs unsupported raw facts or cannot fit its accumulator, return unknown/resource_limit; neither protocol is unlimited access.

## Initial gates and realistic sizes

These are sizing examples, not production benchmarks. [BR-1](../spec/mcp-gates/brokered-reads.spec.md#BR-1) maps all nine initial read identities/closed schemas to actual source and explicit adapter gaps.

| Gate | Inputs and bounded handling |
|---|---|
| Checks | Effective required suite set + exact-head check facts/coverage/freshness. About 1,000 × 1 KiB facts can fit the byte/record budget but require about ten pages; selected 16-round ceiling can serve this shape, original eight-round single-reference ceiling cannot. Historical reruns/logs are excluded only under approved latest-applicable-suite semantics. Missing required suite is unknown, observed failure unmet. |
| Reviews | Exact head/path digest, policy, roles, assignments/findings/dismissals/approval scope. About 2,000 × 2 KiB facts is ~4 MiB, but 20 serial 100-record pages exceed the 16-round ceiling. Use a registered narrower exact-scope projection, independent authorized collections, or unknown; do not assert all data fits merely because byte ceiling allows it. Full 50 MiB diff/discussion predicates are unsupported without a bounded approved projection. |
| Child outcomes | Explicit required/advisory/independent links, success/integration/legacy-closure predicate and child revisions. Five thousand 1 KiB facts may fit bytes/records but not one serial collection's rounds. Exact required-set aggregate or narrower authorized gate is needed. Failed/canceled closure is not success; membership/outcome changes invalidate the parent receipt. |
| Report | Durable artifact/digest and message coverage through exact incoming/processed watermark; separate receipt acknowledgment if required. A 100 MiB report need not be evaluator input for delivery/coverage. Content-analysis predicates needing uncaptured text remain unknown; mutable URLs are not a fetch escape hatch. |
| Integration | Exact PR merged head/all scoped CL outcomes and authoritative receipts, not readiness or terminal closure. Thousands of CLs need bounded exact-set projections or fail closed on limits. Unreadable CL is unknown, closed-unmerged PR unmet. |

A combined task may need 1 MiB checks + 4 MiB reviews + 5 MiB children across separate attachments sharing one dependency-validated bundle and separately authorized views. Do not deliver their union to every provider. Each adapter/attachment still must meet read/round/record/time budgets and registered scope. Qualification must measure actual projection sizes, serial shape, parsing/concurrency memory and source latency before admission; this documentation supplies no benchmark proof.

## Responsibilities, wire examples and preserved guarantees

[Check transcript](../spec/mcp-gates/examples/success-paged.json): Grain sends core context → gate returns read_requests(change.checks.list, exact resource/head, required-set revision, null cursor) → Grain authorizes/reads/records dependencies → next gate call includes read_result page/next cursor → second scoped page → final met with request digest/evidence/state candidate → Grain atomically validates core+all dependencies/coverage and commits once. [Full taskless review transcript](../spec/mcp-gates/examples/action-review-brokered.json) does the same under action profile 5.0. [Denial](../spec/mcp-gates/examples/denied-read.json), [head change](../spec/mcp-gates/examples/stale-snapshot.json), [transient read retry](../spec/mcp-gates/examples/transient-read-retry.json) and [exact provider retry](../spec/mcp-gates/examples/provider-crash-retry.json) cover failure paths. [README](../spec/mcp-gates/examples/README.md) specifies standard JSON-RPC wrappers and what each application message means.

Grain owns registry/adapter pins, scope/grants/revocation, redaction, finite scans, required coverage, dependency ledger and acceptance; provider owns pure pinned interpretation and bounded continuation. A digest is acknowledgment/context binding, not credentials or approval. No non-final message changes gate_state, dispatches, installs subscriptions, takes actions or creates trigger events. Missing/denied/stale/incomplete data independently prohibits met; a provider cannot omit a prerequisite read/citation to bypass policy.

Essential guarantees retained: exact subject/head and source freshness, record/set/negative-evidence/ABA and child/message fences, one current consistent recorded bundle, permission isolation/revocation, schema/release pins, bounded pure evaluation, final-only atomic state/subscription CAS and idempotent receipt, durable copied decision evidence, and separate action/closure fences. Action guards still require caller authorization, source-side exact-version conditions or proven exclusion, intent and authoritative reconciliation; freshness checks cannot freeze independent external systems. Closure still requires current message watermarks, child outcomes and settled/fenced operations.

Removed mechanics: gate-specific reference catalogs and mandatory full materialized backing snapshot/index. Retained mechanics: pagination inside typed list operations, bounded continuation, exact round hashes/checkpoints, read correlation/loop limits and TTL. New responsibility: automatic trusted dependency/coverage tracking plus versioned adapters. Optional adapter-local captured immutable data is allowed only for a specific bounded source with documented capture/generation/expiry semantics, not as a universal assumption.

## Migration, sibling coordination and blockers

MGS-2/11, MGD-1/6, discovery, wire/record/read-registry schemas, action-profile compositions and examples now adopt brokered reads consistently. Completion 4.0/action 5.0 explicitly reject old 2.0/3.0; there is no reinterpretation/fallback. Recompute declarations/registry/schema/context/request digests and repin attachments. Existing gate runtime is unimplemented, so this is contract/fixture churn, not a deployed database migration; inventory any separate implementation work before assuming zero cost. The eager draft example is removed; the original comparison remains in git history.

Foundation phase now builds versioned committed bounded projections, read registry/adapters and dependency receipts instead of universal materialized page storage. Shadow phase adds bounded broker/continuation/exact retry/recovery. Authority migration, Go/SQL parity, central closure, waits/dispatch and UI/API phases remain; AGB executor/credential-boundary work stays independent. Readers/negotiation precede writers. [BR-4](../spec/mcp-gates/brokered-reads.spec.md#BR-4) lists remaining blockers, including exact predicate mappings, source generations/negative coverage, both-store transactions, read-only execution, parser/concurrency admission and crash/revocation conformance. No implementation or task filing is authorized by these phases.

Tracked-resource #45/#48 retains identity/provider pins, access restrictions, authorization partition/recovery epoch, equality-only provider revision tokens, accepted observation sequence and dirty/covered generations. Broker operations consume its committed projections. #48's TDS-14 gate-publication reference must follow the amended MGS/BR validation semantics; its resource trio/Watch envelope is not redefined. Trigger #46/#49 retains authenticated occurrence identity/replay/gaps and independent cursors. #49 selects Grain-initiated open/read/renew/close with an upstream GitHub gateway; that ingress grants no provider→Grain access. Freshness refresh, dirty hints, read/round/retry/state churn never become material transitions/occurrences. Reuse installation registry, schema/auth/collector helpers where semantics match; no second credential catalogue or generic data service is introduced.

The transport decision is accepted; no additional operator transport choice is requested. Adapter/source admission and actual implementation/deployment remain separate future work, not automatically filed here.
