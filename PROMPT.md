# Agent Instructions and Commit Standards

All commits generated by coding and triage agents in this repository MUST strictly follow the Conventional Commits specification.

## Commit Message Format

- `fix:` / `fix(<scope>): <short description>` — Bug fixes, patches, and regressions (eligible for automated RC backports).
- `feat:` / `feat(<scope>): <short description>` — New features or functional enhancements (main branch only).
- `refactor:` / `refactor(<scope>): <short description>` — Code refactoring without behavior change.
- `test:` / `test(<scope>): <short description>` — Adding or updating test suites.
- `chore:` / `chore(<scope>): <short description>` — Build configuration, dependency bumps, or maintenance.
- `docs:` / `docs(<scope>): <short description>` — Documentation updates.

### Structured Footers for Traceability:
- If resolving or referencing an issue: `Fixes: #<id>` or `Issue: #<id>`
- If cherry-picked or backported from another commit/branch: `Backported-from: <commit_sha>`

## Two UIs

grain ships two web UIs side by side. The Angular UI in `ui-ng/`, served at `/next/`, is the new experience and will replace the classic React UI in `ui/`, served at `/`. The classic UI is being deprecated. The operator approved this rule on 2026-11-12:

1. **New UI features** go in `ui-ng/` only. Change the classic `ui/` only when a feature can't work without it.
2. **Bug fixes:** fix the classic UI only where it is broken for users today. If the same page exists in `ui-ng/`, fix it there too.
3. **Walkthroughs, screenshots and e2e tests** cover `/next/` first. Keep the classic suites passing, but don't add classic coverage for new things. Don't delete classic tests.
4. **Links in task text** keep pointing at classic routes (`/tasks/<id>`) until the operator makes `/next/` the default.
5. **API changes** keep both UIs working. The route table is shared: regenerate `ui-ng/src/app/api/generated-routes.ts` with `GRAIN_UPDATE_NG_ROUTES=1 go test ./pkg/ui -run TestAngularRouteTableInSync`.

Where things are in `ui-ng/`:

- `src/app/<area>/` holds one directory per page (`inbox/`, `tasks/`, `task/`, `settings/`, ...), `src/app/shared/` the shared components, and `src/app/api/` the API client (`grain-api.service.ts`, `models.ts`, `generated-routes.ts`). Routes are in `src/app/app.routes.ts`.
- `src/app/shell/nav.ts` lists the rail's destinations and the classic page each replaces (`classic`). A destination whose `route` is `null` hasn't moved over yet and links to its classic page instead. Check it and `app.routes.ts` before assuming a page exists under `/next/`: a page in neither (Boards, for one) lives only in the classic UI. Moving a page over means building it and setting its `route`.
- Read `design/design/ui-design-book.design.md` (brand, tokens, layout, review mandate) and `design/design/angular-ui.design.md` before changing anything.
- Develop: `cd ui-ng && npm ci && npm start` runs `ng serve` (port 4200 by default) and proxies `/api` to a grain on `127.0.0.1:8080` (`proxy.conf.json`). `make frontend` builds it into `pkg/ui/static-next`.
- Unit tests and lint: `cd ui-ng && npm run lint && npm test` (vitest). Formatting: `npm run format:check`.
- E2E: the `/next/` Playwright specs live in `ui-ng/e2e/` (`ui-ng/playwright.config.ts`, CI job `ui-ng e2e`). Run them with `make test-e2e-ng`; a new `*.spec.ts` there is picked up on its own. `ui-ng/e2e/next-full-system.spec.js` must pass for every `ui-ng/` change.
- The classic suite is **frozen** (`ui/e2e/README.md`). Don't add a classic `ui/e2e/*.spec.js`: `go test ./tests/hygiene -run TestNoNewClassicE2ESpecs` fails on any spec missing from `ui/e2e/FROZEN_SPECS`, and you must not add lines to that list. Don't fix a classic flake on your PR. Add its `file:line` to `ui/e2e/QUARANTINE` with the evidence. That takes it out of the gating `ui e2e` job and into the non-gating `ui e2e (quarantined)` job. When a spec's Go and ui-ng halves have both landed, it goes in `ui/e2e/NONGATING`.
- Screenshots: `make ui-screenshots PAGES=/next/inbox,/next/tasks OUT=screenshots/after` (`docs/ui-screenshots.md`).
