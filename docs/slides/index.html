Workflow 01 · Intake & Policy

Create a Task

Structured task definition with granular capability assignment and auto-merge controls.

  • Granular Task Specification: Operators define task title, instructions, target repository, priority tier (P0–P3), and area tags.
  • Least-Privilege Capabilities: Assign specific capabilities (self-debug, grain-ci, gemini-key, gcp-key) needed for execution.
  • Autonomous Merge Policy: Toggle Auto-Merge to allow verified pull requests to land straight into base branches without manual review.
  • Human Approval Gate: Tasks can land directly in the queue or await operator sign-off before dispatch.
Speaker Note: Grain replaces unstructured prompting with structured engineering backlogs. Operators define requirements, select capability sandboxes, and configure merge policies upfront.
Workflow 02 · Concurrency & Scheduling

Task Picked Up by Agent

Dynamic queue scheduling respecting cluster concurrency limits and model backends.

  • Bounded Concurrency Pool: Cluster worker capacity (e.g. 4 concurrent workers) prevents host saturation and API rate limits.
  • Autonomous Priority Dispatch: Tasks automatically transition from Queued to Running based on priority, readiness, and dependencies.
  • Multi-Model Backends: Gemini 2.5 Pro, Claude Code, and Antigravity frameworks dynamically assigned per workload.
  • Real-Time Lifecycle Tracking: Clear visual state progression across Backlog, Queued, Running, and Repairing.
Speaker Note: The orchestrator schedules tasks into a fixed worker pool. When an agent slot frees up, the highest-priority runnable task is dispatched immediately into an isolated sandbox.
Workflow 03 · Security & MicroVMs

Isolated Sandboxes & Scoped Credentials

Hermetic VM sandboxes with temporary credentials and live resource telemetry.

  • Hermetic MicroVM Isolation: Every run executes inside a fresh Kontur VM or isolated container, preventing cross-contamination and host compromise.
  • Ephemeral Credential Scoping: Sandboxes receive short-lived repository tokens and minted cloud credentials (gcp-key, gemini-key); master keys remain on the host.
  • Hardware Resource Controls: Strict limits on vCPUs, RAM allocations (2048 MiB), disk quotas, and execution timeouts.
  • Live Infrastructure Telemetry: Real-time monitoring of active sandboxes, memory trends, CPU load averages, and health.
Speaker Note: Security and isolation are foundational in Grain. Agents run inside sandboxed VMs with temporary, least-privilege tokens, while the host daemon oversees cluster health and telemetry.
Workflow 04 · Execution & Human-in-the-Loop

Agent Does the Task

Live streaming transcripts, tool executions, and interactive human-in-the-loop unblocking.

  • Live Streaming Transcripts: Full transparency into agent reasoning, shell commands, file edits, and test runs.
  • Interactive Question Protocol: When encountering ambiguity, agents pause execution and post a targeted question to the operator.
  • Instant Dialogue Unblocking: Operators reply directly in the chat to resume the paused agent with full contextual awareness.
  • Immutable Audit History: Complete record of all tool calls, diffs, and conversational turns preserved for review.
Speaker Note: Grain eliminates black-box execution. When agents hit ambiguous requirements, they pause and ask the operator. Once answered in the UI, the agent resumes execution instantly.
Workflow 05 · CI Verification & Auto-Repair

CI / Merge Pipeline & Autonomous Repair

Native CI workflow verification with autonomous conflict repair on pull request branches.

  • Native Grain CI (.grain/workflows): Workflow orchestration running inside isolated sandboxes with matrix parallelization.
  • Pre-Merge Verification Gate: Full gating suite holds the merge queue until all linters and integration tests pass.
  • Autonomous Merge Conflict Repair: If a PR encounters git conflicts or CI regressions, Grain automatically re-dispatches an agent to repair the branch (Repairing state).
  • Shared Outage Correlation: Distinguishes between local code regressions and shared upstream infrastructure failures.
Speaker Note: Verification is built directly into Grain. If a PR encounters merge conflicts or failing checks, Grain automatically interposes an agent to resolve the issues and re-verify the branch.
Workflow 06 · Sub-Tasks & Dependencies

Agent Sub-Tasks & Follow-Ups

Autonomous task decomposition, chained dependency DAGs, and proposed follow-up work.

  • Autonomous Task Decomposition: Agents break down complex features into focused sub-tasks linked via LinkChildOf.
  • Chained Dependency DAGs: Enforce execution order with LinkDependsOn, blocking downstream tasks until prerequisite code merges.
  • Follow-Up Task Proposals: Agents discover technical debt or follow-up improvements and file structured proposals via propose_task.
  • Contextual Handover Notes: Standing handover documents carry architectural decisions and invariants across task boundaries.
Speaker Note: Agents operate as autonomous teammates. When tackling large issues, they decompose work into sub-tasks, establish dependency graphs, and propose follow-up improvements.

Architecture · Google Internal Deployment

Grain Inside Google

Cloud Run Proxy with IAP, outbound Capsule reverse tunneling, and distributed User Capsule remote executors.

  • Outbound Capsule Tunneling: Grain on a dedicated Capsule dials OUT to Cloud Run Proxy via IAP to establish a persistent control channel with zero inbound firewall holes.
  • Identity-Aware Proxy (IAP): Cloud Run Proxy is fronted by Google IAP, enforcing zero-trust corporate identity and IAM access control for all executor connections.
  • Distributed User Capsules: Remote executors (grain executor) run on user dev capsules with local agent CLIs (agy, claude, codex) and ambient developer credentials.
  • Hermetic Tool Execution: Agent CLI tool actions are tunneled back through Cloud Run Proxy to execute safely inside isolated Granule microVM sandboxes on Grain Capsule.
Speaker Note: Grain inside Google operates over a Zero-Trust topology. Grain on a Capsule dials outbound to a Cloud Run Proxy with IAP. Remote executors on developer User Capsules connect through the proxy, driving local CLIs with ambient auth while tunneling tool executions into Grain's isolated sandboxes.
