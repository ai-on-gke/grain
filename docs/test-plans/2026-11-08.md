### What changed
- **Delegating apps & personal consent grants across API, CLI, cross-replica cache & `ui-registry`** (#872, #879, #884):
  - Added registry-admin routes `GET /api/admin/delegating-apps`, `POST /api/admin/delegating-apps` (normalizing bare service-account emails to `serviceAccount:<email>`), and `PATCH /api/admin/delegating-apps/{name}` (`disabled`), paired with `grain registry delegating-apps list|create|disable|enable`.
  - Added person-facing consent routes `GET /api/delegation-grants[?include_revoked=true]`, `POST /api/delegation-grants` (`app`, `entries`, `access`, `ttl_seconds` capped at app `max_grant_ttl_seconds`), and `DELETE /api/delegation-grants/{id}`, paired with `grain registry grants list|create|revoke` (accepting either `dlg_...` ID or app name).

  - Added `ui-registry` `/admin#delegating-apps` and `/grants` ("Apps acting for you") screens and matching `grain-registry demo` fixtures/endpoints (#884).
- **`catalog.scope_owners`, `delegate:` `--label` CLI & status/error privacy** (#876, #809):
  - `catalog.scope_owners` rules control who may claim primary ownership of repository scopes: bare `<owner>/*` rules also govern host-qualified claims (`github.com/<owner>/...`) unless overridden by a host-specific rule, and pre-existing primary claims not authorized by `scope_owners` are demoted on `/api/directory`, `/api/route`, and connected-entry heartbeats.
  - `grain access allow` adds `--label <name>` (`[a-z][a-z0-9-]{0,31}`) for `delegate:<email>` entries (`#876`).
  - Restricted `/api/status` version/count exposure, scrubbed `grc_...` / bearer secrets in CLI errors, and prevented metadata/error leaks (#809, #876).
- **Hosted instance `stop`/`start`, custom boot disks & `grain-instance-init.sh` metadata** (#878, #883, #914):
  - Added `grain registry stop` and `grain registry start` (human-only, refusing delegating apps and `connected` entries), `ui-registry` Stop/Start actions with confirmation modal, `stopped`/`stopping` lifecycle badges and auto-wake banner, and `-disk-gb` (20..4000 GB, registry schema 7 `boot_disk_gb`) on `grain registry create` and `resize`.
  - `reconcile.InstanceGrainConfig` (#914) now emits the snake_case keys `scripts/grain-instance-init.sh` requires (`instance`, `deployment_owner`, `owner_group`, `issuer`, `audience`, `jwks_url`, `management_url`, `sql_instance`, `db_name`, `db_user`, `db_dsn`, `sm_prefix`, `object_store`, `config_repo`) alongside `GRAIN_*` keys, and `deploy/test/registry-sandbox/` adds disposable GCP + peered hosted-VM Terraform/scripts (#864, #883).
- **Two-step transfer expiry, admin recovery, migration locking & rolling drain handoff** (#852, #854, #865, #866, #869):
  - Registry schema 6 adds 7-day `transfer_expires_at`, transfer cancel, credential/tunnel/SSH revocation on transfer accept, audited admin force-transfer, retention restore guards (`purged_at` / expired `db_purge_after`), immediate `POST /api/admin/entries/{name}/purge` (with optional 30-day name reservation release), and admin recovery APIs + `ui-registry` panels (quotas, scope conflicts, SQL pool drain, orphan GCE VMs, active tunnel disconnect, reconciler lease).

## §6. Daemon Runtime Resilience — Secret Manager `ErrGoneUpstream` Redaction & Transcript Upload Retry, Stale-While-Revalidate `hostexec` Probes, 1-Hour System-Schedule Grace & Host Placement Diagnostics

### What changed
- **Secret Manager `ErrGoneUpstream` redaction resilience & raw transcript upload retry** (#912):
  - Under `-secrets-backend=secretmanager`, `versions/latest:access` returning HTTP `404` or `400 FAILED_PRECONDITION` (`DESTROYED` / `DISABLED`) now wraps `secrets.ErrGoneUpstream`, evicts any cached value, and names `grain secrets delete <key>` in its error.
  - `KnownValues` skips `ErrGoneUpstream` keys (logging once on disappearance and once on recovery) so a secret deleted out-of-band in GCP no longer breaks transcript redaction and upload for every task run, while `401`, `403`, and `5xx` errors continue to fail closed.
  - Added `Store.MissingUpstream` (bypassing cache) and wired `grain secrets list` to annotate gone keys with `(missing in Secret Manager)` plus a `stderr` reconciliation hint.
  - `pkg/daemon/transcripts.go` retains and retries a finished run's raw `.jsonl` transcript file when run-end redaction or object-store upload fails instead of unlinking the local file immediately.
- **Stale-while-revalidate `hostexec` probes on hung host agents** (#906):
  - `queryHostdOffers` (`pkg/daemon/hostexec.go`) now serves an expired unreachable host failure immediately (`<200ms` instead of blocking 3.00s on `hostdOffersTimeout` every 15s) while spawning at most one detached background refresh probe; concurrent callers during the hung probe receive the cached failure without coalescing onto the hung dial, and socket creation/inode change or remote session reconnect still invalidates immediately.
- **1-hour first-firing grace on freshly seeded system schedules** (#921):
  - `seedSystemSchedule` (`pkg/orchestrator/systemschedule.go`) computes `NextRunAt` via `firstSystemFiring` at least `systemScheduleFirstFiringGrace` (1 hour) after seeding so starting a fresh deployment at `02:59 UTC` (or starting a `MaxWorkers: 1` daemon in tests near a cron boundary) never immediately fires nightly memory/release-notes/infra/steward tasks over an empty history, while preserving `NextRunAt` on already-existing rows.
- **Agents-only host placement refusal & `"the host agent refused:"` diagnostics** (#915):
  - Placing a capability server onto an `agents-only` (`grain-agentd`) host now explicitly explains that a placed capability server needs a full grain host (`grain host`), and host-agent allowlist/protocol refusals consistently report `"the host agent refused: ..."` rather than internal `hostd` jargon.
