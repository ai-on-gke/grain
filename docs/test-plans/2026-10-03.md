# Nightly new features test plan: 2026-10-03

This plan covers what merged after `docs/test-plans/2026-10-02.md`, which stopped at `main`
`5e4f4a3dc` (2026-10-02 12:35 UTC). It runs through `candidate` at `57632f61f` (2026-10-03 03:46
UTC). That is 129 non-merge commits.

**Where the code is.** Every commit in this batch is on `candidate`:
`git log --no-merges origin/candidate..origin/main` is empty, and `5e4f4a3dc` is an ancestor of
`candidate`. The newer `main` tip (`4f8bc9c55`) adds only merge commits. So every task below is
filed against **`candidate`**, the build this deployment runs. Each report must still name the
commit it tested and confirm it with `git branch -r --contains <sha>`. Yesterday's §1-§7 tasks were
filed against `main` before the cut. Their reports were not in `docs/test-runs/` when this plan was
written. Where they overlap with this plan, the sections below say so, so that one finding is not
reported twice.

Focus areas:

1. **Team-owned GitHub credentials.** There is no deployment fallback any more. Team settings >
   Git identity has its own token fields. Tasks are held until their team has a credential. A
   one-time migration runs at startup, and the GitHub banner now covers teams only.
2. **The `nothing_needed` tool and per-task ending action.** It closes a task by default, or leaves
   it for acknowledgement. Its outcome shows in the attempt history.
3. **`grain init` and host bring-up.** `grain init` takes a bare Linux host up to a running daemon.
   The batch also adds arm64 guest images, `-granule-ready-timeout`, a refusal of a foreign sandbox
   subnet, GCE metadata blocking on every install, and model proxies that survive a taken git-proxy
   port.
4. **Deployment and team time zones.** `Config.TimeZone` is now a real setting that reaches every
   rendered timestamp, and a bad team time zone or limit is a 400.
5. **CLI task dependencies.** `grain create -depends-on`, and `grain update -depends-on` /
   `-no-depends-on`.
6. **Team scoping of CI, metrics and capabilities.** CI runs, artifacts, faults and `/api/metrics`
   are team-scoped. CI capabilities are judged as the repository's owning teams. Host-level
   capabilities are admin-team only. Repo declarations are refused for teams that may not work in
   the repo. Viewers lose the live console.
7. **Network boundary hardening.** The tunnel and relay fail closed and route streams by type. The
   git proxy authenticates before it reads a body. The package cache is read-only for no-network
   sandboxes and verifies OCI digests. A NetworkNone gateway accepts only service ports. Executors
   cannot take over another executor's instance id. Checkpost signs the method and path. Public IAP
   principals are refused.
8. **CI, merge and operator data correctness.** Flake and quarantine outcomes are stored. Forge
   holds PRs on `action_required`, stale and conclusionless checks. A security hold is explained on
   the PR. Export/import carries team state repos. Image upgrades are pinned to a digest. The
   state-repo mode is explicit.
9. **UI fixes from yesterday's walkthroughs.** Accessible names for modals, panes and the composer.
   Escape saves a settings field. Encoded declared-row links open. Unknown board comparisons are
   named. Detail opens that resolve out of order are ignored. Page state resets when the team or
   repo changes.

`tests/security` (`make security`, also run by the `go` job) gained MCP tool scoping, git-proxy
repo scope, sandbox egress, and capability, proposal and scheduled-CI boundaries (`1c9a5738d`,
`7fbdd5d58`, `a59b94ed0`, `3d17825b7`). That suite is the floor for §6 and §7. It proves the answer
at each boundary from a test principal. It does not prove what a person sees, what a real sandbox
can reach, or that a refusal left nothing behind.
