## §3. Merge Queue `merge_on_green`, Base-Repair Human-Gate Bypass, Submit Head-Pinning, and Security-Hold Deduplication

### What changed
- **`merge_on_green` per-repo and per-branch configuration** (`968fe0d43` on `candidate`, PR #4685; `4877c18c0` on `main`, PR #4632):
  - `pkg/config/repos.go`, `pkg/mergequeue/queue.go`, `pkg/orchestrator/merge_queue_adapter.go`: Adds `merge_on_green` (`MergeOnGreen *bool`) at both repository and branch levels in `repos.yaml` (`MergeOnGreenForBranch(branch)`), allowing branches to opt in or out of automatic merge-on-green independently of repo defaults, and surfacing `mergeOnGreen` in `/api/repos` and `/settings/repositories`.
- **Base-repair human-gate bypass (`base_repair_bypasses_human_gates`)** (`4e581526b` on `candidate`, PR #4733; `3d76b3acf`, `7f822ca7b`, `e89a5eaea`; `6e213ccca` on `main`, PR #4678):
  - `pkg/config/repos.go`, `pkg/orchestrator/merge_readiness.go`, `pkg/orchestrator/auto_submit.go`: Adds `base_repair_bypasses_human_gates` (`BaseRepairBypassesHumanGates *bool`) on repository and branch configs (`BaseRepairBypassesHumanGatesForBranch(branch)`). When enabled and the target base branch is red, a task marked `FixesBaseBranch` (`fixes_base_branch: true`) bypasses the human-approval gate so a base-branch repair can land without waiting for human review, while **still enforcing** the `pkg/trustboundary` security-review hold (`SecurityHoldReason` is never bypassed).
  - `ui/src/components/settings/RepositoriesSection.jsx`: Exposes both `"Merge on green"` and `"Base-branch repair bypasses human gates"` checkboxes per repository and per branch in `/settings/repositories/<owner>/<name>`.
- **Human `Submit` head-SHA pinning & security-hold deduplication** (`bdd31c36a` / `819d821a2` PR #4641, `eb8827a47` PR #4571, `62ca29585` PR #4658 on `main`):
  - Pins the PR head commit SHA approved when a human clicks `Submit` (`SubmitApprovedHeadSHA`) so a subsequent agent push invalidates the approval instead of riding the earlier human click into the merge queue.
  - Deduplicates security-review tasks when a branch sits in the merge queue across multiple ticks without pushing a new commit.

### What CI proves

- `pkg/orchestrator/base_repair_bypass_test.go`, `pkg/mergequeue/queue_test.go`: Unit-tests `FixesBaseBranch` bypassing human gates while preserving trust-boundary holds.

## §6. Grain CI Recheck Joining & Superseding, Operator-Cancelled CI Retry (`Retry` / `Re-run CI`), and `/api/ci/runs` SQLite Poll Cache

### What changed
- **Grain CI recheck joining & superseding** (`5224748c7` on `candidate`, PR #4686; `be6a89a7b` on `main`, PR #4681):
  - `pkg/ci/service.go`, `pkg/mcp/sandbox/tools_ci.go`: When `retrigger_ci` launches a selective recheck of failed jobs at a commit, subsequent `wait_for_checks` calls join and wait on the in-progress recheck run rather than returning the stale cached red verdict from the original run; starting a new recheck supersedes any earlier in-flight recheck for the same commit; and the composite full-suite verdict merges each job's latest result across the original run and completed rechecks.
- **Operator-cancelled CI retry (`Retry` / `Re-run CI`)** (`a5a25f9fa` PR #4656, `a9b744fcb` on `candidate`; `ec5879f49` PR #4607 on `main`):
  - `pkg/ci/service.go`, `pkg/ui/ci.go`, `ui/src/components/CIRunDetailView.jsx`, `ui/src/components/TaskDetailPanel.jsx`: Allows operators to retry cancelled or failed CI runs directly from the UI (`POST /api/ci/runs/<id>/retry` or `POST /api/tasks/<id>/rerun-ci`), clearing the cached cancelled/failed job verdicts and starting a fresh uncached run.
- **`/api/ci/runs` SQLite poll cache & visibility fault-cache isolation** (`f1eb05049` PR #4697, `6f82f323d` PR #4665, `607094db1`, `c172311b7` on `candidate`; `3d59aae5d` PR #4486, `87742c29a` PR #4699 on `main`):
  - `pkg/ci/store_cache.go`, `pkg/ui/ci.go`: Caches `/api/ci/runs` list responses in memory, invalidated on any CI run/job state transition in SQLite, eliminating redundant SQLite scans during UI polling while keeping visibility/fault caches isolated per caller scope.
