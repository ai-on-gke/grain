# Nightly new features test plan: September 25, 2026

This plan covers all features and behavioral changes merged into `main` over the past
day (following `docs/test-plans/2026-09-24.md` and subsequent runs) through `b8fe23e34`
(PR #2046) and `71904f146`. It encompasses 26 merged pull requests and 50+ commits.
It is distinct from `docs/test-plans/2026-09-25-release-testing.md`, which is a release-readiness
sweep of the entire product.

Key focus areas in this batch include:
1. **Per-Team Git Credentials & Commit Identities**: Configuring distinct Git author/committer identities and credential secrets per team, with propagation into sandboxes, dispatch cycles, and recreation flows.
2. **Sidebar Navigation Overhaul & Foldable Sections**: Restructuring the navigation rail with high-priority pinned tasks, visual team containers, foldable Boards & Sessions sections with localStorage persistence, and mobile touch targets.
3. **System Overlay Sandboxes & Caches Tabs**: Unified operational visibility into active sandboxes, VM metrics, package cache disk utilization, hit ratios, and on-demand cache pruning directly from the System panel.
4. **Transparent Package Cache for Playwright Browser CDN**: Transparent reverse proxying, DNS interception, immutable archive caching, and HTTP 206 range pass-through for Playwright browser binaries.
5. **OCI Referrers/Tags Proxying & CI Sandbox Package Cache Wiring**: Elimination of Docker buildx / BuildKit fallback failures via OCI tag/referrer proxying, automatic DNS/CA bootstrapping in release image builds, and CI runner package caching.
6. **VM Guest & Sandbox Network Resiliency**: Dynamic MTU discovery in `netshim` with kernel parameter propagation (`granule.mtu`), automated guest interface and Docker daemon MTU alignment, and dynamic avoidance of host gateway/route collisions on `docker0`.
7. **Conversation UI Copy Controls & Touch Accessibility**: One-click copy controls for agent messages and task comments with animated feedback, state dot animation fixes, and 44px minimum touch targets on coarse pointers.
8. **Closed Task Default Sorting & Lifecycle Visibility**: Default ordering of closed tasks by completion timestamp (`closed_at DESC`) across CLI, REST API, and UI.
9. **CI & MCP Developer Tooling**: Early-return fast failure reporting in MCP `wait_for_checks`, pre-installed `actionlint` and cached browser binaries in CI sandboxes, and in-process OCI registries for container upgrade tests.
10. **Quiet Repository Shipping Detection**: Detecting when merged repositories stop publishing releases, tracking continuous failures and downtime, and alerting in deployment health.

Each section outlines what existing tests prove, the critical unproven gaps across real sandbox/browser environments, and concrete walkthrough steps.

- `pkg/ui/teams.go` exposes these fields in `GET /api/teams`, `POST /api/teams`, and `PATCH /api/teams/{id}`, validating credential secret existence.
- `ui/src/components/TeamsPanel.jsx` adds interactive configuration inputs, identity summary cards, and secret dropdowns in the Team Settings UI.

## 4. Transparent Package Cache: Playwright Browser CDN Interception & HTTP Range Pass-Through

`b5888d8db` (PR #2015, task-632) and `00e73ddf9` (PR #2022, task-564) add transparent caching and DNS interception for Playwright browser downloads.

Concretely:
- `pkg/pkgcache/dns.go` adds `playwright.azureedge.net` and `cdn.playwright.dev` to `DefaultInterceptedDomains`.
- `pkg/pkgcache/playwright.go` implements `KindPlaywright`, reverse proxying browser archive downloads (`.zip`, `.tar.gz`, `.tgz` under `/builds/...`) and caching them immutably.
- Implements HTTP 206 Partial Content range request pass-through and legacy `/playwright/` prefix compatibility.
- Non-archive requests or metadata endpoints pass through transparently without local cache corruption.

### Existing coverage
- `pkg/pkgcache/playwright_test.go` (299 lines) tests URL matching, range header handling, cache hit/miss semantics, and archive extraction against mock HTTP servers.
- `pkg/pkgcache/transparent_test.go` verifies DNS interception and transparent connection routing.

### Gaps and unproven behaviours
- **Real Playwright CLI browser installation**: No test runs `npx playwright install chromium` inside an isolated guest VM using only the transparent package cache with external internet blocked.
- **Large binary caching & multi-part download resumption**: Playwright browser archives range from 50MB to 150MB. Unproven whether multi-threaded downloads or resumed range requests produce byte-identical cached archives on disk.
- **Cache eviction and corruption recovery**: If a cached browser archive is partially written or corrupted during an interrupted download, does subsequent fetch recover cleanly or fail with checksum errors?

### Walkthrough & test procedure
1. Launch `grain demo` with package cache enabled.
2. In a test sandbox with outbound internet restricted to the package cache (172.17.0.1:53), run:
   `npx playwright install chromium firefox webkit`
3. Verify that initial downloads are fetched via `172.17.0.1` and cached under the Playwright cache directory.
4. Clear the local Playwright browser cache on the sandbox (`rm -rf ~/.cache/ms-playwright /var/cache/playwright`).
5. Re-run `npx playwright install chromium firefox webkit`. Assert that all browser binaries are served as instant `CACHE_HIT` responses from the package cache.
6. Launch a headless Playwright browser test to verify that the extracted binaries are intact and execute successfully.

## 6. VM Guest & Sandbox Networking: Dynamic MTU Propagation and Docker Subnet Conflict Avoidance

`541ff6c4f` / `d72a0e352` (PR #1818, task-553) and `39bde7936` / `a74a075ae` (PR #2014, task-575 / PR #2032, task-600) resolve network encapsulation and interface routing issues in nested VM sandboxes.

Concretely:
- `third_party/granule/pkg/netshim`: Dynamically queries the host interface MTU and passes `granule.mtu=<mtu>` via the VM kernel boot command line.
- `granule-configure-routes` configures the guest VM interface MTU, and `dockerd` in the guest is configured to match the discovered MTU. This prevents silent packet drops on 1460 MTU (GKE CNI) or 1440 MTU (VXLAN/Geneve) networks.
- `pkg/orchestrator/granule_sandboxes.go`: `guestDockerNetworkRepair` dynamically inspects the guest default gateway and dynamically selects non-overlapping subnets (e.g. `172.30.255.1/24` with pool `172.31.0.0/16` on 10.x networks) to prevent `docker0` from hijacking host DNS and model proxy routes.

### Existing coverage
- `third_party/granule/pkg/netshim/guest_test.go` and `guestscript_test.go` test kernel parameter generation and route script parsing.
- `pkg/orchestrator/granule_docker_real_test.go` tests KVM nested VM boot and DNS resolution.

### Gaps and unproven behaviours
- **Live nested VM boot on non-1500 MTU host**: Proving that large TCP payloads (e.g. 64KB HTTP streams or large git pulls) transfer without hanging or packet drops when host MTU is 1460.
- **Docker container networking inside nested VM on 10.240.0.0/24 host network**: Verify that containers started inside the guest can resolve external DNS and communicate with the git proxy without routing loops.

### Walkthrough & test procedure
1. Set up a test host interface with MTU 1460 (`ip link set dev eth0 mtu 1460` in a test netns).
2. Boot a Granule VM guest sandbox.
3. Inside the guest, run `ip link show` and assert interface MTU is 1460. Check `/etc/docker/daemon.json` and assert `"mtu": 1460`.
4. Perform a large git clone (100MB+) and verify transfer completes without TCP stalls or packet loss.
5. In an environment with host gateway on `10.240.0.1`, boot a guest, launch a Docker container inside the guest, and verify container connectivity to host services.

Filed: **Walkthrough: VM guest MTU propagation and docker subnet collision avoidance (docs/test-plans/2026-09-25.md §6)**
