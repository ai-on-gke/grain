## §3. Merge Queue Overlap-Gated Re-Check (`merge_recheck`), Abandon & Base-Hold Metrics, Base-CI Red Streak Confirmation, and Trunk Release Gate Priority

### What changed
- **Overlap-gated merge re-check (`merge_recheck: off | observe | enforce`)** (`9babc06a6`, `d0eda8d93`, `8c3189dbf`, `c082d6559`, `086db08cb`, `8ef2a621e`, PR #4810):
  - `pkg/model/merge_recheck_history.go`, `pkg/orchestrator/mergerecheck.go`, `pkg/orchestrator/sync.go`, `pkg/orchestrator/mergebatch.go`: Evaluates every ready merge against the overlap rule between its GitHub merge-base `F` and the current branch tip `T`. When `F != T`, the rule triggers if the PR and `F..T` share any touched file, share a Go package directory with `.go` changes on both sides, or if `F..T` touched a global build input (`go.mod`, `go.sum`, `package.json`, `package-lock.json`, `.grain/workflows/*`, `Makefile`, `scripts/*`).
  - Under `observe` (the default), single merges proceed immediately while recording the overlap evaluation and subsequent post-merge base CI verdict in `merge_recheck_history`. Under `enforce`, a triggering single merge is routed through a merge batch of 1 on top of `T` before landing.
  - Exposes `mergeRecheck` in `GET/PUT /api/repos/{owner}/{name}/settings` and overlap re-check counters in `GET /api/metrics` (`merges` section).
- **Merge batch abandon reasons & `base_hold_history` metrics** (`c5aa70074`, `e376d22fe`, PR #4792):
  - `pkg/model/merge_batch_history.go`, `pkg/model/base_hold_history.go`, `pkg/orchestrator/basehold.go`, `pkg/metrics/merges.go`: Records structured abandon reasons (`interrupted`, `cancelled`, `timed_out`, `base_moved`, `inherited_red`, `no_answer`, `merge_stopped`, `not_built`, `disabled`) on `merge_batch_history` and tracks per-pass held PR counts, peak PRs held, and PR-hours in `base_hold_history` whenever a base branch is red or holding changes in `base_broken`.
- **Base-branch CI confirmation on a streak of red tips** (`8c9183d0b`, PR #4829):
  - `pkg/orchestrator/basecistreak.go`, `pkg/orchestrator/basebranchci.go`, `pkg/model/base_branch_ci.go`: Tracks consecutive red tips failing the same job(s) on `base_branch_ci` (`RedStreak`, `RedStreakJobs`, `RedStreakSince`, `RedStreakTip`, `LastGreenCommit`). When the streak reaches `grain_config.base_ci_red_streak` (default 2), `confirmBaseBranchCI` confirms the branch red immediately without waiting for a confirmation re-run (which would otherwise be dropped when `main` advances rapidly), files a repair task, surfaces `"<job> red on N consecutive tips since <sha>"` on held changes, and wakes the pipeline steward once per streak.
- **Trunk release gate priority (`PriorityReleaseGate = 6`), infra-verdict auto-rerun, and unified red-CI procedure** (`10b31f7d6`, PR #4877; `bae0509ca`, `4549f6f50`, `7d049ee38`, PR #4849):
  - Ranks default-branch post-merge CI, release runs, and nightly/release-train schedules at `ci.PriorityReleaseGate = 6` (above `PriorityMergeHead`, eligible to spend the budget's repair reserve and hold a capacity reservation from the first refusal).
  - Classifies infrastructure verdicts (`infraVerdict`: cancelled/errored/interrupted runs or failures where every failing job hit a capability/credential/quota/rate-limit error) on release gates and re-runs them once automatically before confirming a red base or filing a repair/triage task.
  - Injects `redCIProcedureSection` (`pkg/orchestrator/run.go`) into repo tasks with Grain CI and tracks CI-fixing behavior in metrics (`4549f6f50`), while ensuring `FixesBaseBranch` repair tasks are not told to skip failures already on `main` (`7d049ee38`).
