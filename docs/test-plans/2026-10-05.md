   - Open Settings → Repos, attach `grain-ci` to a demo repo, and save. Assert no "unknown
     capability" error.
   - Run each CLI form against the demo daemon: `grain repo capabilities -set grain-ci`,
     `grain settings -default-capabilities grain-ci`, and
     `grain create -capability grain-ci …`.
   - Push to the repo (or use `-fake-ci`), and assert that a grain CI run starts.
2. Port check:
   - Find the tasks or PRs that landed `6172e1205` and `5bd2827bb`, and read their merge-queue
     notes.
   - Check whether a port task was filed and what state it is in. If none was filed and the reason
     is a bug in the port path, fix it with a regression test. If not, file the port with
     `propose_task(branch: "candidate")`, citing the commit, rather than cherry-picking by hand.
3. Run `go test ./tests/deploy/ -run Granule` on `main`. If `kind` with `/dev/kvm` is available,
   assert the daemon pod starts without the `-upgrade-image` refusal. Otherwise record that it is
   not.

## Standing environment notes for the filed tasks

- **Branch.**
  - §1-§9 target `candidate`, which holds every commit they cover.
  - §10 targets `main`.
  - Each report names the tested commit and confirms it with `git branch -r --contains <sha>`.
  - `bwsalmon/grain` declares `port-branches: [main, candidate]`, so a fix merged on one branch
    files a port task onto the other. Do not cherry-pick by hand. Since `7b52be1af`, a run's prompt
    also says this, and never merge `main` into `candidate` or the other way round.
- **Overlap.** The 10-04 daily UI run's findings A and B are already filed. Before filing a
  finding, check `docs/test-runs/` and the open tasks for the same finding. If it is there, link to
  it instead of fixing it twice.
- **CI authority.** Grain CI (`.grain/workflows`) is the only merge gate. GitHub Actions checks are
  informational.
- **Browser tests.**
  - Set `PLAYWRIGHT_BROWSERS_PATH=/var/cache/playwright`.
  - Build the UI (`cd ui && npm ci && npm run build`) so the run uses the production bundle in
    `pkg/ui/static`.
  - Run against the real `go run ./cmd/grain demo -addr 127.0.0.1:0 -open=false`.
  - Do not mock grain's own APIs or React. Stub only GitHub (githubsim), Google OAuth, live model
    sessions, registries you cannot reach, and real cloud APIs, and list each stub in the report.
  - Slowing or failing a real response with `page.route` is not mocking it.
- **Formatting.** `npm run format` in `ui/` for UI changes, and `gofmt` for Go.
- **Security suite.** `make security` must stay green, and no `.grain/baselines/` count may rise.
- **Trust-boundary hold.** A fix touching a trust-boundary path is held for security review before
  it auto-merges, and that is expected. Examples: `pkg/gitproxy`, `pkg/relay`, `pkg/mcp`,
  `pkg/ci`, `pkg/orchestrator`, `pkg/ui` auth, `tests/security`, `.grain/triggers/**`, and (since
  `507b850a0`) `.grain/merge-rules.yml`.
- **Reports.** Each task writes `docs/test-runs/2026-10-05-<feature>.md`, or the date it runs. The
  report covers the environment, tested commit, commands, outcomes, findings (each with a
  deterministic reproduction), stubs, fixes and the CI verdict.
- **Known flakes.** See the repository notes:
  - `RepoPage.test.jsx` "shows the inherited global value…";
  - `src/App.narrowing.test.jsx:89`;
  - `ui/e2e/team_declarations_ci_walkthrough.spec.js:229`.

  Record a recurrence. Do not chase it in a feature task.
