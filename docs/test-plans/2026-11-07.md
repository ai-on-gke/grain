## §2. Cloud-hosted instance runtime, PostgreSQL default, offline migration, backups & externalized state

### What changed
- **Fresh-install local PostgreSQL default & loopback auth** (#679, #718):
  - `scripts/setup.sh` provisions a local `grain-postgres.service` (pinned by image digest) on fresh installs while preserving SQLite on existing SQLite installations. Loopback TCP connections require `PGPASSWORD` (`scram-sha-256`, #718).
  - The PostgreSQL adapter serializes read-write transactions like SQLite's write lock and advances the change token on every commit (#679).
- **Offline-only store migration & `migrate-local-to-gke.sh` guard** (#716, #823):
  - Live online store migration routes were removed (#716): migrating SQLite → PostgreSQL (`grain upgrade-postgres`) refuses a live store, the daemon refuses to start against a stale pre-migration SQLite file once migrated, and Settings → Database Backend is read-only with offline instructions.
  - `scripts/migrate-local-to-gke.sh` refuses to run when the source host's store is the local PostgreSQL container rather than SQLite (#823).
- **`grain backup` for PostgreSQL** (#830): `grain backup` snapshots PostgreSQL stores via `pg_dump` alongside SQLite backups.
- **Single-writer lock, DB webhook cursor & `-disable-self-upgrade`** (#740):
  - On `-db-driver=postgres`, `grain daemon` acquires a PostgreSQL single-writer lease, fences split-brain writes immediately on lock loss, and stores the GitHub webhook cursor in PostgreSQL (resetting a cursor that sits ahead of a fresh store).
  - `-disable-self-upgrade` (with optional `-management-url`) disables in-place self-upgrades on managed/cloud instances and points Settings → Upgrade at the external management console.
- **Generalized verifier, Secret Manager, GCS object store & GCE instance init** (#742, #738, #737, #807):
  - `-ui-require-iap` generalized to `-ui-require-verifier` (`iap`, `registry`, etc., #742), with sanitized stderr labels in `grain access-code`.
  - `-secrets-backend=secretmanager` and `-secrets-sm-prefix` (#738) store secret values in Secret Manager while indexing metadata in Postgres `secret_entries`.
  - `-object-store` (#737, `pkg/objectstore`) offloads run transcripts (redacted before upload), CI artifacts (scoped per daemon), and console session bundles, failing closed on archive/redaction errors.
  - `grain-instance-init`, replaceable GCE release image baker, and `-deployment-owner` bootstrap managed VM instances (#807).

### What CI proves
- `pkg/model/postgres/*_test.go`, `pkg/backup/backup_test.go`, `pkg/objectstore/*_test.go`, `pkg/cli/secrets_sm_test.go` and `pkg/cli/disable_self_upgrade_test.go` unit-test individual adapters and flags.
- `tests/deploy/database_test.go`, `tests/deploy/instance_init_test.go` and `scripts/migrate-local-to-gke_test.sh` check script contracts.
- Playwright `database-backend-layout.spec.js` and `disable-self-upgrade.spec.js` check UI rendering on stubbed config responses.

### What is NOT proved

2. **PostgreSQL single-writer lock & split-brain write fencing**:

3. **`-disable-self-upgrade` + `-management-url` live daemon & UI behavior**:
