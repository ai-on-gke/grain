# Nightly new features test plan: 2026-10-01

This plan covers what merged into `candidate` and `main` since `docs/test-plans/2026-09-30.md`
(`a0fcf7484`, 2026-09-30 03:02 UTC) through `main` at `5ae6d177a` (PR #2437) and `candidate` at
`dec130fa6` (PR #2428). That is roughly 90 non-merge commits, almost all of them on `main`.

**Where the code is.** Except for `0472c7b1f` (blocker task-ID normalization) and `bef53864f`
(Claude Code CLI 2.1.286), none of this batch is on `candidate` yet. It is the security-hardening
wave that followed the 2026-09-30 security audit (#2370-#2425). `candidate` only got the back-merge
of yesterday's test runs (`1b690b993`, PR #2428). So the walkthroughs for §1-§7 are filed against
**`main`**: running them on `candidate` would test code that does not have the feature. Only §8 is
filed against `candidate`. Once the next release cut puts this batch on `candidate`, the reports
these tasks write are the qualification evidence for it.

Focus areas:

1. **Trust-boundary security hold on auto-merge, and capability-escalated proposals.** `pkg/trustboundary`, `securityhold.go`, the `system:security-review` template, and `model.EscalatedCapabilities`.
2. **CI gate integrity.** Base-branch workflow gating (`GateOnBase`), auto-retried jobs shown as running, quarantine `test_name` literal matching, checkpost failure retention, and release secrets withheld from undeclared jobs.
3. **Web UI/API perimeter hardening.** Host guard (421), CSRF via `CrossOriginProtection`, CSP and security headers, unauthenticated callers limited to loopback (`-ui-trusted-cidrs`), safe attachment serving, body limits (413), sanitized 5xx and panic responses with `ref`, admin-only database routes, and identity no longer taken from `?user=`.
4. **Team-scoped reads and team-scoped URLs.** Task and secret-metadata reads filtered by the caller's teams, `POST /api/teams` gated, `/teams/<id>/settings`, and team-prefixed repo routes.
5. **Credential proxy hardening.** Model proxy endpoint/method allowlists, body cap and token lifetime; git proxy host/TLS pinning, redirect refusal, narrowed App tokens, token sealing and refresh; pkgcache GHCR push refusal and GET-only GitHub; secrets-repo credential host check; state-repo push fsck.
6. **Sandbox isolation and the fixed sandbox port block.** NetworkNone egress (link-local, IPv6 DNS, pkgcache), GCE metadata block, fail-closed host firewall, ARP-spoofing filter, unprivileged VM containers, hardened local containers, and `-sandbox-port-base` 9728/256.
7. **Remote executor, relay and tunnel hardening.** MCP tunnel argv allowlist and pinned GitHub host/TLS, `GRAIN_EXECUTOR_SOCK` kept out of agent environments, checksummed installer, relay `daemon_id` hijack, WebSocket Origin check, no `?token=`, and mux flow control.
8. **Blocker task-ID normalization and Claude Code CLI 2.1.286** (on `candidate`).

The `tests/security` suite added in `39bfc6d6f` (`make security`, also run by the `go` CI job)
proves the static rules and the identity/containment entry points. It sets the floor for §3-§7, and
each section below says what the suite does not reach.

## 1. Trust-boundary security hold on auto-merge, and capability-escalated proposals

`25b12a037` (#2425 Layer 2a) and `e482cb075` (#2409). Both close paths by which work could land, or
be queued, without a person seeing it.

What changed:
- `pkg/trustboundary/trustboundary.go` adds a versioned, in-code path list (`trust-boundary/v1`) covering auth/routes (`pkg/ui/server.go`, `principal.go`, `access.go`), `pkg/mcp/sandbox_tools.go`, `pkg/orchestrator/`, the credential proxies (`pkg/gitproxy`, `modelproxy`, `pkgcache`, `relay`, `tunnel`), `deploy/`, `*.tf`, `.github/workflows/`, `.grain/`, Granulefiles, Dockerfiles and `scripts/setup.sh`.
- `pkg/orchestrator/securityhold.go`: before a run that would auto-merge is marked completed, `finishWithPullRequest` lists the PR's files (`ListPullRequestFiles` now also returns a rename's previous path). ## 3. Web UI/API perimeter hardening

`e1288b880` (#2380), `06afc2771` (#2371), `0e3fb0426`, `e4b4f755c` (#2370), `e7c55b578` (#2374), `6a73e1620` (#2423), `98d50c673` (#2424), `1f580349e`, `5b165faa6` (#2373), `39bfc6d6f`, `d800e2969`, `ecb536e40`, `b3034209e` and `2d9f80d41`.

What changed:
- `ui.HostGuard` answers 421 to an unknown `Host`. Allowed names are IP literals, `localhost` and `*.localhost`, the machine's hostname, `*.ts.net`, the listen address, and entries in `-ui-allowed-hosts` (`*` disables the check). The guard applies when `-ui-addr` names a specific address. `grain demo` is guarded.
- `http.CrossOriginProtection`: unsafe methods from cross-site or same-site browsers, or with a mismatched `Origin`, get a JSON 403. Requests without browser metadata (CLI, curl) pass.
- Every response carries a CSP (`script-src 'self'`, `frame-ancestors 'none'`), `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, COOP and `Permissions-Policy`.
- A request with no verified principal falls back to the admin OS-user actor only from loopback, in-process callers, or `-ui-trusted-cidrs`. Anything else gets a 401, except `/api/config` and `/api/auth/*`. Identity headers are believed only from those same sources. `?user=` is no longer an identity source. `POST /api/teams` is allowlisted. A store error on the allowlist returns 503.
- Attachments are served inline only for png, jpeg, gif, webp, bmp and text/plain; anything else is `application/octet-stream` with `attachment` disposition, plus `default-src 'none'; sandbox`.
- JSON bodies are bounded: 8 MiB by default, with attachment routes sized for their attachments. Oversized bodies get 413.
- `pkg/apierror`: a 5xx response says only `{error, code, ref}` and the full error is logged under `ref`. Handler panics produce the same sanitized 500.
- `/api/database/test`, `/upgrade` and their aliases require system admin, and the test route returns a generic error. The System pane log endpoint redacts credentials. The markdown URL allowlist is pinned. `/api/executors/bin` serves only grain binaries.

### Existing coverage
Unit tests cover each handler: `csrf_test.go`, `security_headers_test.go`, `recover_test.go`, `readjson_test.go`, `database_test.go`, `server_test.go` (attachments) and the HostGuard tests. `tests/security` covers identity headers, session tokens and static rules. `2d9f80d41` holds every `pkg/ui` route to an authorization table.

### Gaps
- No real browser has loaded the production bundle (`pkg/ui/static`) under the new CSP. Some inline style, `blob:` image, web worker or font may be blocked, and only a browser console shows that. Every main view should be visited with Playwright while CSP violations (`securitypolicyviolation` and console errors) are collected.
- DNS-rebinding style requests (`Host: evil.example` against the demo's loopback port) have not been tried live, nor has the Vite dev proxy path (`npm run dev`), which must still work.
- A real cross-origin page has not been used: serve an HTML page from a second local port that `fetch`es a `POST` with `text/plain` to the daemon, and submits a form. Both must be refused, while the UI's own actions (create task, close task, team create) still work.
- The daemon has not been bound to a non-loopback interface (for example the host's bridge IP) to confirm that an unauthenticated curl from that address gets a 401, that `X-Grain-User` from it is ignored, and that adding `-ui-trusted-cidrs` restores access.
- No one has uploaded `text/html` and `image/svg+xml` attachments through the API and opened them in the browser to check they download rather than render, and that image previews still render.
- Not tried live: a 9 MiB JSON body (expect 413); create-task with the maximum attachments (must still succeed); forcing a storage error, for example a read-only SQLite file, to check the 5xx carries a `ref` that appears in the daemon log; and the database routes as a non-admin (expect 403).

### Walkthrough & test procedure
1. Build the UI (`cd ui && npm ci && npm run build`) and start `grain demo` on `main`. Use `PLAYWRIGHT_BROWSERS_PATH=/var/cache/playwright`.
2. Playwright CSP sweep: sign in, then visit the board, task detail (with markdown containing images and links), CI, repos, teams, settings, system and the merge queue. Fail on any CSP violation or console error. Assert that every response has the documented security headers.
3. Use curl with `-H 'Host: evil.example'` (expect 421), `Host: localhost:<port>` (expect 200), and the demo restarted with `-ui-allowed-hosts '*.example'` (expect 200 for `a.example`).
4. Cross-origin: serve `attacker.html` on a second port. Have Playwright open it and fire `fetch(daemon + '/api/teams', {method:'POST', mode:'no-cors', body:'{}'})` and a form POST. Assert, through the daemon API, that nothing was created. Then perform the same action through the real UI and confirm it succeeds.
5. Trusted sources: run the daemon (`grain daemon`, not demo) with `-ui-addr 0.0.0.0:<port>`. Curl from a non-loopback source (a network namespace or container on the docker bridge) with no auth (expect 401 on `/api/tasks`, 200 on `/api/config`), with `X-Grain-User: admin` (expect 401), and with `?user=admin` (expect 401). Restart with `-ui-trusted-cidrs <that cidr>` and expect 200.
6. Attachments: create a task with `text/html` (`<script>`), `image/svg+xml` (`onload`) and png attachments. In Playwright, clicking the html and svg links must download and never execute; the png preview must render.
7. Limits and errors: send a 9 MiB `POST /api/tasks` (expect 413); a valid maximum-attachment create (expect success); a forced 5xx (expect a body with `ref`, and the same `ref` in the daemon log with the full cause); `POST /api/database/test` as a non-admin (403) and as an admin pointing at a closed port (a generic message only).
8. Any CSP breakage found should be fixed in `pkg/ui/security_headers.go` or the component, with a Playwright regression spec under `ui/e2e/`.

## 5. Credential proxy hardening

Model proxy: `cdae1634c`, `4eec98e86`, `2e97cd4c8`, `a122ccb6c`, `9be4c051c` and `df7b186e3`. Git proxy: `c321c7116`, `e2d03a389`, `ac3a1ab97`, `3debffddb`, `b587de053`, `f3e4cccd5` and `964ca0ade`. Package cache: `6fd1bf2d6` and `93702cc71`. Also `c3603fc31` (secrets repo).

What changed:
- **Model proxy.** Each vendor has an allowlist of paths, methods and query parameters; anything else is refused before the credential is attached. The default body cap is 64 MiB (413 above it). Tokens end with the run that minted them; the old flat 24h lease is gone. The custom-backend token is revoked at run end.
- **Git proxy.** It forwards only to the configured host. A host string like `github.com@evil.example` is refused, as is plain HTTP off loopback. It refuses redirects and applies timeouts. GitHub App installation tokens are narrowed to the one repo. Sandbox tokens are sealed with their own key, so importing a new secrets key no longer breaks dispatch. A live run's token is refreshed past the 24h TTL. Pushes into the state repo run `fsck` and are fenced.
- **Package cache.** It never spends the daemon's GHCR credential on a push scope. Its GitHub routes forward GET/HEAD (and POST only to `git-upload-pack`/`git-receive-pack`), and the shared resolver no longer forwards out-of-allowlist DNS for NetworkNone clients (no DNS tunnel).
- **Secrets repo.** Credential-ladder tokens are sent only to github.com remotes.

### Existing coverage
Unit tests for each package (`pkg/modelproxy`, `pkg/gitproxy`, `pkg/pkgcache`, `pkg/secretsrepo`) against `httptest` upstreams. `tests/e2e/team_pat_scoping_gitproxy_isolation_walkthrough_test.go`.

### Gaps
- No test drives a real agent CLI through the proxy: Claude Code 2.1.286 and Codex through the model proxy. The allowlists may be missing an endpoint the CLIs actually call (count_tokens, `/v1/models` GET, streaming query parameters, Gemini `:streamGenerateContent?alt=sse`). That would break real runs, and only a live CLI shows it. The CLI can be pointed at a local stub vendor that records requests, so no real key is needed.
- Not shown live: that a token is unusable right after its run ends, both for a normal backend and a custom backend, with a curl replay of the captured token after completion.
- The git proxy has not been run against a local HTTPS git server that 302s to another port (it must not follow), a misconfigured host string (refused at startup or on request), or the secrets-key import followed by a new dispatch (it must still mint git tokens).
- A state-repo push of a tree containing a `.git` entry or a malformed mode has not been tried through the proxy; it must be refused.
- Pkgcache has not been sent a `docker push` scope token request, which must not return a push-capable token, or a `POST https://api.github.com/...` through the transparent proxy, which must be refused.

### Walkthrough & test procedure
1. On `main`, start the daemon with a stub vendor upstream: a small Go or Python server recording method, path and query, with the model proxy pointed at it.
2. Run real `claude` (2.1.286) and `codex` CLIs against the proxy, as a sandbox would, through a scripted prompt that uses streaming, tools and token counting. Assert that every request they make is allowed, and list the paths used in the report. Then `curl` the proxy with `DELETE /v1/models/x`, `GET /v1/files`, a 65 MiB body and an unknown query parameter; each must be refused without reaching the stub.
3. Capture a run's proxy token, let the run finish, and replay it. Expect 401, for both the default and a custom backend.
4. Git proxy: point the configured host at a local TLS git server that 302s; the push or fetch must fail without following. Configure `github.com@127.0.0.1`; it must be refused. Import a new secrets key through `POST /api/state-repo/secrets-key`, then dispatch a task; it must mint a token and clone.
5. From a sandbox-equivalent client, push a crafted tree (a `.git` entry built with `git hash-object --literally` / `mktree`) to the state repo through the proxy. It must be refused, and the daemon's state must be untouched.
6. Pkgcache: request `scope=repository:x/y:pull,push` and assert there is no push token. Send `POST` to `api.github.com` through the transparent route and expect a refusal.
7. Any CLI endpoint the allowlist misses is a real bug. Fix it in the vendor allowlist and add a regression test.

## 6. Sandbox isolation and the fixed sandbox port block

`c3b8c7c0e`, `93702cc71`, `81c8c9f06`, `e18a4c613`, `9a153282e`, `07d076fe2`, `e62a44b52`, `b2505035a`, `77dd6da67`, `1dc3b7a5d` and `f6b6647fe`.

What changed:
- **NetworkNone granule VMs.** No link-local forward accept and no IPv6 DNS. The host firewall install fails closed (missing `nft`, an uninspectable container, or a refused rule fail the Acquire). Both IPv4 and IPv6 are jumped to drop. `nft` is looked up on fallback paths.
- `81c8c9f06`: containers and guests cannot reach `169.254.169.254`.
- **Granule.** `tc u32` filters on the tap ingress (`spliceGuest`) stop a guest ARP-spoofing the gateway or neighbours and forging a source MAC. VM containers run unprivileged, with only `/dev/kvm`, `/dev/net/tun` and `CAP_NET_ADMIN`.
- **`-container-sandboxes`.** `--cap-drop ALL`, `no-new-privileges`, `--pids-limit 4096`, swap capped, and the container is off the shared default bridge.
- **Port block.** All six sandbox-facing services (git proxy, three model proxies, pkgcache, actions cache) bind `-sandbox-port-base` (default 9728) plus a fixed offset in a 256-port block. Startup logs the range. A taken port fails only that service; the git proxy's also halts dispatch, which needs it, but leaves the other five up. `-sandbox-port-base=0` restores ephemeral ports.

### Existing coverage
`cmd/grain/sandboxnet_test.go` covers the offsets, alignment and avoidance of the ephemeral range. Granule and orchestrator unit tests cover the rule construction. `e2e` tests use `-sandbox-port-base=0`.

### Gaps

## 7. Remote executor, relay and tunnel hardening

`5f0137b69`, `c2da232d0`, `27f7a1866`, `a9edc7c2e`, `d2a9d9cf4`, `0c07e84e3`, `93c4c3943`, `140bf9271` and `18cb8f40a`.

What changed:
- **Executor MCP tunnel.** It is served only for argv that grain issued, and the GitHub host, TLS and data dir are pinned. `GRAIN_EXECUTOR_SOCK` is no longer in the agent's or its commands' environment.
- `/api/executors/install.sh` verifies a SHA-256 for every download (`--sha256`), keeps the token off the command line, and writes the token file with 0600 from the start.
- **Relay.** A live `daemon_id` cannot be taken over (409, `ErrDaemonIDInUse`), and an unknown id gets no fallback. WebSocket upgrades check `Origin`. `?token=` is no longer accepted by the relay or the tunnel gateway.
- **Mux.** 1 MiB per-stream credit-based flow control and bounded receive buffers.
- Relay, tunnel gateway and checkpost responses no longer carry raw errors.

### Existing coverage
Unit tests in `pkg/modelexec`, `pkg/relay` and `pkg/tunnel`, plus `tests/e2e/remote_executor_dispatch_e2e_test.go` and `remote_executors_relay_e2e_test.go`.

### Gaps
- No live remote executor (a second process or host running `run-remote-executor.sh` from the daemon's `install.sh`) has been run end to end: install with the correct `--sha256`, then a wrong one (it must abort before executing anything), and check the token file mode.
- A task dispatched to that executor has not been checked for: `env` in its agent shell lacking `GRAIN_EXECUTOR_SOCK`, and a crafted tunnel stream with `-sandbox-root /` or `-github-host evil` argv being refused.
- The relay has not been run: start it with the daemon connected, have a second client register the same `daemon_id` (expect 409 while the first is live; a reconnect after the first dies must work), send a WebSocket upgrade with `Origin: https://evil.example` (expect refusal), and send `?token=` (expect 401).
- Untested: a slow consumer, with a large proxied download through the tunnel that is not read; daemon and relay memory must stay bounded.

### Walkthrough & test procedure
1. On `main`, start the daemon plus `grain relay` locally. Install a remote executor using the served `install.sh` into a temporary prefix: once with the correct `--sha256`, once with a wrong one.
2. Dispatch a stub-agent task to the executor. The agent runs `env` and tries to connect to any `GRAIN_EXECUTOR_SOCK`. Assert it is absent.
3. Using a test client holding the executor token, open an MCP tunnel stream with forged argv. Assert the refusal and an audit log line.
4. Relay checks as listed above, with curl or `websocat`. Record status codes.
5. Flow control: proxy a 500 MiB response through the tunnel to a client that reads nothing for 30 s. Sample RSS and assert it stays under about 64 MiB of growth.

Filed: **Walkthrough: remote executor MCP tunnel, installer and relay hardening (docs/test-plans/2026-10-01.md §7)**
