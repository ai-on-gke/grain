## §1. Retired in-process capability aliases no longer grant

### What changed (PR #1455, [Task #3621](/tasks/3621))
- **Grant time** (`2246226c3`): `model.CanonicalLegacyGrant(s)` now rewrites only aliases a build outside core registers through `capability.Register`'s `Aliases`. Core's old alias table becomes a migration-only copy (`retiredGrantReplacements` / `retiredGrantMultiReplacements`, read through `model.RetiredGrantsBecame`). Bare names — `gcp-key`, `gcp-key:<name>`, the model proxies, `gemini-key`, `image-signing`/`registry-push`/`package-publish`, `grain-ci`, `bootstrap-playbooks`, `github-credential:<name>`, `read-issues`, `github-sandbox`, `self-debug`, `local-scripts:<name>` — no longer grant anything. The bare-name branches are gone from `IsGrainSourceGrant`, `IsGrainCIGrant`, `IsGrainJournalGrant`, `IsGrainHealthGrant`, `IsGrainHostExecGrant`, `ParseGrainSQLGrant`, `IsGitHubReadIssuesGrant`, `IsGitHubSandboxRepoGrant`, `IsBootstrapPlaybooksGrant`, `IsGitPushAnyRefGrant`, the run's tool-grant lists and `APIAliasPreset`.
- **Still bound for safety:** the state-repo import (`pkg/staterepo/decl.go`) upgrades older `grain/config` exports through `RetiredGrantsBecame`; the catalogue keeps a `settings/capabilities.yml` entry naming a retired capability bound to what it became; local policy (`pkg/policy`, `816693080`) keeps `deny: [self-debug]` refusing `api:self-debug` and `grain#source`, and deny globs cover aliases registered outside core (`27c548679`).
- **Refusals:** a CI job declaring a retired bare name is refused, naming what to declare (instead of waiting forever for a provider). `.grain/` declarations keep bare names as written (`TestSyncRepoDeclarationsKeepsRetiredBareNamesAsWritten`) and are no longer rewritten to the repo-scoped CI read (`0b6f21eef`).
- **Remaining reads closed:** `SandboxNamespaceScope` stops opening journal/health/issues/SQL reads for bare names; the daemon's `grantTools` keys journal tools by `grain#journal` alone (`7a7020ff7`); `model.GitCredentialName` matches only canonical `repo#credential` grants, while token-deletion holder checks still scan legacy rows (`e66dae83d`); `Store.TaskCIMode` ignores a bare `grain-ci` in `DefaultCapabilities` (`27c548679`).
- **UI:** Settings → Capabilities' `*-deprecation-notice` alerts and three classic specs are removed; `ui/e2e/github-server-card.spec.js` checks the Capability servers card at 1280/390 px.

### What CI proves
- Unit/contract tests across `pkg/capability/*`, `pkg/cli/*` (`mcpserver_grants_test.go`, `ci_policy_test.go`), `pkg/daemon/ci_grant_spelling_test.go`, `pkg/policy/policy_test.go` (`TestRegisteredAliasGlobDenyMatchesCanonicalGrant`), `pkg/model` (`TestTaskCIModeHonoursCanonicalGrainCIAndIgnoresRetiredBareName`), `pkg/gitproxy/credential_fidelity_test.go`, `pkg/model/postgres/legacy_grant_migration_test.go`, `tests/security/{task_grant_escalation,mcp_tools}_test.go`, and the canonical-grant e2e walkthroughs.

### What is NOT proved

No migration in this range rewrites them. Nobody has opened such a store with the new build and checked what each row now grants, what Settings and `/next/` show for it, and whether a scheduled task silently loses `grain#ci` / `api:self-debug` / `repo#credential` mid-flight.
2. **Refusal messages on the real paths:** filing (`POST /api/tasks`, `grain_submit_task`, `propose_task`), template/schedule save, `.grain/` CI job declaration and `request_access` with a bare name — each should refuse (or keep as written and visibly grant nothing) with a message naming the canonical replacement, never a 500 or a silent drop.
3. **Local policy and `settings/capabilities.yml` with retired names** on a live daemon: `deny: [self-debug]`, `deny: ["gcp-key*"]` and a catalogue entry for `grain-ci` still refuse/bind the canonical capability at dispatch, in the run's MCP tool list and in the sandbox `grain` CLI (`grain ls src://…`, `grain ci log`).
4. **In-sandbox effect on a real run:** a task row still carrying `github-credential:<name>` pushes with the default credential (not the named one); a row carrying bare `grain-log` gets no journal tools; a bare `grain-ci` in `default_capabilities` no longer selects grain CI.
5. **`/next/settings/capabilities` and the repo CI picker** (`/next/repos/<owner>/<name>/ci`) render retired rows sensibly (named by what they became, no deprecation notice, no overflow) at 1440/390 px, light/dark.
6. **`grain/config` round trip:** importing an export written by `v3.5.x` naming bare names upgrades them; re-exporting writes canonical names only.

## §6. Review context carried across PR reviews

### What changed (PR #1474, [Task #5323](/tasks/5323))
- **Earlier reviews** (`10acc89a9`): a review of head N+1 gets an "Earlier reviews of this pull request" section listing every earlier review task of any kind on the PR with its verdict, pushed commits and open/answered `add_review_comment` questions (one line each with `path:line`, ~2 KB cap). Findings are persisted on the review task before draft submission so they survive a 422 draft-review collision; queued dependent reviews refresh when an in-flight earlier review finishes.
- **Incremental security-hold re-reviews** once a prior trust-boundary review completed, falling back to full on non-fast-forward updates, >20 touched files, rule version changes, or base merges bringing in trust-boundary paths.
- **Parallel reviews:** two or more review kinds on one head get a "Parallel reviews of this head" section naming each other and pointing at `grain pr open` to avoid duplicate questions.

## §7. Host stop vs drain end to end (`KillMode=mixed`, `ErrHostdStopped`)

### What changed (PR #1469, [Task #5430](/tasks/5430))
- `grain-agentd install` writes `KillMode=mixed` into the systemd `--user` unit: SIGTERM goes to `grain-agentd` alone so `Serve` marks running CLIs interrupted before exiting, and remaining cgroup processes are SIGKILLed after exit/crash.
- `agent.ErrHostdStopped` and `hostd.Exit.Stopped` (`Exit.Draining` with non-empty `Exit.Error`) make `HostdHost.Run`, `runhost.Hostd.Attach` and `orchestrator.classifyRunEnd` record host stop/restart/crash as "the host agent stopped or restarted while the run was going; the run goes back to the queue" instead of "draining for its own upgrade".

### What CI proves
- `TestHostdHostStoppedVsDrainingExits`, `TestAdoptedHostdRunStoppedWithoutDrainIsRecordedInterruptedAsStopped`, `TestHostdStopWithoutDrainSurfacesErrHostdStoppedOnRunAndAttach`, `pkg/agentd/install_test.go` (unit text) — no real systemd.

### What is NOT proved (the end-to-end chain [`2026-11-13-afternoon.md`](2026-11-13-afternoon.md) deferred to this batch)
1. On a real systemd `--user` host (`loginctl enable-linger`; see `docs/test-runs/2026-11-13-hosts-env-drain.md` for the setup), with two detached fake-agent runs going: `systemctl --user stop grain-agentd` → both runs recorded with the *stopped/restarted* reason, requeued, no surviving CLI processes (`systemd-cgls`, `pgrep`); `restart` → runs adopted or requeued per `canAdoptLiveSpool`, never orphaned; `kill -9` of `grain-agentd` → cgroup cleaned, reason says stopped/crashed; `grain-agentd -drain` / `SIGUSR1` → still recorded as *draining for upgrade*.
2. An existing install upgraded in place: does re-running `grain-agentd install` (or the upgrade path) rewrite an old unit without `KillMode=mixed` and `daemon-reload` it?
3. `/next/fleet` and the task conversation show the new reason text, and the requeued run dispatches again.

### Walkthrough & test procedures
1. Install systemd user units in the sandbox VM, build `HEAD`, register the host against a real `grain daemon -sandbox-port-base=0` (SQLite and PostgreSQL), drive items 1–3 with a fake agent CLI that sleeps and traps SIGTERM (helpers under `docs/test-runs/2026-11-14-host-stop/`).
