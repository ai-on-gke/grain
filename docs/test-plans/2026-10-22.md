## 1. Config Repository (`grain/config`) Mutually Exclusive Internal vs. External Read-Only IaC Modes

**Commits:** `41762bd9b`, `b2cd20dbc` (main: `b608ea2fd`, #4354), `adad9a367` (main: `981f505b2`, #4354)

### What changed
- Replaced bi-directional `grain/config` mirroring (`b2cd20dbc`) with two mutually exclusive configuration repository modes (`41762bd9b`):
  1. **Internal mode (`Remote == ""` — default):** Grain hosts `grain/config` locally via `gitproxy.LocalRepository` and `StateRepoPullRequestClient`, exports UI settings mutations into `grain/config` on each sync cycle, and labels the action button `"Export now"`.
  2. **External mode (`Remote != ""`):** Grain pulls and applies configuration from the configured external Git repository in strict read-only Infrastructure-as-Code (IaC) mode (`staterepo.SyncExternal`), never exports or pushes daemon-generated commits to origin, disables hosting `grain/config` locally (removing `grain/config` from local Git proxy hosting and native PR endpoints), labels the sync button `"Pull now"`, and marks repo-managed UI settings and API mutators read-only (`409 Conflict` / refusal).
- In External mode, `SettingsPage` renders an info banner (`data-testid="external-config-repo-banner"`) reading `"Configuration is read-only and managed in <repo> (<branch>). Switch to the internal config repository in Config Repo settings to edit settings in the UI."` and provides `SettingsReadOnlyContext` (`readOnly = true`) across all sections except `/settings/config-repo` and `/settings/preferences`. Within `/settings/git` and `/settings/models` (`CredentialsSection.jsx`), secret/credential management remains available while repo-managed settings are locked.
- `grain state status`, `grain state repo [-branch B] [-token-file T] [URL | -none]`, and `grain state sync` report and operate according to the active mode (`internal` vs `external (read-only IaC)`).
- `NewStateManager` records initial `state-repo.json` settings so `reconcileRepo` only calls `ConfigureMirror` when `state-repo.json` actually changes (`adad9a367`).

### What CI proves

  - Navigating across `/settings/general`, `/settings/models`, `/settings/git`, `/settings/repositories`, `/settings/sandboxes`, `/settings/caches`, `/settings/ci`, `/settings/config-repo`, and `/settings/preferences` in a real browser (`1280x800` and `390x844`) to verify where `data-testid="external-config-repo-banner"` appears, which controls are disabled, and that secret/credential entry and `/settings/config-repo` mode switching remain interactive.

## 3. Console Session Lifecycle Controls (Stop, Restart, Reset/Delete), Backing-Task Redirects, and Session `WorkTree`

**Commits:** `49cfebd4f`, `882d00120`, `3a81d0003` (#4380)

### What changed
- Hid the raw backing `model.Task` implementation detail on console session views (`ConsoleSessionPage.jsx`) and redirected direct `/tasks/{id}` navigation for session-backed tasks (`console-session:<id>` tag) to `/session/{id}` (or `/director` for `director`) (`49cfebd4f`).
- Rendered `WorkTree` disclosure on `ConsoleSessionPage` whenever a console session has filed follow-up tasks (`filedBy`), keeping the session's spawned task tree accessible after `/tasks/{id}` redirects (`882d00120`).
- Added first-class console session lifecycle endpoints and UI controls (`49cfebd4f`):
  - `POST /api/console-sessions/{id}/cancel`: stops an in-flight or queued session turn via `Client.Stop` and returns the session to `awaiting_reply`, wired to a `Stop` button in the session chat composer.
  - `POST /api/console-sessions/{id}/restart`: stops any active turn, closes the old backing task, and synchronously files and parks a replacement session task with optional `carryHandover: true` (carrying over the previous task's latest standing handover summary) or `carryHandover: false` (tagging the closed task with `console-session-reset` so the session starts completely fresh).
  - `DELETE /api/console-sessions/{id}`: stops any active turn, closes and tags the backing task with `console-session-reset` so recreated sessions start fresh, and preserves an empty non-nil `ConsoleSessions` slice (`[]model.ConsoleSession{}`) so deleting `director` is not resurrected by `ConsoleSessionsOr`.
- Wired `ConsoleSessionPage`'s `onSaved` callback in `App.jsx` to refresh `sessions`, the open session's `task`, and the `tasks` list together so `Stop`, `Restart`, and capability saves update the session pane and list immediately without waiting for the next background poll tick (`3a81d0003`).

## 4. Waiting Tasks, `PendingQuestion` Callout, `/inbox` Pre-Fetch, `wait_for_task` Parked UI, and Quota/Budget Contention

**Commits:** `95073d9ec` (#4313), `fb6d2bad7`, `34166a920`, `9060e0a2f`, `44048b35f`, `b0a21c2bb`, `f0ace8dd3` (main: `6ffed3f5a`, #4339), `e9fad2b64` (main: `438cb660e`, #4355), `daf546150` (main: `f14fad6fa`, #4374), `d21320e92`

### What changed
- **`wait_for_task` MCP tool & Parked UI (`95073d9ec`, `fb6d2bad7`, `34166a920`, `9060e0a2f`, `44048b35f`):**
  - Added the `wait_for_task` MCP tool (`POST /api/tasks/{id}/wait-task`), allowing a running agent to either block (`until: "closed"` or `"merged"`, crediting wait time back to the run's deadline) or park (`park: true`, or when `timeout_seconds` exceeds remaining run budget), recording `depends_on` and ending the run as `parked` (refusing to park with unpushed/uncommitted work unless `force: true`).
  - `GET /api/tasks/{id}` now includes `parked: true` when the task's latest run ended as `parked`, and `DetailOverlay` renders its dependency status as `"Waiting on #X"` while `TaskList` rows still display `"Blocked on #X"` (`fb6d2bad7`).
- **`PendingQuestion` callout & `/inbox` pre-fetch (`b0a21c2bb`, `2fc026c20`):**
  - When a non-interactive task is parked in `awaiting_reply` with a question (`ask_question`), `DetailOverlay` renders a `PendingQuestion` callout at the top of the detail pane ahead of the original description and timeline, displaying the rendered markdown question, attachments, and an inline reply composer whose typed draft survives background poll re-renders.
  - On `/inbox`, `Responder` pre-fetches `GET /api/tasks/{id}` on mount (when `document.hidden` is false) and renders the question markdown (`.inbox-question`) directly on `awaiting_reply` rows before `Reply` is clicked, while linking `#N` task references inside the question with modified-click support (`2fc026c20`). For `request_secret` tasks (`pendingSecret`), `/inbox` hides the inline text preview and directs the operator to the write-only secret box in `DetailOverlay`.
- **Quota `GrantWait` (`QuotaWaitCapability`), Queued Icon Tooltip vs. Detail Status, and CI Admission Hold (`f0ace8dd3`, `e9fad2b64`, `daf546150`, `d21320e92`):**
  - When a queued or `RunNow` task is held back by host sandbox resource budget, worker/merger capacity, or a provider usage-limit pause, `dispatch` records a `QuotaWaitCapability` (`"quota"`) `GrantWait` while preserving any non-quota `GrantWait`s and clearing stale quota waits on ineligible candidates (`f0ace8dd3`, `daf546150`).
  - `TaskList`, `TaskBoard`, and `ConsoleSessionPage` omit pre-run `waiting` text from row/card badges and typing indicators so waiting queued tasks render cleanly as `"queued"`, surfacing `"queued — waiting: <reason>"` on the state icon tooltip (`stateTitle(t)`) while keeping `"waiting: <reason>"` visible in `DetailOverlay` and `grain tasks` CLI (`e9fad2b64`).
  - While an eligible agent task is held back by the shared sandbox CPU/memory budget (`AgentShape` recorded on `model.Ledger`), `ci.SharedGate` holds back new CI job admissions with `"waiting behind a queued agent sandbox"` (`WaitForPriority`) so freed slivers accumulate until the agent fits, while preserving the `Stuck` deadlock escape hatch when a running agent holding budget is blocked inside `wait_for_checks`, and waking the reconcile loop immediately when a sandbox releases (`d21320e92`).
