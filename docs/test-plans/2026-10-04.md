## 4. Merge queue and CI verdict correctness

Commits:
- `a224f66aa`, `83de8e5e3` and `59614175e`: a red verdict is classified job by job against the
  base's latest run.
  - When every failure is inherited, the PR goes to the new `waiting_base` state ("waiting for
    `<base>` to go green: `<job>` is red there too"). It spends no repair and is not blocked.
  - Once the base is green again, the queue merges the base into the branch and retests.
  - A fully inherited batch is released, not bisected.
- `64b5383ab`: GitHub merge refusals are classified (`github.ClassifyMergeRefusal`,
  `MergeRequirements`).
  - A refusal for missing approval goes to `waiting_github_approval`, with a note naming the code
    owners or reviewers and how many approvals are still needed. It is not retried every cycle.
- `bb42b0d5a`: a force merge records `ForceMergeHeadSHA`. The UI sends the head it shows, and
  `grain force-merge -head <sha>` takes one. If the branch has moved, the request is refused.
- `dbfcbc009`: before opening or merging a PR, the queue checks whether the work has already landed
  on the base, by comparing content. It neither opens a second PR nor merges an empty one.
- `783807a3e`: a security review is closed once the held change merges or closes, and the change is
  told its review closed unfinished.
- `635b62474`: `GET /api/tasks/{id}` carries `securityHold` and `securityReviewTask`, and the task
  pane shows the hold and links the review.
- `78c6f3bb2` (deployed; see `fbd20123c`): an uncached recheck replaces the cached verdict it
  re-ran.
- `fe3dcedbe` and `d824c3aac`: quarantine no longer excuses a step stopped by its own timeout, and a
  quarantined pass keeps its failures in `FailureSummary`.

## Standing environment notes for the filed tasks

- **Branch.**
  - §1-§9 target `candidate`, which holds every commit they cover.
  - §10 targets `main`.
  - Each report names the tested commit and confirms it with `git branch -r --contains <sha>`.
  - `bwsalmon/grain` declares `port-branches: [main, candidate]`, so a fix merged on one branch
    files a port task onto the other. Do not cherry-pick by hand.
- **Overlap.** Yesterday's §1-§9 tasks (`docs/test-plans/2026-10-03.md`) may still be in flight.
  Before filing a finding, check `docs/test-runs/` and the open tasks for the same finding. If it
  is there, link to it instead of fixing it twice.
- **CI authority.** Grain CI (`.grain/workflows`) is the only merge gate. GitHub Actions checks are
  informational.
- **Browser tests.**
  - Set `PLAYWRIGHT_BROWSERS_PATH=/var/cache/playwright`.
  - Build the UI (`cd ui && npm ci && npm run build`) so the run uses the production bundle in
    `pkg/ui/static`.
  - Do not mock grain's own APIs or React. Stub only GitHub (githubsim), Google OAuth, live model
    sessions and real cloud APIs, and list each stub in the report.
  - Slowing a real response with `page.route` is not mocking it.
- **Formatting.** `npm run format` in `ui/` for UI changes, and `gofmt` for Go.
- **Security suite.** `make security` must stay green, and no `.grain/baselines/` count may rise.
- **Trust-boundary hold (v2/v3).** A fix touching a trust-boundary path is held for security review
  before it auto-merges, and that is expected. Since `84d05077c`, `.grain/triggers/**` is one of
  those paths. Other examples: `pkg/gitproxy`, `pkg/relay`, `pkg/mcp`, `pkg/ci`, `pkg/orchestrator`,
  `pkg/ui` auth, `tests/security`.
- **Reports.** Each task writes `docs/test-runs/2026-10-04-<feature>.md`, or the date it runs. The
  report covers the environment, tested commit, commands, outcomes, findings (each with a
  deterministic reproduction), stubs, fixes and the CI verdict.
- **Known flakes.** See the repository notes: `RepoPage.test.jsx` "shows the inherited global
  value…" and `ui/e2e/team_declarations_ci_walkthrough.spec.js:229`. Record a recurrence. Do not
  chase it in a feature task.
