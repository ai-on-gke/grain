# Nightly new features test plan: 2026-09-30

This plan covers all features, structural refinements, and behavioral changes merged into `candidate` and `main` over the past day (following `docs/test-plans/2026-09-29.md` and subsequent validation runs) through commit `329a5d34d` (PR #2340). It encompasses over 55 merged pull requests and 80+ commits.

Key focus areas in this batch include:
1. **GitHub Issue Correlation, Auto-Closing PR Directives & `read-issues` MCP Capability**: Association of tasks with GitHub issue numbers via task model, schema, CLI (`-issue`), and APIs. Orchestrator automated prompt context injection and PR description `Fixes #<issue>` closing directive generation upon task completion. Addition of `read-issues` capability provider and `list_issues` / `read_issue` MCP tools for sandbox agents, properly forwarded through orchestrator tool grants.
2. **Cross-Team Task Reassignment & Dynamic Team Slug Generation**: Administrative and programmatic moving of tasks across teams via CLI (`grain team move`, `grain update -team`) and REST API (`POST /api/tasks/{id}/move`) with destination target repository allowlist validation. Automatic generation of URL-safe team slug identifiers from team names during team creation and user personal team provisioning.
3. **Team-Scoped Repositories, Auto-Saving Repo Pane & Sidebar Release Version Stamp**: Strict active team scoping across repository listings in `RepoList.jsx`, `RepoPage.jsx`, `Sidebar.jsx`, `NewTaskOverlay.jsx`, and `state.js`. Auto-saving repository settings on field change/blur in `RepoPage.jsx` without manual save buttons. Surfacing release versions (e.g. `v1.2.0`, `v1.3.0-rc`) via `/api/config` and rendering in the sidebar footer build stamp.
4. **Multi-Tenant Capability Security, Subprocess Environment Sanitization & Symlink Containment**: Strict `AuthorizedTeams` allowlist enforcement across privileged capabilities (`selfrepair`, `selfupgrade`, `githubtoken`, `console`, `quarantine`, `gcp-key`, `package-publish`), failing closed with `TeamUnauthorizedRefusal`. Workspace symlink containment via `filepath.EvalSymlinks` preventing directory traversal in MCP file operations. Subprocess environment variable allowlisting in sandboxes to prevent host credential leaks. Multi-tenant scoping for self-debug task inspection tools.
5. **PostgreSQL 64-Bit Duration Metrics, UTF-8 Sanitization & Database Migration**: Migration of `sandbox_usage.duration_ms` from 32-bit `INTEGER` to 64-bit `BIGINT` in PostgreSQL and SQLite to prevent integer overflow during high cumulative runtime. PostgreSQL query driver adapter sanitization replacing invalid non-UTF-8 byte sequences and stripping null characters to avoid SQLSTATE 22021 driver aborts during log migration. Cleanup of legacy `grain_config` columns and default team target repository backfilling.

Each section outlines what existing tests prove, the critical unproven gaps across real sandbox/browser environments, and concrete walkthrough steps.

## 1. GitHub Issue Correlation, Auto-Closing PR Directives & `read-issues` MCP Capability

`c94ae1b09` (PR #2326, task-1117), `338a1d67e` (PR #2306, task-1116), `5146c3e71` (PR #2334, task-1160), and `b92a0ef30` (PR #2330, task-1118) integrate GitHub issue tracking deeply into the Grain task lifecycle.

- `pkg/capability/readissues/readissues.go`: Implements the `read-issues` capability provider allowing agents to inspect GitHub issues.

- `pkg/orchestrator/run.go`, `cmd/grain/mcpserver.go`: Forwards `read-issues` capability to mcpserver via `toolGrants` in `agent.RunConfig.Grants`, unlocking `list_issues` and `read_issue` tools in agent sandboxes.
- `pkg/orchestrator/description.go`, `pkg/orchestrator/run.go`, `pkg/github/githubsim/githubsim.go`: Injects correlated GitHub issue context into agent system prompts, and automatically formats pull request descriptions with `Fixes #<issue>` directives so GitHub automatically closes the issue upon pull request merge.

- **Grant Refusal on Missing Capability**: Ensuring that sandboxes without the explicit `read-issues` grant fail cleanly when attempting to call issue tools.
- **UI Issue Correlation Rendering**: Verifying that correlated issue numbers render as clickable links in the web UI task board and task detail pane.

## 4. Multi-Tenant Capability Security, Subprocess Isolation & Symlink Containment

`dc4160803` (PR #2308, task-1056), `7e5938ce8` (PR #2309, task-1052), `4318a2e36` (PR #2294, task-1055), `049e64677` (PR #2292, task-1053), `d3b854314` (PR #2291, task-1051), `038de1393` (PR #2289, task-1050), `78792d91b` (PR #2290, task-1049), `28695e05c` (PR #2288, task-1048), `8d5857007` (PR #2305, task-1115), and `f247ecde3` (PR #2283, task-1084) strengthen sandbox isolation and multi-tenant security boundaries.

Concretely:
- `pkg/capability/`: Enforces `AuthorizedTeams` allowlist checks across privileged capability providers (`selfrepair`, `selfupgrade`, `githubtoken`, `console`, `quarantine`, `gcp-key`, `package-publish`), returning `TeamUnauthorizedRefusal` on unauthorized team requests.
- `pkg/mcp/sandbox_tools.go`: Introduces `filepath.EvalSymlinks` validation in `resolvePath` to strictly prevent symlink path traversal escapes outside the sandbox workspace root during `read_file`, `write_file`, and `edit_file`.
- `pkg/mcp/sandbox_tools.go`: Sanitizes subprocess environment variables (`sandboxPassthrough` / `sandboxEnv`) to strip daemon tokens, credentials, and sensitive host environment variables.
- `pkg/mcp/task_tools.go`: Scopes self-debug task inspection tools (`list_grain_tasks`, `read_grain_task`, `read_grain_task_prompt`, `read_grain_task_transcript`) strictly to the caller task's team.
- `pkg/ui/console.go`: Adds RBAC checks on interactive console websocket / HTTP streams to prevent cross-team console sniffing.

### Existing coverage
- `pkg/capability/*/*_test.go` unit tests for `AuthorizedTeams` refusal.
- `pkg/mcp/sandbox_tools_test.go` tests symlink resolution and path rejection.
- `pkg/mcp/sandbox_env_test.go` tests environment variable allowlisting.
- `pkg/mcp/task_tools_test.go` tests team scoping on self-debug queries.
- `pkg/ui/console_test.go` tests 403 Forbidden on unauthorized console stream connections.

### Gaps and unproven behaviours
- **Symlink Escape Containment in Live Sandbox**: Unproven in a live sandbox whether an agent attempting to create a symlink (`link -> /home/debian/.gemini-api-key`) and read it via MCP `read_file` is blocked by `EvalSymlinks`.
- **Subprocess Environment Sanitization**: Running `env` via MCP `run_command` in a sandbox to verify no host daemon credentials (e.g. `GRAIN_TOKEN`, `GRAIN_DB_URL`, `GCP_SECRET`) are present.
- **Cross-Team Capability Denial**: Verifying that a task from Team B requesting `package-publish` or `selfupgrade` is refused at dispatch time with `TeamUnauthorizedRefusal` and logged in task audit events.
- **Cross-Team Self-Debug Task Inspection**: An agent from Team B calling `list_grain_tasks` via MCP only sees tasks from Team B, and calling `read_grain_task_prompt(task_id="team-a-task")` fails with unauthorized access error.

4. Run `run_command(command="env")` in the sandbox; verify only allowlisted environment variables (`PATH`, `USER`, `HOME`, `TMPDIR`, compiler caches) are present.
5. In Team Beta sandbox, invoke `list_grain_tasks` and `read_grain_task` targeting a task from Team Alpha; verify cross-team task data is blocked.
6. Attempt to open a console stream for Team Alpha's task using Team Beta's auth credentials; verify 403 Forbidden.

## 5. PostgreSQL 64-Bit Duration Metrics, UTF-8 Sanitization & Database Migration

`dcb2d5824` (PR #2340, task-1182), `206b551b1` (PR #2307, task-1114), and `573564e1e` (PR #2293, task-1105) harden database schema and migration resilience for large-scale production deployments.

Concretely:
- `pkg/model/schema.go`, `pkg/model/postgres/postgres.go`: Changed `sandbox_usage.duration_ms` from `INTEGER` (32-bit int4) to `BIGINT` (64-bit int8 in PostgreSQL, 64-bit integer affinity in SQLite), and added `ALTER TABLE IF EXISTS sandbox_usage ALTER COLUMN duration_ms TYPE BIGINT` migration in `postgres.Open`.
- `pkg/model/postgres/adapter.go`: Wrapped query arguments and statements in `strings.ToValidUTF8` and removed null bytes in the PostgreSQL adapter to prevent SQLSTATE 22021 driver aborts during import/upgrade of non-UTF-8 terminal outputs or CI logs.
- `pkg/model/store.go`: Dropped obsolete legacy columns (`target_repos`, `agent_git_name`, `agent_git_email`, `github_posting_credential`, `ignore_github_ci`) from `grain_config` table and backfilled target repos to default team.

### Existing coverage
- `pkg/model/postgres/upgrade_test.go` tests upgrade with duration_ms > 2.14 billion and non-UTF-8 byte sequences.
- `pkg/model/postgres/adapter_test.go` tests sanitization of invalid UTF-8 strings.
- `pkg/model/sqlite/store_test.go` tests dropping legacy columns and target repo backfilling.

### Gaps and unproven behaviours
- **Live PostgreSQL Database Migration**: Unproven whether exporting an active SQLite database with large sandbox runtimes (>2.5 billion ms) and raw non-UTF-8 ANSI escape log sequences, running `grain migrate --from sqlite.db --to postgres://...`, and verifying data integrity and subsequent task execution on PostgreSQL store succeeds without error.
- **Accumulation of Real Sandbox Runtime Metrics in PostgreSQL**: Executing tasks under PostgreSQL storage backend, recording task runs with high duration values, and verifying aggregate metrics queries in `/api/metrics` return accurate figures without integer overflow.

### Walkthrough & test procedure
1. Provision a local or containerized PostgreSQL instance for testing.
2. Seed a SQLite database with `sandbox_usage` entries containing `duration_ms = 3500000000` (3.5B ms) and task run logs containing non-UTF-8 byte sequences (`0xFF 0xFE` terminal noise).
3. Run the database migration utility to import SQLite schema and records into PostgreSQL.
4. Start `grain daemon` connected to the PostgreSQL database.
5. Query the metrics API (`GET /api/metrics`) and verify total sandbox usage and durations are computed accurately.
6. Dispatch a new task on the PostgreSQL backend, record its execution runtime in `sandbox_usage`, and verify records are cleanly inserted without schema or encoding errors.

Filed: **Walkthrough: PostgreSQL 64-Bit Duration Metrics, UTF-8 Sanitization & Database Migration (docs/test-plans/2026-09-30.md §5)**
