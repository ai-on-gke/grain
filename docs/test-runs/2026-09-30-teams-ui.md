## Executive Summary

A comprehensive end-to-end operator walkthrough and automated validation of Grain's multi-team management, team creation and validation rules, concurrency limit chips, global team selector scoping and persistence, task intake and detail overlay lifecycle, bulk edit operations, schedules and interactive console sessions, multi-team saved boards, and deletion safeguards was conducted against a real `grain demo` server.

All 15 Playwright E2E tests across the multi-team test suite, 98 unit tests across 10 team component test suites (and 2,668 frontend tests across 156 files overall), as well as backend Go packages (`pkg/access`, `pkg/repodecl`, `pkg/ui`, and all underlying system modules) executed cleanly with 100% pass rates and zero regressions.

## Scope & Coverage

### 1. Settings > Teams Management & Concurrency Limits
- **Default Team Card Inspection**:
  - Navigated to `Admin` > `All Teams`.
  - Inspected the built-in `Default Team` card (`default` slug), verifying default admin role assignment, concurrency limit chips (`Max Workers`, `Max Mergers`, `Max CI Jobs`), and lack of a destructive `Delete Team` action button.
  - Verified the `Copy Command` executor bootstrap button and the `Copy Clone Command` config repository clone button, checking visual confirmation state transitions (`Copied`).
- **Validation Rules & Character Enforcement**:
  - Validated that submitting the Create Team form without a required team name displays a descriptive validation alert (`Team name is required`).
  - Tested invalid slug input containing non-alphanumeric/hyphen characters (e.g., `invalid@slug!`), confirming server validation rejection with an appropriate error banner (`contains invalid characters`).
  - Validated duplicate slug rejection when attempting to register a team using an existing slug (`qa-infra`).
- **Custom Slug Creation & Override Badges**:
  - Created custom team `QA & Infrastructure` with explicit slug `qa-infra`, custom concurrency limits (`Max Workers: 4`, `Max Mergers: 2`, `Max CI Jobs: 8`), git identity (`Grain QA Agent`, `qa-agent@acme.example`), and role assignments (`debian:admin, alice:admin, tester:member`).
  - Verified chip and badge rendering on the newly created team card.
- **Auto-Generated Slug Creation**:
  - Created team `Security Operations Walkthrough` with name and member assignments without specifying a slug; confirmed auto-generated slug creation (`team-1` or derived slug) and proper card rendering.
- **Team Editing**:
  - Edited `QA & Infrastructure` limits from `Max Workers: 4` to `Max Workers: 6` and updated the team description. Verified immediate live card updates in the UI.

### 2. Global Team Selector, State Persistence & Scoping
- **Global Selector Options**:
  - Exercised `#team-selector` in the top header and navigation rail across views (`All teams`, `QA & Infrastructure (qa-infra)`, `Security Operations Walkthrough`).
- **State Persistence**:
  - Verified that switching team context updates browser storage (`localStorage.getItem("grain.selectedTeam") === "qa-infra"`) and persists across route transitions and page refreshes.
  - Verified switching back to `All teams` properly resets the storage key to `null`.
- **Team-Scoped Settings Panes**:
  - Verified team-specific settings categories (`Team`, `Members`, `Capacity`, `Git identity`) when accessing Settings under an active team selection.

### 3. Task Intake, Detail Overlays & Bulk Edit
- **Task Intake with Target Team**:
  - Created a new task with target team preselected to `QA & Infrastructure (qa-infra)`.
  - Verified immediate appearance in the task backlog with proper team metadata.
- **Task Detail Overlay & In-Place Editing**:
  - Opened Task Detail Overlay and confirmed the declared team badge `QA & Infrastructure (qa-infra)`.
  - Exercised in-place task editing to reassign the target team to `admin (default)` and verified live badge updates before reverting back to `qa-infra`.
- **Backlog Team Filtering**:
  - Created a second task assigned to `Default Team`.
  - Verified team scoping: filtering by `QA & Infrastructure` displayed only QA tasks; filtering by `Security Operations` displayed an empty state; filtering by `All teams` displayed both tasks.
- **Bulk Edit Operations**:
  - Multi-selected multiple tasks across teams via row checkboxes.
  - Opened `Bulk edit` dialog, selected `Team` field, set target to `QA & Infrastructure`, and executed batch update across selected tasks.

### 4. Schedules & Console Sessions Team Scoping
- **Schedules**:
  - Created a recurring schedule assigned to `QA & Infrastructure`.
  - Verified schedule list filtering under active global team context vs. All teams.
- **Console Sessions**:
  - Created an interactive console session assigned to `QA & Infrastructure`.
  - Verified sidebar session entry visibility and reactive filtering under the active team selector.
- **CI Runs Scoping**:
  - Navigated to `/ci` under active `qa-infra` team selection; verified `Start a run` dialog preselects `qa-infra` target team.

### 5. Multi-Team Saved Boards & Config Repo Routing
- **Board Scoping & Filtering**:
  - Seeded boards scoped to `qa-infra` and `default`.
  - Navigated to `/boards`: verified all boards visible in `All teams` view, and filtered appropriately when switching global team selector to `qa-infra`.
- **Config Repo Routing**:
  - Verified clicking `New board` with active team `qa-infra` routes the task repository to `grain/config-qa-infra`.
  - Verified clicking `Add panel` within a board scoped to `qa-infra` routes to `grain/config-qa-infra`.

### 6. Team Deletion Safeguards & Cleanup
- **Deletion Rejection with Active Tasks**:
  - Attempted to delete `qa-infra` while tasks remained assigned; verified HTTP 400 rejection and user-facing error notification (`cannot delete a team that still has tasks`).
- **Clean Deletion**:
  - Bulk-reassigned remaining tasks back to `Default Team`.
  - Deleted `qa-infra` and `Security Operations Walkthrough` teams cleanly; verified only `Default Team` remained in Settings.
