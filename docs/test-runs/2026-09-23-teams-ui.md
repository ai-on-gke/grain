## Unit Test Coverage

### 1. Teams Management Panel (`ui/src/components/TeamsPanel.test.jsx`)
Added 8 comprehensive unit tests for `TeamsPanel.jsx`:
- **Team List Rendering & Limit Chips**: Validates rendering team cards, name, description, and chips for Max Workers, Max Mergers, and Max CI Jobs. Confirms that `0` values render as `"Unlimited"` and non-zero values display their exact numeric limit. Confirms `"Default Team"` badge on the default team card.
- **Fetch Error Handling**: Validates that failed GET `/api/teams` triggers the `showError` handler.
- **Custom Slug Creation**: Tests opening the `+ New team` modal, entering a custom ID slug (e.g. `qa-infra`), team name, description, and limits, and submitting POST `/api/teams` with the custom ID.
- **Auto-generated Slug Creation**: Tests creating a team without providing a custom slug, confirming `id` is omitted in POST `/api/teams` payload for server-side generation.
- **Editing Existing Teams**: Tests opening the edit dialog, verifying pre-populated values (and omission of the immutable ID field), modifying limits and description, and submitting PUT `/api/teams/:id`.
- **Dialog Cancellation**: Tests closing both Create and Edit modals without sending HTTP requests.
- **Delete Confirmation & Protection**: Tests delete flow: default team does not offer a delete button; non-default team triggers confirmation prompt; declining aborts DELETE, while confirming submits DELETE `/api/teams/:id`.
- **Delete Refusal Handling**: Validates that backend error responses on DELETE (such as active tasks remaining attached) trigger `showError` in the UI.

### 2. Task Intake & Overlays (`ui/src/components/NewTaskOverlay.advanced.test.jsx`)
Added 3 unit tests for `NewTaskOverlay.jsx` team selection:
- Target team dropdown populated from `config.teams` with team names and IDs.
- Selecting a non-default team attaches `team: "<teamId>"` to the POST `/api/tasks` payload.
- Selecting the default team omits `team` from the POST payload.
- Task draft persistence preserves the selected team across overlay reopen.

### 3. Schedule Intake & Overlays (`ui/src/components/SchedulesList.test.jsx`)

- Target team dropdown populated from `config.teams` and selected team serialized into POST `/api/schedules`.
- Edit overlay preselects the schedule's existing team and saves updated team target via PATCH `/api/schedules/:id`.

### 4. Task Attributes & Filtering (`ui/src/taskFilters.test.js`)
Added unit test for `team` enum attribute:
- Matches tasks by team attribute.
- Correctly treats tasks without an explicit team as `"default"`.

### 5. Backend Team API & Slug Validation (`pkg/ui/teams_test.go`)
Added backend unit tests for:
- Creating teams with custom slugs (e.g. `qa-infra`).
- Rejection of invalid slugs with HTTP 400 Bad Request.
- Rejection of duplicate team slugs with HTTP 400 Bad Request.

### Bugs Found and Fixed During Walkthrough:
1. **Custom Slug Support in UI Team Creation Endpoint**: `pkg/ui/teams.go` `CreateTeamRequest` lacked `ID string json:"id,omitempty"`. Added `ID` field and validated custom slug format with `model.ValidateTeamID`.
2. **Duplicate Slug Handling in Backend**: `CreateTeam` previously did not check if the custom ID was already registered in the store before putting it. Added duplicate team ID check returning validation error (HTTP 400).
3. **DeleteTeam Error Mapping**: When deleting a team with active tasks, `c.Store.DeleteTeam` returned `model.ErrTeamNotEmpty`, which was unmapped by `writeClientError` and resulted in HTTP 500. Wrapped `model.ErrTeamNotEmpty` in `validationErrorf` so the server responds with HTTP 400 Bad Request.
