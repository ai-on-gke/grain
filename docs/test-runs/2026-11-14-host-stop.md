## Item 1 — stop, restart, kill -9, drain, SIGUSR1 with two detached runs

The installed unit has `KillMode=mixed` (`systemctl --user show -p KillMode`), and its cgroup holds `grain-agentd`, both `agy` stubs and their `sleep`s.

| Mode | SQLite | PostgreSQL | Survivors (`pgrep`, `systemd-cgls`) |
| --- | --- | --- | --- |
| `systemctl --user stop` (start again 20 s later) | Tasks 4, 5: both run 1 `interrupted`, "the host agent stopped or restarted while the run was going; the run goes back to the queue: stopped because the host agent stopped or restarted"; run 2 dispatched on restart | Tasks 2, 3: the same | none; the cgroup is empty and the unit `inactive (dead)` |
| `systemctl --user restart` | Tasks 6, 7: the same reason, requeued, run 2 dispatched within 1 s | Tasks 4, 5: the same | only the new run 2 processes; the old pids are gone |
| `kill -9` main PID | Tasks 8, 9: `interrupted`, "…stopped or restarted…: the host agent stopped while it ran" (`loadSpools`); requeued | Tasks 6, 7: the same | journal: `Main process exited, code=killed, status=9/KILL`, then `Killing process … (agy) with signal SIGKILL` for all four. Restarted after `RestartSec=10`, which kept the final spools for the daemon |
| `grain-agentd -drain` (cutover) | Tasks 10, 11: `interrupted`, "the host agent is updating (draining for its own upgrade); …: stopped because the host agent drained for an upgrade" at the 15 s cap | Tasks 8, 9: the same | none; `drained; exiting so the new build takes over`, restarted |
| `kill -USR1` main PID | Tasks 12, 13: the same drain reason | Tasks 12, 13: the same | none |

- **Stop vs drain are told apart.** Every stop, restart and crash says *stopped or restarted*. Every `-drain` and `SIGUSR1` says *draining for its own upgrade*. PR #1469 holds on a real unit.
- **Never orphaned.** Restart: the replacement `grain-agentd` cannot adopt a live CLI it did not spawn (`canAdoptLiveSpool` needs it as the parent). `KillMode=mixed` makes sure none survives, and the replacement serves the kept final spools, so the daemon reads both exits and requeues the runs.
- **Requeued runs dispatch again.** In every mode, run 2 of each task started on `walk` once it was back. That run 2 ends `failed: the agent made no tool calls at all` is the stub's doing.
- **Run 2's prompt quotes the reason:** `attempt 1 ended "interrupted": antigravity: running agy: the host agent stopped or restarted while the run was going; …`.
- **The SIGTERM trap fired only on the old `control-group` unit (below).** Under `KillMode=mixed`, `grain-agentd` killed the run's process group itself, with SIGKILL.

### F1 — a stop the host stays down for was recorded as a lost host (fixed)

On `systemctl --user stop`, hostd closed its session to the daemon in the same instant it killed the CLIs. The daemon therefore never read their `Stopped` exits. It logged `lost host walk while streaming run 4-1's CLI … it keeps running, and is re-attached if the host agent is back within 15m0s` and held both runs as **running**. This was true even though `pgrep` and `systemd-cgls` showed nothing left. The daemon learned the real reason only if the host came back within the reattach timeout.

**Reproduction on systemd:**

1. Restart the daemon with `DAEMON_EXTRA="-hostd-reattach-timeout 30s"`.
2. Run `AWAY=45 ./item-host.sh stop`.

Tasks 14 and 15 were then recorded at +30 s as `interrupted`: **"the host agent disconnected mid-run and did not reconnect in time; … host walk dropped run 14-1's CLI … and did not reconnect within 30s"**. That is the lost-host reason, not the stopped one, and with the default timeout it takes 15 minutes.

**Reproduction in Go:** `TestAStoppingHostdDeliversAnAttachedDetachedRunsExitOverTheSession` (`pkg/hostd/remote_linux_test.go`). Before the fix it failed with `hostd: the connection closed before the process's exit status arrived`.

**Fix** (`pkg/hostd/server_linux.go`):

- `Serve` keeps the daemon's connections (the remote session and the socket's) on a context of their own.
- When its own context ends, `stopped()` runs before those connections close. It refuses new starts (`closing`, as a drain does), ends what still runs as `killStopping`, and waits up to `DrainExitGrace` for the daemon to read the exits of the processes the stop ended.
- An exit written before the stop is not waited for again. `TestAServeCancelWhileExitIsHeldKeepsTheSpool` still exits promptly.
- A drain or handover has already done all of this, so for them `stopped()` returns at once.

**Checked on systemd after the fix**, on SQLite (tasks 16, 17) and PostgreSQL (tasks 2, 3): `stop returned` at 14:25:10, and in that same second the daemon recorded both runs `interrupted` with the *stopped or restarted* reason and queued them. That was **while the unit was still `inactive (dead)`**. When the unit started 20 s later, they dispatched again.

## Item 2 — upgrading a unit that lacks `KillMode=mixed` in place

The old unit was simulated by deleting the `KillMode=mixed` line and running `daemon-reload`. `systemctl --user show -p KillMode` then said `control-group`.

- **Re-running `grain-agentd install` rewrites it.** The unit is written again with `KillMode=mixed`, followed by `daemon-reload`, `enable` and `restart`. The new `MainPID` reported `KillMode=mixed`, and token, allowlist and release key were all kept. **Holds.** That restart is a *stop* for any run in flight, so those runs are requeued with the stopped reason.
- **`grain-agentd update` did not (F2, fixed).** A release signed with a throwaway key was pinned in `~/.config/grain/agentd-release.pub` and fed with `update -from <dir>`:
  - An update run by a build of `origin/main` (`v9.9.0`, without the fix) to `v9.9.1` staged and cut over. It left the unit with the guard `ExecStartPre` but no `KillMode`, and the restarted `v9.9.1` reported **`KillMode=control-group`**. `ensureUnitGuard` only ever added the rollback guard, so a host installed before PR #1469 and kept current by `update` never got `KillMode=mixed` until someone reinstalled it.
  - On that control-group unit, a stop with two runs SIGTERMed the whole cgroup: the stubs logged `got SIGTERM` and exited `code 143`. This time `grain-agentd` marked them `draining true` first, but that is the race PR #1469 removed.
  - **Fix** (`pkg/agentd/update.go`): `ensureUnit` adds `KillMode=mixed` after `ExecStart` when the unit sets no `KillMode` of its own, then runs `daemon-reload`. A `KillMode` an operator set is left alone. Regression: `TestWithKillModeAddsKillModeMixedOnce`.
  - After the fix, an update run by the fixed `v9.9.1` to `v9.9.2` printed `==> added KillMode=mixed to …/grain-agentd.service`. `NeedDaemonReload=no`, and `KillMode=mixed` was already in effect before the cutover restarted the unit. The new `MainPID` (`v9.9.2`) reports `KillMode=mixed`.
  - `update` runs the binary already installed, so a host picks this up at the first update run by a build that has the fix. Reinstalling fixes it at once.
