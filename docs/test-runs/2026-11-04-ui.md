## Item 2: gzip edges

Script: [`gzip-edges.sh`](2026-11-04-ui/gzip-edges.sh). Output: [`gzip-edges.out`](2026-11-04-ui/gzip-edges.out).

| Edge | Observed | Verdict |
|---|---|---|
| `If-None-Match` with gzip | Gzipped response: `ETag: W/"e247…"`, `Vary: Accept-Encoding`. `If-None-Match` sends that weak tag back: with `Accept-Encoding: gzip` the answer is 304 with 0 bytes, and without it the answer is also 304 with 0 bytes. | ✅ |
| Event stream (`GET /api/events?stream=1`, `Accept: text/event-stream`, `Accept-Encoding: gzip`) | `200`, `Content-Type: text/event-stream`, no `Content-Encoding` | ✅ not gzipped |
| Websocket | `pkg/ui` serves no websocket route, and an `Upgrade: websocket` request gets 404 uncompressed. `withCompression` does not wrap a request that carries `Upgrade` (`pkg/ui/compress.go`), and `TestCompressionLeavesStreamsAndCompressedBytesAlone` covers that. | ✅ (no live route to test) |
| Range on a static asset (`Range: bytes=0-99`, gzip accepted) | `206`, `Content-Range: bytes 0-99/2245191`, `Content-Length: 100`, no `Content-Encoding` | ✅ |
| Range on an API response | `200` with the whole 106,360 B body uncompressed. The API ignores Range, and the middleware leaves ranged requests alone. | ✅ not gzipped. Note: a ranged API read gets the whole body uncompressed, which is harmless because browsers do not send Range on `fetch`. |
| CI artifact download (gzip accepted, and gzip plus Range) | New test `TestCIArtifactDownloadIsNotGzippedForAGzipCaller`: no `Content-Encoding`, and the 4,800 B artifact arrives byte for byte. `application/gzip` is not a compressible type. | ✅ (test stub for the CI runner) |

## Item 3: SearchSelect by keyboard only

Script: [`searchselect-walk.mjs`](2026-11-04-ui/searchselect-walk.mjs). For each form at 1440 and 390 px, and for up to three SearchSelects in it, the script does the following with the keyboard only (`focus()`, then `ArrowDown`, typing, `Enter`, `Escape`, `Backspace`):

1. Open the list and run axe on the list and its box.
2. Search for a word from another option, then pick with Enter, watching for any non-GET request, a closed form or a changed URL.
3. Reopen the list and press Escape.
4. Clear the box: Backspace on a chip for a multiple box, or Ctrl+A then Backspace for a clearable single box.
5. **Type a query that matches nothing ("zzqxv") and press Enter.**

## Findings and fixes

| # | Finding | Deterministic reproduction | Fix |
|---|---|---|---|
| F1 | **Enter on an open SearchSelect list that matches nothing submits the form.** MUI's Enter only picks a highlighted option, and "No matches" has none, so the keypress fell through to the form. On the Schedule drawer this filed a schedule. | `/schedules` → `+ New schedule` → focus Template → ArrowDown → type `zzqxv` ("No matches") → Enter. Before: `POST /api/schedules`, drawer closes ([before run 2](2026-11-04-ui/searchselect-walk-before-run2.jsonl), Schedule line). After: no request, drawer open. | `SearchSelect.jsx` tracks whether its list is open (`onOpen`/`onClose`, and the caller's `open` if it passes one) and calls `preventDefault()` on Enter while it is, unless an IME is composing. A highlighted option is still picked by MUI as before. Unit test: "keeps Enter from the form while the open list matches nothing". e2e: `searchselect-keyboard-walkthrough.spec.js` at 1440 and 390. |
| F2 | **Every open multiple SearchSelect list fails axe**: each `role="option"` held a real MUI `Checkbox` `<input>` with no label (axe `label`, critical, ×7) inside an interactive role (`nested-interactive`, serious, ×7). Seen on NarrowingBar values. The same component draws Legacy capabilities, suite Templates, New Task Area and others. | `/` → Filter → Add filter → State → focus Values → ArrowDown → axe on the listbox. | The tick is now a drawn, `aria-hidden` `CheckBox`/`CheckBoxOutlineBlank` icon (`.search-select-check`, same 4 px padding and 20 px icon as the small Checkbox, primary when picked). `aria-selected` already says the row is picked. `multi-search-select-layout.spec.js` now measures `.search-select-check`. The new spec asserts axe is clean on the open list, there is no `<input>` in it, and that the tick sits inside the row, in front of its label, on the same centre line (±3 px), at 1440 and 390. |
| F3 | **A finished report's reason chip said "question"** beside its "Answered in a comment" badge, which is the word #674 removed from the badge. The orchestrator gives every `awaiting_reply` task `awaiting_reply/question` (`pkg/orchestrator/livenessreasons.go` `taskReasonOf`). Interactive tasks waiting for a message read "question" too. | Demo task #7 in `/` and `/inbox`: `.task-reason` text is "question". | `state.js` `taskReasonLabel(t)`: for that one sub-case the chip names `askedCase`'s kind ("answered", "your message", "access request", "stopped"), and a real question still reads "question". `TaskList.jsx` uses it. The raw reason code is unchanged in the chip's tooltip and the API. Unit tests in `state.test.js`, plus the e2e spec. A finer server-side reason (`awaiting_reply/answer` and so on) would let API readers tell the cases apart too. That is left as a possible follow-up, because the reason codes are part of the liveness registry and its design doc. |

Not product bugs, but recorded:

- On consolerestserver, the first `paging-walk.mjs` stopped after one "Load older" click. The cause was the script: it waited for `innerText` to stop containing "Loading closed tasks…", but `innerText` is lower-cased by the theme's `text-transform`, so the wait passed at once. On the slower server the button was still mid-load and so not yet named "Load older". [`load-older-probe.mjs`](2026-11-04-ui/load-older-probe.mjs) showed paging working (200 → 400 → 600 → 800 rows). The script now waits on the button's accessible name, and the results above are from the corrected script.
- `useClosedTasks.loadMore` returns without a word if a background refresh is in flight (`inFlight`). A click that lands in that window does nothing, and the button stays enabled. This is rare (a refresh takes about 150 ms) and it does not lose data, because the next click works. Not changed.
