# Teams management, task intake and multi-team UI walkthrough

**Date**: 2026-10-07
**Commit tested**: `396b556c7` (candidate tip at the start of the run). The fixes were re-verified on this branch's own build (`e9de947c1`), on a fresh demo store.
**Environment**: Debian sandbox, Linux x86_64, Go 1.26.6, Node 20.19.0, Playwright 1.62.1 with Chromium headless shell 151 (v1234).
**Server**: `grain demo -addr 127.0.0.1:18080 -open=false` over its throwaway embedded SQLite store. It served the production frontend, built with `npm run build` into `pkg/ui/static` and embedded by `go build ./cmd/grain`.
**Browser**: Playwright library scripts drove visible controls at 1400×900. They were written for this run under `/tmp` and not committed; they are not the `ui/e2e` specs. Every `console` error and warning, `pageerror`, `requestfailed` (other than `net::ERR_ABORTED`), `/api/` response ≥ 400, non-GET `/api/` request (with its body) and native dialog was logged.

This run follows [2026-10-06-teams-ui.md](2026-10-06-teams-ui.md) and [2026-10-05-teams-ui.md](2026-10-05-teams-ui.md). This time team management went mostly through the sidebar's **New Team** dialog, the Admin **Edit Team** dialog and Team settings > Capacity. The run then looked for edges the earlier runs did not reach:
- non-integer limits;
- a team's default time zone flowing into new schedules;
- deleting a team that has no tasks but still owns a schedule;
- renaming a team while it is selected.

Both bugs below were found that way.

### Console and network
The only errors seen were:
- the expected 400s from refused creates, edits and deletes;
- 404s on `github-branches` (no GitHub in demo).

The red "no model connection / no GitHub credential" banners for a freshly created team stay up beside later messages, so an alert read right after an action can hold several messages. That is expected.

## Findings

| # | Finding | Disposition |
|---|---|---|
| B1 | **A fractional concurrency limit came back as a raw Go decoder error.** The sidebar's Create New Team dialog and Admin's Create/Edit Team dialog sent Max Workers / Max Mergers / Max CI Jobs exactly as typed (`Number(x) \|\| 0`). `CreateTeamRequest` / `UpdateTeamRequest` hold ints, so 2.5 read `json: cannot unmarshal number 2.5 into Go struct field CreateTeamRequest.maxWorkers of type int`. Team settings > Capacity already refused it. | **Fixed**: `ui/src/teamLimits.js` checks the three limits before anything is sent. Both dialogs refuse a fractional or negative limit with `Max Workers must be a whole number, 0 or more.`, Capacity's wording, and keep the dialog open. |
| B2 | **A new schedule kept the previous team's time zone when moved to a team without one.** `ScheduleOverlay` seeds a new schedule with its team's zone. On a Target team switch it called `setTimeZone` only when the new team had a zone, so a schedule opened under a Europe/Berlin team and moved to a UTC team still saved `timeZone: Europe/Berlin`. A zone picked by hand was overwritten by a zoned team's default. | **Fixed**: the seeded zone now follows the target team, back to none too, until a human picks one. A picked zone stays put. |
| N1 | Team create/edit dialogs still offer no agent framework or connection field, although `CreateTeamRequest` accepts both. | Noted, as on 10-06; those are set on Team settings > Models / Connections. |
| N2 | `GET /api/tasks?team=qa-infra` returned every team's tasks: the list does not filter on `team` (the UI filters client-side), so nothing visible is wrong. | Noted only; this was an API read made to confirm the UI, not a UI path. |
| — | 10-06 B1 (Enter on New Team switched to All teams) | Not reproduced. The picker was driven by keyboard throughout. |
