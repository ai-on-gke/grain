# Teams management, task intake and multi-team UI walkthrough

**Date**: 2026-10-06
**Commit tested**: `2101ce9a2` (candidate tip at the start of the run). The fix was re-verified on this branch's own build (`d738ae75b`), on a fresh demo store.
**Environment**: Debian sandbox, Linux x86_64, Go 1.26, Node 20.19.0, Playwright 1.62 with Chromium headless shell 151.
**Server**: `grain demo -addr 127.0.0.1:18080 -open=false` over its throwaway embedded SQLite store. It served the production frontend, built with `npm run build` into `pkg/ui/static` and embedded by `go build ./cmd/grain`.
**Browser**: Playwright library scripts drove visible controls at 1400×900. They were written for this run under `/tmp` and not committed; they are not the `ui/e2e` specs. Every `console` error and warning, `pageerror`, `requestfailed` (other than `net::ERR_ABORTED`), `/api/` response ≥ 400, non-GET `/api/` request (with its body) and native dialog was logged.

This run follows [2026-10-05-teams-ui.md](2026-10-05-teams-ui.md). It checked that run's two findings on the current build, used Admin's **Create Team** / **Edit Team** dialogs for team management (the 10-05 run mostly used the sidebar dialog and Team settings), and then went after edges the scripted specs do not reach: reserved and unusual IDs, mixed-team bulk edits, team-scoped sessions at deletion time, cross-team board deep links, and the team picker driven by keyboard only. The bug below was found in the keyboard pass.

## Stubs

None. The real server, frontend, browser and gestures were used throughout.

Non-UI calls:
- Reads: `GET /api/teams/:id`, `/api/tasks/:id`, `/api/schedules`, `/api/console-sessions` and `/api/boards`, made from the Playwright request context (the same signed-in session) to confirm what the UI showed.
- One API write: `DELETE /api/teams/qa-infra` once, to reset a team an aborted first script run had already created through the UI. It was then created again through the UI.

`GET /api/repos/acme/widgets/github-branches` returns 404 in demo because there is no GitHub; the base-branch field degrades to free text. No Gemini key was present at `/home/debian/.gemini-api-key`, and none was needed, because nothing here dispatches an agent. Demo runs `-ci=false`, so CI runs per team cannot be observed; `/teams/<id>/ci` shows the "Not available … -ci=false" notice under every team.

Setup: `npm ci`, `npm run build`, `go build -o /tmp/grain ./cmd/grain`, and `NODE_EXTRA_CA_CERTS=/etc/ssl/certs/ca-certificates.crt npx playwright install --with-deps chromium`. The first account (`admin`) was created through the demo's own **create account** form. Registration also gave it a personal team, `admin1`. Its slug skips `admin` because `admin` is an admin-only team ID (`model.AdminOnlyTeamIDs`).

### 11. Deletion safeguards
- The default card has no Delete button.
- qa-infra (tasks, a schedule and a session): Delete with the native confirm (`Are you sure you want to delete team "qa-infra"?`) **dismissed** sends nothing. Accepted → 400 `cannot delete a team that still has tasks`, and the card stays.
- release-eng-team held only its Director and a user-made session, "Release war room". Focus the card's Delete button (accessible name `Delete Team`), press Enter, accept the confirm → 204. The card is gone after a reload. Both sessions went with the team.
  - This is deliberate (`DeleteTeamWithUser`): a session that has a conversation holds a task, and a team with tasks cannot be deleted.
  - The confirm does not mention sessions. Noted only.
- `/teams/release-eng-team/session/release-war-room` afterwards falls back to `/session/release-war-room`.

### 12. Keyboard-only team picker (bug B1 found here)
- Focus the picker, Enter, then Tab: focus walks every option and lands on **New Team** (`role="button"`).
- Pressing Enter there opened the Create New Team dialog, **and** switched the app to All teams behind it. The URL went from `/teams/qa-infra` to `/`, and `grain.selectedTeam` was removed. A mouse click on New Team does not do this.
- In the dialog, focus starts in Team name. Enter inside the dialog does not submit (it is not a form), so you have to Tab to **save**. Noted only.

### Console and network
The only errors seen were:
- the expected 400s from refused creates, edits and deletes;
- 404s on `github-branches` (no GitHub in demo).

There were no uncaught page errors and no 5xx. As on 10-05, the steady `net::ERR_ABORTED` on polled `GET /api/tasks` is Chromium's report of a `304` poll reply and was filtered out. An error alert stays up for 5 s (`App.jsx`), so a refusal message can still be showing beside the next, successful action. Cosmetic.

## Findings

| # | Finding | Disposition |
|---|---|---|
| B1 | **Enter on the team picker's New Team button switched the app to All teams.** `Sidebar.jsx`'s `onTeamPickerKeyDown` takes the first option on Enter whenever focus is not on an option. The handler sits on the whole list, so Enter on New Team (below the options) bubbled up to it and clicked "All teams", alongside the button's own click that opened the dialog. | **Fixed**: only Enter from the search field takes the first match. |
| N1 | `/teams/<team>/boards/<id>` opens a board of another team: `openBoardRow` looks in every board, not the team's. The board's query then runs over the URL team's tasks, while that team's board list says it has none. | Noted. This may be intended like cross-team task links (grain/task-1696 made schedules, templates and suites open under any team, naming their own). Whether a board should say which team it belongs to is a design question. |
| N2 | A cold deep link to `/teams/<team>/…` selects that team but does not save it to `grain.selectedTeam`; Back and Forward do. | Noted; arguably right, since a shared link should not change a reader's saved choice. |
| N3 | Bulk edit's Team row on a mixed selection pre-selects `admin (default)` and sends `team: ""`, which the server reads as default. | Noted; the outcome matches the select, and other mixed rows behave the same way. |
| — | 10-05 F1 (schedule could not move back to default) and F2 (team move kept an unservable model) | Both verified fixed on this build. |
