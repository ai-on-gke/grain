## Item 1 — Mixed-version interop

`interop.sh` (`PAIR=old-hub` and `PAIR=new-hub`). Topology: daemon/CLI → `hdrtap` (`:4230`, which logs header names) → `iapstub` (`:4231`) → hub (`:4232`; JWKS `:4233`), with a PostgreSQL hub store (`:4240`) and `tunnel.transport: ws-mux`. Each daemon registers its entry with its *own* version's CLI, opens the outbound tunnel and verifies the hub's assertion (`-ui-require-verifier=registry`). `echoconn.go` is a second connected entry that echoes the `X-Grain-*` headers the hub forwards.

| Check | Old hub (`c08832a2` `grain-registry`) + HEAD daemon (`-hub-*` flags) | HEAD `grain-hub` + old daemon (`-registry-*` flags) |
|---|---|---|
| Register (`grain hub register` / `grain registry register`, `-mint-token`) | ✅ exit 0, `grc_…` | ✅ exit 0, `grc_…` |
| Tunnel connects | ✅ `online/true`, daemon logs `hub tunnel (conn-alice) connected` | ✅ `online/true` (old daemon reports no `grain_version`, as before) |
| Identity assertion through the tunnel (`alice` → `/api/whoami`) | ✅ 200 `{"actor":"alice@example.com","source":"registry","verified":true}`; `bob` → 403 | ✅ same; `bob` → 403 |
| Headers the **hub** forwards to the entry | `X-Grain-Registry-Assertion` only | `X-Grain-Hub-Assertion` **and** `X-Grain-Registry-Assertion` |
| Headers the **daemon** sends on `/connect` | `X-Grain-Hub-Token`, `X-Grain-Registry-Token`, `X-Grain-Auth`, `X-Grain-Entry`, `X-Grain-Connect-Protocol`, `X-Grain-Host-Kind`, `X-Grain-Version`, `X-Grain-Commit`, `Authorization` | `X-Grain-Registry-Token`, `X-Grain-Auth`, `X-Grain-Entry`, `X-Grain-Connect-Protocol`, `X-Grain-Host-Kind`, `Authorization` |
| Headers the daemon sends on each heartbeat (31 in the run) | `X-Grain-Hub-Token`, `X-Grain-Registry-Token`, `X-Grain-Auth`, `Authorization` | `X-Grain-Registry-Token`, `X-Grain-Auth`, `Authorization` |
| Metrics (`GET /metrics` as admin; `alice` → 403) | `grain_registry_*` only (10 series), as `c08832a2` always did | `grain_hub_*` (10) **and** `grain_registry_*` (10), same values (`active_tunnels 2`) |

So each pairing works with only the old headers on one side.

**Observation (no fix possible on the old side).** A *client* that sends its own `X-Grain-Hub-Assertion` through an **old** hub has it passed through untouched, because the old hub only knows to strip and overwrite `X-Grain-Registry-Assertion`. A HEAD daemon then sees two different assertion values and refuses with **401** (`conflicting … headers`, `pkg/webauth/hub.go:78`). This fails closed: there is no bypass, because both values must verify against the hub's JWKS. It can only break the sender's own request, and only while an old hub fronts a new daemon. The HEAD hub overwrites both names (`proxy.go:160`), so a forged header of either name is replaced. That is the transcript's `client sends X-Grain-Hub-Assertion: forged → 200` on the new-hub pairing.
