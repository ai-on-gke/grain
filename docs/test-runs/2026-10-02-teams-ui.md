# Teams management, task intake and multi-team UI walkthrough

**Date**: 2026-10-02
**Commit tested**: `cf9d6156c` (candidate tip at the start of the run). Fixes re-verified on this branch's own build (`8a48308f2`).
**Environment**: Debian sandbox, Linux x86_64, Go 1.26.6, Node 20.19.0, Playwright 1.62.1 / Chromium headless shell (chromium-1234)
**Server**: `grain demo -addr 127.0.0.1:<port> -open=false` over its throwaway embedded SQLite store, serving the production frontend built with `npm run build` into `pkg/ui/static` and embedded by `go build ./cmd/grain`
**Browser**: Playwright library scripts (not the `ui/e2e` specs) driving visible controls at 1400×900. Every `console` error and warning, `pageerror`, `requestfailed` and HTTP status ≥ 400 was logged.

This run follows [2026-10-01-teams-ui.md](2026-10-01-teams-ui.md). It went deliberately past both earlier runs: invalid input in **Edit** Team, deletion blocked by schedules, what deletion leaves behind, schedule team reassignment, team-scoped session creation, and "new board" routing when the team is switched afterwards.

## Stubs

None. The real server, frontend, browser and gestures were used throughout. Non-UI calls, all reads or setup:
- `GET /api/teams`, `/api/teams/<id>` and `/api/console-sessions`, to confirm what the UI showed.
- One `POST /api/tasks` with `curl` (task 15), to check whether the server itself accepts a task on one team aimed at another team's config repo (F5).
- One `POST /api/auth/login` from the Playwright request context, to sign the keyboard probe back in on the second demo.

`GET /api/repos/acme/widgets/github-branches` returns 404 in demo because there is no GitHub. That is an external boundary, and the branch picker degrades to free text. No Gemini key was present at `/home/debian/.gemini-api-key`. None was needed, because nothing here dispatches an agent.

Setup, as in the last run: `NODE_EXTRA_CA_CERTS=/etc/ssl/certs/ca-certificates.crt npx playwright install --with-deps chromium`. The first account (`admin`) was created through the demo's own **create account** dialog.

## Findings

| # | Finding | Disposition |
|---|---|---|
| F1 | **Edit Team** with a negative limit returns **500** (create returns 400). `UpdateTeam` left the check to the store, whose plain `Validate` error maps to a server error. The same applies to an invalid `timeZone` over the API. | **Fixed**: `UpdateTeam` runs `Team.Validate` on the edited row and answers 400. |
| F2 | Deleting a team leaves the Director session `CreateTeam` seeded for it, plus any other session of that team, listed under All teams. A team re-created under the same ID gets a second Director. | **Fixed**: `DeleteTeamWithUser` removes the team's console sessions after the store delete. |
| F3 | A team with no tasks but a schedule is refused with "cannot delete a team that still has tasks". | **Fixed**: the store returns `ErrTeamHasSchedules` ("…still has schedules"), which still matches `ErrTeamNotEmpty`. |
| F4 | The Create Team dialog was retitled "Edit Team: <name>" during its fade-out after a successful save. | **Fixed**: it switches to edit mode only when the follow-up credential write fails, which is the retry case it exists for. |
| F5 | In New Task, changing Target team keeps the old team's config repo (e.g. **new board** opened under default, then moved). Separately, the server accepts any team's `grain/config-<id>` as a target for a task on any team (`model.RepoAllowed` admits every team config repo), so `POST /api/tasks {"team":"platform-reliability","repo":"grain/config-default"}` → 201. | **UI fixed**: the repo follows the team to its own config repo. **Server-side scoping: follow-up proposed** (isolation design question). |
| F6 | From code, not observable in demo, where no orchestrator runs: `reconcileConsoleSessions` files a task on each session's team, and every team gets a Director at creation. On a running deployment, every team therefore has a task once the first cycle has run, and `DeleteTeam` refuses it with "still has tasks". | **Follow-up proposed.** |
| — | Enter in the team search box doesn't pick the single match. Bulk-edit's mixed Team select shows `admin (default)`. A schedule keeps the previous team's time zone when moved to a team without one. Fractional limits get raw Go decoder text. Task detail URL stays under the old team after moving the task. | Minor, noted only. |
