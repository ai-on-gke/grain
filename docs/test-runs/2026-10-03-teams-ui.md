## Findings

| # | Finding | Disposition |
|---|---|---|
| F1 | **Create Team accepts an ID that differs from an existing one only in case**: `QA-Infra` beside `qa-infra`, and `Default`/`DEFAULT` beside the built-in `default`. Team config repos are matched to their team ignoring case (`Store.RepoTeams`, `RepoOwningTeam` use `strings.EqualFold`). So `RepoTeams(grain/config-qa-infra)` returned `[QA-Infra qa-INFRA qa-infra]`, and `RepoOwningTeam`, walking teams in ID order, picked the upper-case impostor first. A `Default` team would own `grain/config-default`, which the real default team never claims. The cards lower-case their text, so the two teams look identical. | **Fixed**: `CreateTeam` looks the ID up with `Store.TeamIDTaken` (case-insensitive) and answers 400 (`team ID "QA-Infra" differs from the existing team "qa-infra" only in case`). The default-team guard ignores case, and generated slugs skip case variants of stored IDs. Stored rows are untouched. |
| F2 | Team picker keyboard dead end: Enter in **Search teams…** didn't pick, ArrowDown didn't reach the options, and the old search survived closing. This was noted as minor on 10-02. | **Fixed**: Enter takes the first option shown, ArrowUp/ArrowDown move between options, Escape closes and refocuses the Team button, and closing clears the search. |
| F3 | A schedule deep link under a team the schedule no longer belongs to silently shows that team's (possibly empty) list. Templates and suites use the same `visible*` lookup. Task deep links open regardless. | **Fixed (grain/task-1696)**: the pane now opens whatever team the URL names, as task detail does, and its Target team field shows where the item is. A link to an item that does not exist still says `no schedule "<id>"`. Covered by `ui/e2e/cross-team-deep-links.spec.js`. |
| — | Personal team from registration (`admin1`) has no Director session. Non-ASCII letters are dropped from generated slugs (`Ünïcode Team ✓` → `n-code-team`). The task detail URL stays under the old team after moving the task. No framework/backend fields in the Team dialog (API only). | Minor, noted only. |
