Task 412's whole brief was "test the grain CI by submitting a run": drive
one dispatched agent run all the way through to a verdict from

no defect to fix and no feature to add, so this file is the deliverable
-- the change it carries into CI is this file itself.

## Why a docs-only change still exercises the whole suite

`tests.yml` triggers on `pull_request:` with no `paths` filter, so a
commit that touches nothing but `docs/` runs every job in it: the Go
suite, the frontend, the Playwright UI suite, both real-KVM suites, the
container and installer suite, actionlint, shellcheck and Terraform. That
is the property this run was checking, and it is worth stating plainly
because it is easy to assume the opposite: a docs-only pull request here
is not a cheap pull request, and it is a complete test of CI.

The corollary matters more to an agent than to a person. A push to a
branch is *not* what starts these checks -- `push:` is scoped to `main`
-- so a run that pushes `grain/task-NNN` and then waits for a verdict
waits forever unless it opens the pull request first. `open_pull_request`
before `wait_for_checks`, not after.
