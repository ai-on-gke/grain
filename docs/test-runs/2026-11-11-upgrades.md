## Item 3: minimum interval

- **F3, the method: `faketime` cannot drive a grain daemon.** `faketime -f '+7h' /tmp/now` (a two-line Go program printing `time.Now()`) printed the real time. `grain` reads its clock through the Go runtime's vDSO call, not through libc, so libfaketime's `LD_PRELOAD` never sees it. The daemon offers no clock override either. So "two releases within 6h → one drain" under `faketime`, as the plan words it, cannot be walked on a real daemon. A real walk would mean waiting out the 1h settle window plus a 6h interval. I filed a follow-up for a test-only clock seam.
- Instead, the clock-driven cases come from the reconciler tests. They drive `reconcileReleaseUpgrade` with explicit times against a real store. I ran them with `GRAIN_REQUIRE_POSTGRES=1` (PostgreSQL installed) as well as on SQLite:
  - `TestMinIntervalCoalescesReleasesAfterACompletedUpgrade`: two releases inside 6h give one drain, and that drain goes straight to the newest.
  - `TestMinIntervalZeroTurnsItOffAndFailedOrUnchangedDoNotResetIt`: `0` turns the interval off, and a failed upgrade sets no cooldown.
  - `TestMinIntervalHugeValueDoesNotWrap` (**new**).

  An unchanged upgrade sets no cooldown either: `watchAutoUpgrade` sets `SucceededAt` only when `status.Unchanged` is false.
- **"A huge value doesn't wrap".** On the real daemon (`/tmp/d3`), `PUT /api/settings {"autoUpgradeMinIntervalHours": 9223372036854775807}` returned 200. `model.Config.AutoUpgradeMinInterval` saturates, so the reconciler never wraps. However, the value comes back to the browser as the JSON number `9223372036854775807`, which JavaScript reads as `9223372036854776000`. Saving the field again then sends a number Go refuses (`json: cannot unmarshal number … of type int`, HTTP 400). The same happens for `1e20`. **F2, fixed:** the API now refuses values above `model.MaxAutoUpgradeMinIntervalHours` (2562047, the most whole hours a `time.Duration` holds, about 292 years) with `autoUpgradeMinIntervalHours must be at most 2562047 …`. `grain sync` goes through the same API. `-1` is still refused, and `0` is still accepted.
- **Settings field only for "On each release".** In `UpgradePanel.jsx`, the minimum-interval field and its helper text render only under `mode === "release"`. I confirmed that by reading the code. `UpgradePanel.test.jsx` covers saving the field (including `0`). I did not re-shoot it.
