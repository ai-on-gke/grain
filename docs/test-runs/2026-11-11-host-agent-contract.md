## Item 2 — open env and the deny set

- **Daemon-supplied variables arrive.** On a real agy run on `walk`, the
  stub saw `AGY_CLI_DISABLE_AUTO_UPDATE=true`, admitted by `"*"`, and the
  per-run `HOME`, admitted because `HOME` is listed by exact name. It got
  nothing else beyond the identity variables. The codex run got
  `CODEX_HOME` and `CODEX_EXEC_SERVER_URL`.
- **The deny set is refused** by a real HEAD grain-agentd, over its socket
  (`envprobe`):
  - Refused: `PATH`, `HOME` (not listed for codex), `USER`, `LD_PRELOAD`,
    `LD_LIBRARY_PATH`, `BASH_ENV`, `ENV`, `NODE_OPTIONS`, `PYTHONSTARTUP`,
    `PYTHONPATH`, `PERL5OPT` and `RUBYOPT`, each with
    `environment variable X is not one this entry accepts`.
  - Admitted: `GRAIN_WALK_FROM_DAEMON`, `OPENAI_API_KEY` and
    `AGY_CLI_DISABLE_AUTO_UPDATE`.
- **Old agentds are never sent new syntax:**
  - With v3.2.0 and then v3.5.1 connected, `GET /api/hostds`'s
    `allowlistSnippet` for `walk` was the closed `env: [MCP_TOOL_TIMEOUT, …]`
    list with absolute paths, never `"*"` or `~/`.
  - `allow -target-bin <old>` did the same (item 1).
  - Real codex, agy and claude runs on the old hosts' closed-list allowlists
    started, so the daemon sent them no name outside their lists.
  - v3.2.0 refuses a `~/` entry (`the binary must be a clean absolute path`),
    which is why this matters.
- **Finding (filed, not fixed):** variables outside the frozen set are
  admitted under `"*"`.
  - `JAVA_TOOL_OPTIONS=-javaagent:…` passes: the value does not start with
    `/`, so `paths_under` is never applied. So do `GIT_CONFIG_PARAMETERS`,
    `PROMPT_COMMAND`, `SHELLOPTS` and `PS4`.
  - `GCONV_PATH`, `NODE_PATH`, `PYTHONHOME`, `PERL5LIB` and `RUBYLIB` pass
    only for paths under `paths_under`, the stage directory the daemon can
    write.
  - The design's own argument (an agents-only host's CLI already has a shell)
    makes this defence in depth. The set is frozen, so widening it is a
    contract decision. Filed as a held proposal.

**Result: holds as designed.** Deny-set scope filed for a decision.

## Item 5 — drain with a run in flight

With an agy run detached on `walk` (the stub sleeping 15 s), `drainprobe`
over walkhost's socket gave:

```
in flight: cli agy pid 8650 run 6-1 detached=true
drain answered after 1ms
start right after the drain: err=the host agent refused: grain hostd is draining for an upgrade; … draining=true
hello while draining: draining=true
```

- The host logged `refusing new starts; 1 process(es) still running`. When
  the agent exited (13 s later) it logged `cli "agy" (pid 8650) ended: code 0`
  and `drained; exiting so the new build takes over` in the same second.
  The drain was done the moment the agent exited.
  - drainprobe's own "gone after 44s" is the client's 30 s dial retry on a
    missing socket, not the host lingering.
- A drained grain-agentd exits **0** (checked with nothing running:
  `agentd exit status 0`).

**Bug (fixed here):** `grain-agentd install` wrote `Restart=on-failure` into
`~/.config/systemd/user/grain-agentd.service`.

- A drain or cutover ends with that clean exit 0, so systemd never started
  the host again.
- The design ("Cut over": systemd `--user` (`Restart=always`) starts the new
  binary) and `grain-hostd.service` (`Restart=always`) both rely on the
  restart.
- Fix: the unit now says `Restart=always`. `systemctl --user stop` is still
  final. `TestInstall` asserts it (`pkg/agentd/install_test.go`), and
  `docs/grain-agentd.md` says re-running `grain-agentd install` rewrites an
  older unit.
- Re-running the fixed `grain-agentd install -no-start` on walkhost rewrote
  the unit with `Restart=always`.

**Finding (filed):** the drained host exited in the same second the run's
CLI ended. The daemon logged `lost host walk while streaming run 6-1's CLI …
at cursor 88; … re-attached if the host agent is back within 15m0s`: the
Exit frame was lost.

- When the host came back, it logged `kept the final spool of cli "agy"
  (run 6-1 …) for a daemon to read`. The daemon re-attached, and the task
  moved on (`awaiting_reply`).
- With `Restart=always` that is a ~10 s delay. Under the old unit it was up
  to 15 minutes with the host offline.
- Filed as a follow-up: a drained host should flush the Exit frames of
  attached streams before it exits.

**Result: holds** (refuse at once, done when the agent exits). The
restart bug is fixed, and the Exit-frame race is filed.
