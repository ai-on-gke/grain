## Stubs

- `localStorage["grain.username"] = "debian"` (an init script) so the
  first-visit "create account / log in" dialog does not cover the app.
  The demo trusts loopback as the `debian` user, but a browser with no
  remembered username is still asked to pick one (`isFirstTimeUser` in
  `App.jsx`). That is the intended first-visit behaviour, not a bug.
- Nothing in grain's API or frontend was stubbed. The external
  boundaries that are unavailable here showed up as such: GitHub
  (`GET /api/repos/acme/widgets/github-branches` → 404 whenever a task
  detail's branch picker loads; console error only, nothing shown to the
  user) and grain CI (the demo runs with `-ci=false`, so the CI page says
  "Not available"). CI-run team filtering could therefore not be
  exercised against real runs.

### Schedules

16. `/t/qa-infra/schedules` → + New schedule ("In team QA
    Infrastructure"), title, every 12h → `sched-3` with `team: qa-infra`.
    It is listed under QA Infra only (also after a reload), not under
    default. **Pass.**
17. **Bug found and fixed.** The form's "What this schedule files" preview
    gave the model as "the deployment's default model / the deployment
    decides" for a QA Infra schedule, although QA Infra has default model
    `gemini-3.1-pro` and the tasks it files run on that.
    Cause: `ScheduleOverlay` added `team` to the save payload only, not to
    `scheduleRequest()`, which the preview POSTs to
    `/api/schedules/composition`. The server therefore composed every
    draft as the default team's.
    Reproduction: create a team with a default model, open its Schedules,
    open + New schedule and type a title. The preview's Model row names
    the deployment.
    After the fix it reads "the team's default model (gemini-3.1-pro) /
    the team decides". Rechecked in the browser after a rebuild.
    Regression test: `SchedulesList.test.jsx` "previews a new schedule as
    its own team's". It fails without the fix ("expected undefined to be
    'infra'") and passes with it, along with the other 80 tests in that
    file.
18. Edit `sched-3` → Target team `security-ops-squad-1` → Save. The repo
    choices follow to that team's config repo, the schedule leaves QA
    Infra's list and appears on the squad's, and a deep link through
    `/t/qa-infra/schedules/sched-3` resolves to
    `/t/security-ops-squad-1/schedules/sched-3`. **Pass.**
