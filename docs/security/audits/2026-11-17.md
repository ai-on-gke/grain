## Findings

### 1. Three surfaces added this range are outside the trust-boundary list, so a change that weakens them merges without a security hold

**Severity.** Medium, as the previous reviews rated the same class of gap
(v22 `pkg/webauth/`, v23 the human-review hold, v28 the six script and
package siblings, v29 `access_code_mode.go`). **Reproduced.**

**Where.** `pkg/trustboundary/trustboundary.go` (`Version =
"trust-boundary/v29"`, `Categories`), which `pkg/orchestrator/securityhold.go`
line 164 (`trustboundary.Classify(files)`) and line 631 consult to decide
whether a pull request is held for a security review. Three surfaces the
range added decide who is admitted or what a host executes, and
`Classify` returns nil for every one of them:

1. **`pkg/ui/accept_findings.go` and `pkg/model/review_findings_accept.go`**
   (#1292, merged 11-16 03:01). `AcceptReviewFindings` is the only path
   that clears a review's findings on a gate (`security-review`, `review`
   or `trigger:<name>`) without a clean re-review; the security hold's
   own refusal text now points at it. It refuses a limited role
   (`!a.Full`) and any principal that is not a person
   (`who.Actor.Kind != model.PrincipalHuman`, line 69). That is the same
   rule v23 classified `pkg/model/human_review_hold.go` and
   `pkg/ui/human_review.go` under auth-routes for ("an agent may raise a
   human-review hold but never release it, which the security hold relies
   on"); `Classify` puts those two in auth-routes and the new pair nowhere.
2. **`pkg/ui/verifier_session.go`** (#1574, merged 11-16 07:47, whose
   last commit is the "refuse SessionGrace from a verifier that binds no
   session" tightening). It issues and checks the HMAC-signed session cookie that admits
   a request *without* `IdentityVerifier.Verify` (`verifyWithSession`,
   `requestVerifierSession`, `sameSessionPrincipal`, `parseVerifierSession`)
   -- authentication in the plainest sense, next to `pkg/ui/verifier.go`,
   which is in auth-routes.
3. **`pkg/agentd/update.go`** (#1533, merged 11-15 07:29) with the
   package it completes: `pkg/agentd/release/release.go` (`VerifyManifest`,
   `resolveSigningKey` -- the pinned key and its rotation chain),
   `pkg/agentd/install.go`, `pkg/agentd/release/cmd/grain-agentd-sign/main.go`
   and `scripts/build-agentd.sh`. `updater.run` fetches a manifest and a
   binary from the controller, verifies the manifest's signature against
   the key pinned at install and the binary's size and SHA-256, then runs
   the binary (`runStaged`) and makes it the host agent (`switchCurrent`),
   pinning any rotated key. This is the host's half of the signed-release
   contract whose controller half (`pkg/ui/hostd_install.go`, classified
   setup-scripts) and build half (`release-train-assets.yml`,
   release-machinery) are on the list, and whose sibling `pkg/hostd/` is
   exec-sandbox. The host-owned allowlist's `update:` policy and the pinned
   key exist precisely so that a controller cannot push an arbitrary binary
   onto a host; the code that enforces both is reviewable by nobody the
   hold knows about.

**Who can do what.** Anyone who can land a green pull request on `main`
unattended -- an agent task filed by a role holding `tasks:write` with
`autoMerge`, a `base-green` repair, or an external contributor whose pull
request is set to auto-merge -- can, with no security review filed:

- drop the `PrincipalHuman` check in `AcceptReviewFindings`, after which
  any agent (including the reviewed task's own run, through the agent

  merges over them;
- change `sameSessionPrincipal`, `requestVerifierSession` or
  `parseVerifierSession` so a replayed or re-signed cookie is admitted as

- change `resolveSigningKey` to accept an unanchored rotation, or
  `updater.run` to skip `VerifyManifest`/`VerifyBinaryHash`, after which
  every enrolled host whose owner runs `grain-agentd update` (and every
  host, once `update.mode: auto` is implemented) executes whatever the
  controller's `/api/hostd/agentd/{os}/{arch}` route serves, as the host

## Examined and found sound

- **CI API list routes without a repository** (#1556,
  `pkg/capability/ciapi/serve.go`, `pkg/ui/access_roles.go` lines

  (`requireRepo`/`unowned`, two levels deep), refuses a 200 that is not

  single object owned by another repository as not found.
  `HoldsReleaseGate` tightens `POST /api/notifications/release-pending`
  from "may file release-notes" to the whole `release-gate-read` preset.
- **External pull-request feedback waking tasks** (#1713,
  `pkg/orchestrator/githubevents.go`, `pkg/model/pr_feedback.go`,
  `pkg/orchestrator/run.go`). Comments, inline review comments and
  reviews on a grain-owned pull request are recorded as PR feedback and
  can make a waiting task dispatchable -- but only after
  `senderTrusted` (`CollaboratorPermission` through
  `IsTrustedCollaboratorPermission`, cached per repo+login, false on
  404/403 or when the client cannot read collaborators), after the
  self-bot and `IsGrainSignedComment` echo checks on the *new* text only
  (the enclosing PR body no longer counts), and with the body quoted line
  by line under a header saying it is untrusted input that answers no
  question and grants nothing. The prompt section says the same, and
  acknowledgement is tied to the dispatch that carried it in full
  (`ackBlocked` when the notice was truncated).
- **Host agent self-update** (#1533, `pkg/agentd/update.go`,
  `pkg/agentd/release/release.go`, `pkg/hostd/allowlist.go`). Order of
  checks: allowlist `update.mode` (off refuses), pinned key read,
  manifest parsed, platform matched, `VerifyManifest` (ed25519 over the
  canonical text; a rotation accepted only through `resolveSigningKey`'s
  chain from the pinned key), version against `update.pin` and
  "no downgrade unless pinned exactly", `versionDirRE` on the directory
  name, binary fetched and `VerifyBinaryHash` (size and SHA-256), then
  `-build`/`-check` from a `CreateTemp` under the user's own `versions/`,
  rename into place, guard and pending files, `switchCurrent`; a rotated
  key is pinned only after all of that. The controller can advertise an
  update (`Hello.Platform/UpdateMode/UpdatePin`) but cannot write the
  policy or the pin; `FeatureSelfUpdate` is removed from `Hello.Features`
  unless `Server.SelfUpdate` is set, so a root `grain host` is never
  offered one. (The classification gap is finding 1; the code holds.)
- **Host daemon stop** (#1601, #1469, `pkg/hostd/server_linux.go`,
  `pkg/agentd/install.go`). Connections outlive Serve's `ctx` only until
  `stopped()` has set `s.closing` (new starts refused), killed what still
  ran as `killStopping` and waited `exitGrace` for the exits to be read;
  `KillMode=mixed` SIGKILLs anything left in the unit's cgroup once the
  agent exits, so a stopped unit leaks no CLI. `Exit.Stopped()` maps to
  `ErrHostdStopped` → `InterruptedOutcome`, no strike.
- **Accept findings** (#1292, `pkg/ui/accept_findings.go`). Person-only
  (`PrincipalHuman`), unlimited role only (`!a.Full` refused in the
  client and again in `filingEscalation` for roles), a reason of at most
  500 characters required, the gate named explicitly, and recorded

  (`ErrFindingsRequireRereviewOrOverride` still stands for Submit and
  Release). `tests/security` covers the route. Sound as code; see
  finding 1 for the list.
