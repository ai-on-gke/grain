## Observations (not findings)

Recorded so the next review can tell what was weighed and why it was
not filed. None names a caller who can do something they should not be
able to today; each is a place where the line is thinner than the
surrounding ones.

1. **A sandbox re-runs `push`-event Actions runs through the API door**
   (#1302, `pkg/ui/ci_actions_rerun.go`). `POST /api/ci/runs/{id}/rerun`
   under `ci:write@repo` takes a `gha:` run id and, for a non-human
   caller, refuses only `workflow_dispatch`, `release`,
   `pull_request_target` and `deployment` events
   (`isPersonOnlyActionsEvent`). On this repository `push` to `main`,
   `candidate` and `v*` tags runs `release.yml`, `promote.yml`,
   `publish-release.yml` and `release-train-assets.yml`, which hold the
   registry, image-signing and agentd-signing secrets. A re-run is of
   the same commit with the same inputs, so no new code runs under those
   secrets; `scripts/release-images.sh`'s `tag_may_move` is forward-only
   and refuses release tags, so an old run cannot move `main`, `latest`
   or a stamped `vX.Y.Z` backwards; `promote.yml` re-reads the git
   `latest` tag at run time; and GitHub's own `run_attempt` bounds each
   run at `MaxActionsRerunsPerHead` (3). What remains is re-publishing
   identical content and spending signing-key uses, which is not a
   failure mode. The sandbox CLI door (`grain ci retrigger`) is narrower:
   it lists only `push`/`pull_request`/`merge_group`/`dynamic` runs on
   the task's own branch, owned by the task's own head repository, at
   its pull request's head. A later change that gives `ci:write` to a
   broader population, or a workflow whose `push` run reads mutable
   state that is not forward-only, should revisit adding `push` on
   protected refs to the person-only list.

2. **The merge credential is a named credential like any other** (#1215,
   #1256). `TeamGitConnection.MergeCredential` names a credential under
   `secrets/github`; the REST client merges under it alone and refuses
   to fall back to the push credential. Nothing excludes that name from
   the `repo#credential` grant's enum (`grainserver.repoCredentialArgs`),
   so a task a person grants `repo#credential {name: <merge app>}` pushes
   through the git proxy as the App whose bot login `GRAIN_MERGE_LOGINS`
   trusts. The proxy still holds the task to `repo#write {refs}` (its
   own branch unless widened), the grant is a per-task decision that
   `settings/capabilities.yml` can hold to a person, and the reviewed-
   merge gate reads the pull request's `merged_by`, not a push. Not a
   finding; a deployment that adopts a merge credential should keep it
   out of any repository-default grant list, and `grain health` could
   warn when a task holds it.

3. **`env_deny_v2` is a blocklist** (#1326, `pkg/hostd/allowlist.go`).
   Under a host allowlist entry that says `env: ["*"]`, hostd now also
   refuses `DYLD_*`, `GCONV_PATH`, shell startup variables, interpreter
   module paths, JVM option variables, `GIT_*`, `XDG_CONFIG_HOME`,
   `OPENSSL_CONF|ENGINES|MODULES` and `LUA_*`, on top of the frozen v1
   set (`LD_*`, `BASH_ENV`, `ENV`, `NODE_OPTIONS`, `PYTHONSTARTUP`,
   `PYTHONPATH`, `PERL5OPT`, `RUBYOPT`, identity variables). The names
   the daemon sends a host are a fixed per-framework set
   (`claude.HostdEnv`, `codex.HostdEnv`, `antigravity.HostdEnv`), none
   task-controlled, so the list defends against a compromised daemon
   under an operator-chosen open allowlist rather than against a task.
   Names still admitted that a future walkthrough may want to weigh:
   `GLIBC_TUNABLES`, `MALLOC_*`, `GODEBUG`/`GOFLAGS`, `SSL_CERT_FILE`/
   `SSL_CERT_DIR`, `CURL_HOME`, `HOSTALIASES`, `RES_OPTIONS`,
   `NODE_EXTRA_CA_CERTS`, `PIP_*`, `NPM_CONFIG_*`, `GEM_*`, `TCLLIBPATH`.
   Append-only under a new feature, as the comment on the list says.

4. **`GET /api/tasks/{id}/diff-preview` under `tasks:read`** (#1233)
   shows up to 30 hunks of a task's branch diff to a caller who may not
   hold `repos:read` (which `GET /api/repos/{owner}/{name}/compare`
   needs). The agent gate binds the call to the task's repository
   (`agentCallRepo` → `taskRepo`), the body is passed through the
   deployment's secret redactor (and refused when the redactor cannot
   load), and `tasks:read` already serves the run transcript
   (`GET /api/tasks/{id}/attempts/{number}/transcript`), which carries
   the same file contents. Consistent with the existing line.

## Examined and found sound

- **Security review carried across a head move** (#1301,
  `pkg/orchestrator/samechange.go`, `securityhold.go`). A head that
  moves without changing the change keeps its review, findings and
  clearance instead of filing another. `sameChange` compares GitHub's
  three-dot diffs (`/compare/base...head`) of the previous and new heads
  file by file after `filePatches` normalisation, which drops only
  `index`/`similarity` lines and hunk headers (git patch-id's rule),
  keeps context and mode lines, refuses binary patches and quoted
  paths, and reads as "changed" on any error. An evil merge of the base
  shows in the three-dot diff and is reviewed again. `carrySecurityReview`
  re-decides who must approve: a Submit is consumed unless pinned to the
  new head, `RequiresHuman` matches re-raise the human-only hold, owner
  approvals are asked again; `c26610624` (same PR) stops a head being
  carried past a person-only gate it has no hold for. The
  `tests/security` suite passed over it.
- **`POST /api/declarations/revoke`** (#1324,
  `pkg/ui/declaration_acceptance.go`). Takes exactly what accepting
  takes -- a person acting directly, not delegated, holding every scope
  the accepted set needs -- and the store refuses the revocation
  (`ErrAcceptanceMoved`) unless the accepted set is still the one the
  scopes were checked against. Recorded in the config audit.
- **Public `grain-agentd` download** (#1159, `pkg/ui/hostd_install.go`).
  `{os}/{arch}` are held to `[a-z0-9]` and then to
  `agentdrelease.Platforms`; a local signed manifest is preferred, an
  upstream fetch is bounded (64 MiB, 60 s, 30 s backoff after failure)
  and refused unless signed by the pinned key, and the bundled fallback
  is hash-checked against a manifest in an operator-owned directory.
  Bearer guesses on the open route still count against `s.access`.
- **Actions re-runs from a sandbox** (#1302, `pkg/gitproxy/cli_actions.go`,
  `pkg/ui/ci_actions_rerun.go`). On a repository GitHub Actions gates,
  `grain ci retrigger`/`run-job` re-run only the runs at the task's own
  pull request's head (refusing when the head cannot be read, so a
  same-named fork branch is never picked), bounded by `run_attempt`.
  This door no longer needs `api:ci-read`, which is deliberate: it is
  the capability a task always had by pushing an empty commit, minus
  the head move that threw approvals away.
- **Template sandbox shape** (#1269, #1435).
  `model.ValidateTemplateSandbox` caps `cpus`/`memory-mb`/`disk-gb` at
  the default ceilings on `POST/PATCH /api/templates`, in the state-repo
  importer (`decl.go`, mapping and verbatim spellings alike, unknown
  keys refused by name), and the agent gate holds a `sandbox` body key
  and a filed template to the role ceiling and the agent's own task's
  shape (`checkFilingTemplate`); run-end proposals are clamped to the
  deployment maximum (`clampProposalSandboxShape`) and the note says so.
- **Agent API gate otherwise** (#1224, #1217). The `tasksAdmin` patch
  body rule, the approval rails and the cross-task rail are unchanged in
  logic; only refusal texts now spell canonical references. The relayed
  `commentDelivery`/`notice`/`relayed` fields are response pass-through.
- **Relayed answers** (#1217, `pkg/ui/relay_comment.go`). `relay: true`
  on `POST /api/tasks/{id}/comments` is allowed only to a console
  session acting on behalf of a verified person, never an external
  credential or a dispatched run, never onto itself, and the person's
  own role is checked as for their own comment (`personMayReply`,
  including `roleTaskWithin`). What a human comment unlocks was traced:
  waking a parked task (`reopenAcknowledgeable`), settling review
  questions (`reviewquestions.go`, which re-files the review after the
  fix pushes and restores auto-merge only when no human-only or pending
  review hold stands), and goal/no-progress resets. No approval,
  Submit, declaration acceptance or access grant reads comment
  authorship.
- **Access roles** (#1090, `pkg/ui/access_principals.go`). The
  self-change check was split into escalation (refused) and
  narrowing (confirm), run after `checkLastFullAdmin`; the widen test
  (`noWiderThan`), the deny-entry refusal and the "add an entry matching
  yourself" refusal are intact. `cleanAccessReason` strips ANSI and
  control characters from audit text. The access-code page's form
  action carries the deep link's `#fragment`, which never reaches the
  server.
- **GCP test endpoints** (#1322, `pkg/capability/gcpsets/endpoints.go`).
  Need both `-test-endpoints` and `GRAIN_GCP_TEST_ENDPOINTS` (the
  variable alone is refused), every service or none, loopback hosts
  only, no credentials or query in the URL, and the metadata-server
  credential source is refused under them so a real token is never sent
  to a stub.
- **CI API token in step env** (#1319, `ciapi.StepEnv`). Exported only
  from placements the job's own grant materialised; the same job that
  already had the token as a file.
- **Go build cache writers** (#1261, `pkg/daemon/ci_gocache.go`). A job
  writes the shared cache only when its commit is vouched for, its event
  is `push`/`release`/a trusted schedule, and `CiReleaseRefRefusal`
  passes its ref (default, paired or open-release branch); a fresh
  256-bit token per job, revoked on release. Pull requests, task
  branches, manual runs and every task sandbox stay readers (closes
  finding 1 of `2026-11-10-sandbox-to-host.md`, #1230).
- **Kubernetes** (#1139). Open-network granule pods get the
  metadata-server guard env after the operator's env, so it cannot be
  overridden; external capability grants are refused unless the
  operator asserts `NetworkPolicyEnforced`.
- **Upgrade cancel and rollback** (#1226, `pkg/upgrade/rollback.go`).
  `DELETE /api/upgrade/current` takes only a reason; the rollback target
  is the status file's recorded previous commit (full object id,
  fetched by id, verified `rev-parse` round-trips, `--end-of-options`
  everywhere) or previous image (digest-pinned only), never caller
  input.
- **Secrets** (#1335, #1389). `OpenShared` caches a store per
  (key file, data file) and never for a KMS key source; the shared
  store's key is otherwise the one on disk.
- **Merge credential** (#1215, #1256). Merges go through the named
  credential's token or are refused (`ErrNoMergeToken`); a merge
  credential behind a command-backed push credential is refused; the
  "merged-as" event records the forge's `merged_by`.
- **State repo** (#1234, #1260). `usage_setting` is on
  `SettingsTables` and on `NeverAutoMergePaths` together, validated by
  `statecheck.UsageSettings`; a store that predates the table exports
  nothing rather than failing.
- **Workflows** (#1159, #1410, #1253). `tests.yml` still runs on
  `pull_request` (not `_target`) with `persist-credentials: false` and
  pinned actions; dispatch inputs in the release workflows reach shell
  only through `env:`; `cosign` is pinned by sha256.
- **Host agent lifecycle** (#1173 and the hostd fixes). The socket is
  bound in a private directory, chmod 0600, renamed into place, and
  `peerUID` admits hostd's own uid only; the handover and drain changes
  are stream and reaping fixes, not authorization.
- **Dead code removals** (#1237, #1338) remove unexported or unused
  helpers (`hasGrant`, `AmbientHome`, `authenticateSandbox`,
  `IsJournalGrant` and kin); every remaining caller uses the checked
  path.
- **QA control plane** (#1404). Off by default (`qaEnabled: false`),
  settings-gated, writes only `<dataDir>/perf/qa-checks.jsonl`; adds no
  route.
- **Security fixes landed in range**, read as such: #1257 (CI-only
  grants refused on relayed proposals and at approval), #1276
  (brief/compact/rollover held to the cross-task rail -- finding 1 of
  `2026-11-11.md`), #1303 (wait targets' notes withheld outside the
  waiter's repositories), #1361 (grant check refuses ungrantable repo and
  scope-set grants), #1230 and #1261 (Go build cache), #1139 (metadata
  fence), #1326 (`env_deny_v2`), #1269's `2e0812e46` (template sandbox
  ceilings), #1256 (merge credential), #1301's `c26610624` (person-only
  gate not carried), #1435 (run-end proposals clamped).
