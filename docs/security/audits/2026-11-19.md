## Findings

### 1. `pkg/ui/agent_cross_task.go`, the cross-task rail every agent steering and halting route runs through, is outside the trust-boundary list, so a change that narrows it merges without a security hold

**Severity:** medium. **Reproduced:** yes, against the classifier
(below); not end to end against a live daemon, as the classification is
the whole decision (`pkg/orchestrator/securityhold.go` line 164,
`matches := trustboundary.Classify(files)`, and line 178, `known &&
len(matches) == 0` clears the hold; `repoGuard` adds only trigger,
template and state-repo matches for this repository).

**What the file decides.** `agentRails` in `pkg/ui/agent_api_gate.go`
(auth-routes) calls `s.agentCrossTaskRail` for every non-GET agent call
that names a task. The rail, and everything it consults, lives in
`pkg/ui/agent_cross_task.go`:

- `agentSteeringRoutes` -- the routes an agent holding `api:tasks:write`
  may call on another task only when that task's grants, reads, writes
  and network access are within its own: `PATCH /api/tasks/{id}`,
  `brief`, `compact`, `rollover`, `requeue`, `messages`, `notes`, and
  since #1398 the nine halting routes (`close`, `stop`, `pause`,
  `defer`, `park-until`, `resume-later`, `wait-on`, `depends-on`,
  `withdraw-approval`);
- `agentTaskWithin` and `agentCoversGrant` -- the containment test
  itself (capabilities, api scopes, bound secrets, reads, writes,
  network);
- `agentGrantDangerous` -- which grants are always wider;
- `childOf` and `related` -- the parent/child exemptions;
- `untrustedAgentInputNotice` -- the marker a narrower sender's note
  carries into a wider task's run.

The 2026-11-10 task-grant-escalation audit's path 4c (an agent steering
a sibling task that holds wider grants, high) was closed by this file;
the 2026-11-11 review's finding 1 (brief / compact / rollover) and
review 5271's finding (the halting routes, #1398 this range) were fixed
in it. `tests/security` asserts only the PATCH prompt-steering case
(`TestPath4KnownGapAgentCrossTaskPromptSteering`) and the response
shapes of the mutations; every other refusal the rail makes is asserted
only in `pkg/ui/agent_cross_task_test.go`, which is not on the list
either.

**Failure mode.** An agent task filed by a role holding `tasks:write`
with auto-merge on this repository -- or any contributor whose pull
request is set to auto-merge -- can, with no security review filed,
remove a route from `agentSteeringRoutes` (say `close`, or `wait-on`),
or make `agentTaskWithin` return `""` for some class of grant, and
delete the matching case from `pkg/ui/agent_cross_task_test.go`. The
pull request touches two unclassified files; `Classify` returns nil;
`securityhold.go` records `LinkTrustBoundaryCleared` and leaves
auto-merge on; `tests/security` still passes (its one rail assertion is
the PATCH case). The every-PR code review (`.grain/triggers/every-pr.yml`,
`human: on-findings`) is the only review that sees it, and it is a
general review, not the security one the list exists to file. Once
merged, any `api:tasks:write` holder on a repository can again close,
park or re-prompt a task there that a person approved with wider grants
-- the 11-10 path 4c and the 11-11 finding, reopened without a hold.

**This range.** #1398 (`224e04b90`) changed this file and was held and
reviewed only because its third file is
`tests/security/agent_api_task_write_scope_test.go` (the `tests/security/`
prefix). Had it carried its change in `pkg/ui/agent_cross_task_test.go`
alone -- as the three 11-10 fixes to this file did -- the hold would not
have fired. The change itself is a tightening and is sound (read below).

**Reproduced.** A throwaway test calling `trustboundary.Classify` on

## Examined and found sound

- **S3 operator bypass** (#1882, `POST /api/tasks/{id}/qa/bypass-s3`).
  Route scope `internal` (no agent scope reaches it); `humanRouteScopes`
  `merge:write`; `checkDelegatedPersonOnly` refuses a delegated app;
  `roleStandingTargetEscalation` runs `roleTaskWithin` for a limited
  role; and the handler itself refuses any actor that is not a direct
  human. `BypassS3AndOpenPullRequestForTask` re-reads the task, refuses a
  closed one, pins the branch head to the `head` the person reviewed
  (`matchesPinnedHead`, 7+ hex), refuses a commit that is not actually
  blocked (`isS3BlockedForCommit`), promotes the staging branch, records
  a `QACheckIDS3OperatorBypass` run with the person and reason, and
  calls `AwaitPersonForAutoMerge` -- the bypassed change never merges
  unattended. `handleRecordTaskQACheckRuns` (the sandbox-side recorder)
  now refuses a `bypassed` verdict or the bypass check id, so the
  override cannot be forged through the recorder; that recorder already
  refused agent principals. `mutating_routes_test.go` attributes the
  bypass to its person; `delegation_test.go` asserts the 403.
- **Staging-branch CI scope** (#1882). `SandboxNamespaceScope` sets
  `TaskStageBranch` to `QAStageBranchName(taskID)` -- derived from the
  run's own task id, only under an enforced treatment arm -- and
  `Scope.MatchesTaskBranch` admits exactly that ref beside the task
  branch in `cli_actions.go`'s run lookups and superseding-run checks.
  `taskActiveCIBranch` in `pkg/ui/ci.go` picks the stage ref only when
  the resolution is an enforced treatment with staging isolation and the
  ref exists on the remote. No other task's branch becomes reachable;
  the fork-head guard in `RerunTaskActions` still refuses when the head
  cannot be read. `git merge-base` resolution in the sandbox validates
  `baseHint` (`validateMirrorBranchName`) before shell-quoting it, never
  falls back to the root commit (`ErrBaseResolutionFailed`), and the
  daemon lets the PR open under a human hold after three failed attempts
  (`AllowHoldAfterS3Cap`), not silently.
- **QA mirror resolver** (#1869, `pkg/daemon/porter.go`). The
  controller-side mirror clone mints a `qa-mirror-<hex>` git-proxy token
  with `CiReadScopes` on the one repository, and `openMirrorWithSession`
  defers its release (scopes dropped, token revoked) as soon as the
  workspace is open. The mirror runs only `git` on a bare repository
  with `GIT_CONFIG_*` stripped from the environment; repository-defined
  commands run only through `SandboxWorkspace.RunCommand`, in the
  sandbox. Credentials are stripped from the URL before it is used as a
  cache key and redacted from error output.
- **Cross-task halting rail** (#1398). Strictly a widening of what the
  rail covers; the only new exemption, `childOf`, matches a
  `LinkProposedBy` or `LinkChildOf` link on the *target* pointing at the
  acting task. `proposedBy` is daemon-internal: `handleCreateTask`
  refuses it from a signed-in person and `agentAPIGate` from an agent
  (`proposedBy is daemon-internal`), and nothing in `pkg/ui` writes
  `LinkChildOf` from a request body (only `pkg/demo` writes it). A child
  cannot halt its wider parent: the exemption is one-way.
- **Reviewer-head credit** (#1809). The git proxy records each
  fast-forward of a borrowed branch an allowed push makes
  (`RecordReviewedBranchPush`, on the sandbox's live task only when it
  carries `LinkPushesReviewedBranch`); `recordReviewerHead` credits the
  review with the branch head only when one of those pushes reached it,
  or with its own last push when a person pushed on top -- in which case
  the person's commit is classified again before it merges. A push the
  host refused is recorded but reaches no branch, so it credits nothing.
  Fail-safe in every branch.
- **Staging proxy** (#1877, #1847). `setStagingForwarded` keeps the
  inbound `X-Forwarded-For` chain and `X-Forwarded-Proto` (`http`/`https`
  only, single value) only when `relayedByVerifiedEdge` -- a registered
  `IdentityVerifier` accepted the request's assertion, which a direct
  caller cannot mint; otherwise `SetXForwarded` alone. The forwarded
  headers go to the staging app, not into any decision of grain's.
  `stripStagingCredentials` now matches header names with underscores
  read as dashes (CGI collapses them), so `X_Goog_IAP_JWT_Assertion`
  cannot be smuggled past the strip; `stripGrainCookies` filters the raw
  `Cookie` lines by name rather than re-serialising them. Strictly more
  is stripped than before; `tests/security/staging_proxy_credentials_test.go`
  covers both.
- **Rollback-copy reader** (#1846). `readMigratedCopy` `Lstat`s, refuses
  anything but a regular file, opens with `O_NOFOLLOW|O_NONBLOCK`,
  re-checks `SameFile`, and bounds the read at 1 MiB; only then is a
  copy compared and deleted. A planted symlink, FIFO or device is neither
  followed, waited on nor "verified".
- **Forge-command error path** (#1880). Every URL query in a cut body's
  stderr is redacted to `[redacted]` before it reaches a log or the
  agent; a text/html body cut short is an error, not a page. The new
  run-log zip fallback (`ActionsRunLogs`, `JobLogFromRunZip`) reads at
  most 64 MiB per job out of a zip the same caller could already read
  job by job, and caches sibling jobs' logs under the same per-repo cache
  the per-job path uses after the same authorization.
- **Upgrade cancel** (#1851). `stageImage` records the pre-pull image ID
  and on cancel keeps a pre-existing tag only when it still resolves to
  that ID, so `docker pull` moving `:main`/`:latest` onto a newly fetched,
  unverified image no longer leaves it behind under the tag; a cancel
  before the pull begins deletes nothing.
- **Granule re-vendor** (#1884). `pkg/granule` loses its Docker-29

  trigger change moves the `published` filter into the job. `go.mod`
  pins `v0.0.0-20261118222756-8b4787eaef1b`. Identity to upstream not
  verifiable from this sandbox (above).
- **Trust boundary v31** (#1828). Additive: accept-findings and the
