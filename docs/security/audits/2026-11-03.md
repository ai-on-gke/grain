## Findings

Two findings, both reproduced, both filed. Neither is a hole in a gate
that exists; both are places where the day's new hostd surface, and
what it depends on, is not held to the standard the rest of the
boundary is.

### 1. A registered hostd's own allowlist labels can capture label-selected host work meant for another hostd — **Medium**, reproduced

**Who can do what.** The operator of any hostd that is registered in
the hostd registry (`POST /api/hostds`, a `capabilities:admin`
action — so somebody an admin trusted to run *some* work, bound to
their row by IAP owner matching since #542) can, by writing
`labels: {gpu: a100}` into their own machine's allowlist, have every
task whose hostd selector is `gpu=a100` routed to their machine from
its next run on — including tasks a person pinned by that label
because the admin put it on a *different* hostd's registry row. The
run's agent CLI, its prompt, the task's grain token (with all the
task's grants), the staged files and the carried grain endpoints then
land on that operator's machine, where the operator reads and controls
them. The only trace is the attempt's hostd audit
(`task_run_hostd`, shown on the task's attempt), after the fact.

**Where.** `pkg/daemon/hostd_registry.go` `SelectHostd` (`:167`) —
for a label selector it walks `ListHostds`, asks each connected hostd
for `Hello` and merges `hello.Labels` (the hostd's allowlist
`labels:`, `pkg/hostd/allowlist.go:112`) under the registry row's
labels (`:191–:200`), then returns the **first connected** match.
Registry labels only override keys the hostd also claims; a key the
registry row does not set is taken from the hostd unchecked. The
repository's own
`TestLocalAndRemoteHostdsServeTogetherRoutedByPinAndLabel`
(`hostd_registry_test.go:105–106`) pins "the registry's labels, and
the allowlist's" as deliberate, so this is design at the selection
level; what a self-asserted label hands over was not weighed. The
agent gate (`agentMayRouteHostd`) is not involved: the pin is a
person's, the diversion is the hostd's.

**Reproduced** with a throwaway `pkg/daemon` test (not committed) on
`TestLocalAndRemoteHostdsServeTogetherRoutedByPinAndLabel`'s fixture:
registry rows `ws-a` (owner alice, labels `gpu=a100`) and `ws-b`
(owner bob, no labels); `ws-a` not connected; `ws-b` dialing in with
`labels:\n  gpu: a100` in its allowlist.
`cfg.SelectHostd(ctx, store, HostdSelector{Labels: {"gpu":"a100"}})`
returned `name="ws-b", err=nil` — the work went to bob's machine
rather than waiting for `ws-a` (`HostdWaitError`).

**Fix task:** filed (see closing note; title `fix(security): select a
hostd by its registry labels only, never by labels the hostd asserts
about itself`). Suggested fix: in `SelectHostd`, match `sel.Labels`
against the registry row's `h.Labels` alone; keep `hello.Labels` for
display (`/api/hostds`, Settings → Hostds) and, if an operator wants
them honoured, make that an explicit per-row opt-in a
`capabilities:admin` sets (`PATCH /api/hostds/{name}
{"labelsFromHostd": true}`) rather than the default. Regression test:
`pkg/daemon/hostd_registry_test.go`,
`TestHostdSelfAssertedLabelsDoNotSelectIt` — the scenario above
returns `*HostdWaitError{Name: "ws-a"}`, and
`ws-b`'s self-asserted label is visible in its status but selects
nothing. Because the change narrows who may receive routed host work,
it should land held for a person (`hold_for_approval: true`,
`auto_merge: false`).

## Examined and found sound

What was read across the boundary and why it holds, so the next night
can tell what was looked at.

- **`PUT /api/tasks/{id}/hostd` and a filing's `hostd` (#540).**
  `agentFilingEscalation`'s `hostd` case (`agent_api_gate.go`) runs
  `agentMayRouteHostd`, which lets an agent name only `""` or the exact
  normalised selector its own task carries (`Store.TaskHostd`);
  `NormalizeHostdSelector` sorts labels so order cannot evade the
  equality. `tests/security/hostd_routing_test.go`
  `TestAgentCannotRouteWorkToAnotherHostd` pins it. Templates do not
  carry a hostd (`fromTemplate` copies none), `propose_task` and the
  sandbox CLI have no hostd argument, and `PATCH /api/tasks/{id}` is
  limited by `agentTaskPatchBodyAllowed`; so there is no second filing
  path around the gate. A *person* with `tasks:write` may pin work
  anywhere, which is the design.
- **Hostd registry tokens (#473).** Minted with 32 random bytes,
  returned once, stored only as `HashHostdToken` digests; lookup is by
  digest with `revoked_at IS NULL` and a second `Revoked()` check on
  the row; `Rotate` revokes every live token first; `hostd_token` is
  a `LocalTable`, so the state-repo export carries the registry but
  never the digests (`staterepo/dump.go`). The shared `-hostd-token`
  compares with `subtle.ConstantTimeCompare`, and `Identify` refuses a
  registry row that takes the shared token's name (session takeover,
  revocation bypass) and `registryResolver` refuses a row named
  `local`. A revoked hostd still connected is skipped by
  `SelectHostd` and refused by `hostdExecutor` at the next run.
- **Remote hostd identity (#542).** `/api/hostd/connect` is `internal`
  and authenticates in its own protocol; `hostdConnectIdentity` takes
  the principal only from `cachedOrVerifyCaller` (a verified IAP or
  registered-verifier assertion run through `checkAllowedPrincipal`),
  never from a header, and a request that is relayed or off-host to a
  daemon with a verifier but no identity is a *remote hostd with no
  identity*, which `ownerRefusal` refuses rather than falling back to
  the token. `IDTokenEmail` (unverified parse) is used only by the
  hostd CLI to display its own login, not by the daemon.
- **Staging on the hostd machine (#469).** `confined` keeps every
  stage path under `~/.grain/hostd-stage` (resolved through symlinks
  once, then every intermediate component `Lstat`'d and refused if a
  link); `read_tail` and `write_file` open with `O_NOFOLLOW` and
  refuse non-regular files, so the one symlink a run may stage (to the
  machine's codex `auth.json`, and only that exact path) cannot be
  read back to the daemon through `read_tail`; `remove_all` refuses
  the root; `mkdir_all` re-checks for a pre-existing symlink. The
  carried listener binds `127.0.0.1:0` only, and `carriedHTTP` requires
  the exact `Host`, no `Origin`, and a constant-time-compared random
  path segment.
- **`run_host_command` over the mcpserver (#503).** Served only to a
  run holding `grain#host-exec` (person-granted,
  `RequirePersonGrant`) in an `-interactive` session; `Confirm` posts
  the command and takes the first message after it, and
  `MessagesSince` (no `agents=true`) returns `PrincipalHuman` authors
  only — every agent-API, external-token and sandbox-CLI caller is a
  `PrincipalAgent`, and the run's own words are relayed as grain's
  automation principal, so neither can answer. `Decide` is biased to
  refuse. (Its fragility is finding 2, not a hole today.)
- **`package-publish` refresh (#528).** The refresh token is a
  per-run random bearer with a lease of `min(6h, run deadline)`,
  revoked with the lease; `Endpoint.Mount` refuses `/api/` prefixes;
  the route answers `GET` on two paths only and re-mints the *same*
  credential the job already holds (`PackageCredential(registry,
  owner, repo)` of the grant's own repository), so it extends
  lifetime, not reach.
- **CI repository access on `repo#read` / `repo#write` (#475).**
  `RepoAccessAdmitsCIEvent` keeps the retired provider's exact gate
  (`release`, `workflow_dispatch`, trusted `schedule`); reads admitted
  on every event as before; `CheckCIJobRepoAccessPolicy` runs
  `CapabilityPolicy.Permits` with `Untrusted` from the request, so an
  untrusted pull request is refused unless a rule opts it in, even
  with no config at all.
- **`git-push-any-ref` → `repo#write` (#406).** `IsGitPushAnyRefGrant`
  requires `force:true` and both `refs/heads/*` and `refs/tags/*`; a
  narrower `repo#write` opens nothing; the agent gate refuses granting
  any capability ref the acting task does not hold
  (`UncoveredCapabilityRefs`). Observation only: a `repo#write` grant
  carrying an extra `repo` argument beside those is still read as the
  deployment-wide any-ref grant, since the repo argument is ignored —
  no caller produces one today.
- **`GET /api/ci/runs/{id}/log` (#428, #490).** The gate and the
  handler parse the same `gha:<owner>:<name>:<run>` id with
  `ci.ParseActionsRunID`, so the repository the scope is checked
  against is the one the log is fetched for; grain-CI ids keep the
  stored run's `Repo`.
- **`agentCallRepo` hardening (#473).** A body `repo`/`taskId` vouches
  for a repository only on routes whose body type has that field
  (`routeBodyHasField`, reflected through `routeBodies`), and
  `queryCallRepo` checks every repeated or comma-separated `?repo=`
  so an unallowed value cannot ride behind an allowed one.
- **Release approval (#525).** `DecideRelease` checks
  `actor.Kind == PrincipalHuman` before reading anything, so
  `short_soak_ok` is a person's override only; `promote-release.yml`
  carries it as `RELEASE_SHORT_SOAK_OK` from `inputs`, not from the
  event. `patch-tag-guard.sh` (#519) is a new refusal in
  `release.yml`/`promote.yml`, tightening only.
- **GitHub workflows.** No `pull_request_target`, no new `secrets.*`
  in pull-request-triggered jobs, no `${{ github.event.* }}` in `run:`
  lines; the KVM jobs run with `permissions` unchanged.
- **Forge router (#534).** `checkHost` and the GraphQL header check
  refuse sending a request for one host through another host's
  credential — the daemon's own client, tightening only.
- **`-ui-require-iap` (#421) and the allowlist (#481).** Refuses
  startup without an audience; the gcp-key pool accounts are no longer
  on the default allowlist and an explicit entry naming one is
  refused; `trust-boundary/v10` covers the gate's files.
- **State-repo sync (#500, #504, #545).** Warnings and attribution
  only; the import still goes through `ValidateCandidateConfig` and
  `RehearseApply`; a settings write's `note` goes into the commit
  subject, not into anything executed.
- **Merge queue (#535, #485, #444, #415).** No path hands auto-merge
  back on grain's judgement that bypasses `heldForHuman`, which #447
  widened to an agent-declined `auto_merge`.
- **granule resync (#548).** `DialOut` now retries on `ErrAuthFailed`
  with a longer back-off instead of exiting; the handshake still sends
  the sandbox's own id and token over TLS 1.3 and nothing new is
  accepted from the guest. `cgroupmem`, `qcow2`, hypervisor args are
  resource plumbing. `pkg/orchestrator/granule_firewall.go` (#442)
  adds egress fences for open-network pods, tightening only.
- **Attribution (#436, #530).** `Principal.Same` compares kind and
  id, ignoring the new `Source`, so pause/run-now ownership checks
  are unchanged in effect.
