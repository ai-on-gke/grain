# v3.9.0

Released 2026-11-15 from commit `fa4963202`. Changes since `v3.8.0` (`2c9fff5d0`):
https://github.com/ai-on-gke/grain/compare/v3.8.0...v3.9.0

## Highlights

**Breaking changes**
- The retired bare capability names no longer grant anything: `gcp-key` and `gcp-key:<name>`, `gemini-key`, the model proxies, `image-signing`/`registry-push`/`package-publish`, `grain-ci`, `bootstrap-playbooks`, `github-credential:<name>`, `read-issues`, `github-sandbox`, `self-debug`, `local-scripts:<name>` and the rest of the one-release aliases. Templates, schedules, CI jobs and tasks that still name one must declare its canonical grant (for example `grain#ci`, `repo#credential`, `api:self-debug` + `grain#source`). A CI job that declares a retired name is refused with the name to declare instead, and older `grain/config` exports still upgrade on import (#1455, #1546).
- Repository declarations that ask for a named GitHub credential (`repo#credential`) or a widened push (`repo#write` with `refs` or `force`) are now held for a person to accept, as intended, rather than landing approved. A plain `repo#write {repo}` is not held (#1543).
- Repositories listed in `ci_api_repos` can no longer file templates whose API grants reach other repositories or the whole deployment without a person's approval, and need the full `api:release-gate-read` scope set to raise release-pending notifications (#1556).
- Review tasks and gates are renamed: pull request reviews are titled "Code review: …", and a sensitive trigger's template-less review is now a "Targeted review" with its own `targeted-review` merge gate. A force merge that names gates must name `targeted-review` too, though overriding `review` covers it (#1376).
- The `grain/config` export writes plain repository reads and writes once, under `grants:`, instead of also under `reads:`/`writes:`. Expect that diff in `grain/config` after upgrading; releases from v3.8.0 on read it back (#1511).

**Hosts and installs**
- `grain-agentd update` is a new owner-run self-update that installs a newer signed `grain-agentd` release, and Settings → Hosts in `/next/` shows each host's available update (#1533).
- PostgreSQL installs resync their id sequences after bulk imports and on startup, fixing duplicate-key failures after a schema-change rebuild or a state-repository restore (#1502).
- Release `grain` images carry the `io.grain.schema-version` label again, and the host-mode install notice names only `scripts/setup.sh` (#1544, #1510).
- Concurrent VM deletes finish under Docker 29 (#1504), and the Go package cache no longer floods the log with refused read-only writes (#1434, #1547).

**Tasks, reviews and CI**
- Reviewers are given the reviewed task's brief, linked designs and CI guidance (#1475).
- `resume_later` CI waits no longer outlive the repair or backstop that should release them, and `grain health` clears closed ones (#1411, #1507). Stage 1 and base-branch repairs get their repository's default CI grant (#1492).
- A rolled-over task names its successor on its page, row and card in both UIs (#1532). Release-train schedules hold while publishing is held (#1513).
- `comment_on_issue` notes are recorded as comments rather than questions (#1515), and Release hold on a review's findings answers a conflict instead of a server error (#1553).

**The new UI at `/next/`**
- Many `/next/` fixes: pages no longer freeze on a stalled origin, the Inbox and Tasks no longer read a failed task list as empty and give stuck rows their controls, the Timeline draws open tasks to now and saves its view in boards, and the repository page's import, leave and release actions are safer (#1539, #1518, #1452, #1484, #1521, #1522). The standalone Framework API keys card is gone from Settings → Compute & Models: set credentials on each model connection, which never used those keys (#1537).
