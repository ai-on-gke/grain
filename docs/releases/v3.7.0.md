# v3.7.0

Released 2026-11-13 from commit `40b9807f7`. Changes since `v3.6.0` (`754e38d70`):
https://github.com/ai-on-gke/grain/compare/v3.6.0...v3.7.0

## Highlights

**Breaking changes**
- `grain health` now exits 1 whenever it prints a FAILING section (text and `-json`), naming the failing checks on stderr. WARNING and ALERT sections still exit 0. Monitoring scripts that ran it expecting exit 0 should check the status or add `|| true` (#1442).
- Hosts upgraded to this release refuse more environment variables on `clis:` and `capabilities:` entries, even under `env: ["*"]`: variables a child's startup reads to load or run code, such as `JAVA_TOOL_OPTIONS`, `GIT_CONFIG_PARAMETERS`, `GIT_SSH_COMMAND`, `PROMPT_COMMAND`, `PYTHONWARNINGS`, `LUA_INIT`/`LUA_PATH`, `OPENSSL_CONF` and `DYLD_INSERT_LIBRARIES`. Path variables such as `NODE_PATH`, `PYTHONHOME`, `CLASSPATH` and `XDG_CONFIG_HOME` are now refused even inside `paths_under` (`env_deny_v2`). A run that set one of them is refused, and the host's journal names the variable. The daemon sends none of these itself, and older hosts keep the old rules (#1326).
- The git capability built-in moved off the git proxy's port to its own port, 4254. Keep 4254 free on the daemon's machine; `grain health` reports the built-in when it cannot start (#1433).
- Kubernetes installs: `grain.yaml` now ships the `grain-sandbox-network-none` network policy, so `network: none` sandbox pods are actually cut off. Re-apply `grain.yaml` on upgrade to get it (#1457).

**The new UI at `/next/`**
- The Angular UI is now complete at `/next/`, beside the classic UI at `/`, including the director drawer, sessions canvas and model picker. It is the UI new features land in; the classic UI stays for now. Several `/next/` pages were fixed along the way: confirmations for destructive Hosts actions, dialogs that fit a phone screen, CI modes the server accepts, an honest "Not available" on Settings → Upgrade, and repository lists scoped to the instance's own repos (#1347, #1354, #1403, #1450, #1454, #1458, #1459).

**Hosts**
- Drains are more reliable: a run's exit is delivered before a drained host exits, runs a host stop ends are reported as Draining rather than killed, runs abandoned while a host was away at daemon start are cancelled when it returns, and `grain-agentd` can be drained by hand with `-drain` or SIGUSR1 (#1323, #1325, #1385, #1390, #1460).

**Tasks, CI and releases**
- `grain ci retrigger` and `grain ci run-job` can re-run GitHub Actions jobs, and grain files exactly one repair task when `main`'s `tests.yml` goes red on GitHub Actions (#1302, #1291).
- The Inbox now says when the merge queue gives up on a pull request, and a queued task whose blocker only a person can close says so (#1419, #1396).
- Tasks record the template they were filed from, and bug-fix tasks record the release they were found in. Every release gets a release manager task (#1438, #1399, #1290).
- An off-by-default QA control plane with sticky assignment and a settings page was added (#1404).

**Security and secrets**
- Wait targets' closing notes are withheld outside the waiter's repositories, CI-only grants are refused on relayed proposals and at approval, and run-end proposals are held to the sandbox shape maximum (#1303, #1257, #1435).
- A KMS-wrapped secrets key is unwrapped once per daemon process instead of on every use, and `docs/host-setup.md` now explains how to downgrade past the secrets-store credential move (#1335, #1389, #1384).
