# v3.4.0

Released 2026-11-09 from commit `5ff76cf06`. Changes since `v3.3.0` (`545aa3f78`):
https://github.com/ai-on-gke/grain/compare/v3.3.0...v3.4.0

## Highlights

A small release focused on the continuous release train and CI reporting. Nothing needs action on upgrade.

**Release train**
- A red release candidate in Stage 1 (`nightly.yml`) now holds the train the same way a Stage 2 failure does: grain raises `pipeline.rc-failed` naming the failing jobs, posts the `grain/rc-hold` check run, and raises `pipeline.flake-budget`, `pipeline.release-infra-stalled` and `pipeline.release-escalated` where they apply. The train no longer cuts `rc.(N+1)` in the same run that dropped `rc.N`; it waits one run for the hold (#1035, #1039).
- Release notes are now filed automatically: grain watches release tags on repositories that declare `.grain/templates/release-notes.yml` and files one task for each `vX.Y.Z` (or staged `vX.Y.Z-pending`) tag that has no `docs/releases/vX.Y.Z.md` on `main`, so `grain release-notes` and the Upgrade page have notes to show. Tasks it files whose template asks for elevated access wait for a person's approval, and older undocumented tags are skipped (#1038, #1042).
- Scheduled release-train ticks and other `overlap: skip` scheduled runs now close themselves instead of waiting for a person to acknowledge them, so one tick no longer holds up the next (#1040).

**CI**
- `grain ci test-history` now reads GitHub Actions runs on repositories whose CI is GitHub Actions (new `--provider grain|github-actions` flag), instead of reporting a clean history from old grain CI runs. Actions runs count failures only, and the report says so (#1034).
- Promotion workflows skip building the CLI for releases that have no GitHub Release, cache Go builds, and publish CLI archives as soon as a person approves a promotion (#1037).
