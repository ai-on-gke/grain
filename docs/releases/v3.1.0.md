# v3.1.0

Released 2026-11-02 from commit `8a740f996`. Changes since `v3.0.0` (`dc8c85627`):
https://github.com/ai-on-gke/grain/compare/v3.0.0...v3.1.0

## Highlights

`v3.1.0` is the first minor release from `github.com/ai-on-gke/grain`; these notes cover everything since `v3.0.0` (including the `v3.0.1` and `v3.0.2` patch tags).

**Breaking changes and upgrade notes**
- Grain core is now `github.com/ai-on-gke/grain` (Apache-licensed, fresh history). Google-internal pieces live in a separate Google edition that imports core.
- Remote executors are removed (`grain executor`, `/api/executors*`, executor tokens dropped at schema 87, Settings → Executors). `grain hostd` is the only host agent, and it can now dial in to a controller it can't be reached from, including on Kubernetes.
- The config repository is the only API write path for non-bootstrap settings. UI editing is on by default, with an opt-in `settings_locked`. Config-repo PRs are held for a person's Submit, and a refused UI edit can open a validated, held config PR.
- Legacy in-process capabilities are retired onto `api:` presets (`dispatch-control`, `pipeline-control`, `self-upgrade`, `test-quarantine`, `team-broadcast`, `memory`, `release-notes`, `deployment-health`) or in-process methods (`self-repair` → `grain#host-exec`, `grain-log` → `grain#journal`, `db-read`/`db-write` → `grain#sql-read`/`grain#sql-write`, `git-push-any-ref` → `repo#write`). Stored task and CI grants are rewritten automatically. In-tree capability servers (`grain capability gcp`, `git`, `model-proxy`, `config-map`, `gchat`, `host-script`) ship alongside the credential-minting capabilities (`gcp-key`, `gemini-key`, `package-publish`, `registry-push`, `image-signing`, `github-token`, `repo-read`, `repo-write`), whose bare-name grants stay in-process in `v3.1.0` while their retirement follows.
- The sandbox image contract is v2: images must carry the in-sandbox `grain` CLI, and stale stock image pins are flagged.

**Sign-in and identity**
- IAP sign-in: a verified IAP assertion admits a person without the access code. `-ui-allowed-principals` (`user:`/`group:`/`domain:`/`serviceAccount:`) narrows admission, and people who aren't admitted get a refusal page that names them.
- `-ui-require-iap` turns off the access code over the network, with loopback as break-glass.
- The `IdentityVerifier` seam lets an edition plug in its own signed-proxy verifier.
- Operator attribution (partly landed): verified principals show in the user tile (`GET /api/auth/user`, with IAP log-out) and are recorded when filing, commenting, approving, and closing or reopening tasks, with comments and closes/reopens (including grain's own closes) shown on the task timeline. Distinguishing access-code actions from verified sign-in when `-as` matches the owner, `GET /api/whoami`, and per-person attribution across every remaining action follow.

**Merging and CI**
- Clean and green means merge: the merge walk no longer orders PRs, so one stuck PR doesn't hold the others. Merge batching is removed, and the overlap re-check is optional per repo (`merge_recheck`).
- GitHub Actions CI (`ci_mode: github`): the test, scheduled, release, image and promote workflows are ported, with path filtering and `workflow_dispatch` job selection. Concluded workflow runs can trigger schedules and release triage.
- `grain ci list/show/log` and `ci:read` cover GitHub Actions runs, jobs and logs, with no credentials in the sandbox.
- CI steps reattach across a grain restart. Retry merge works in bulk from the batch actions bar.

**Tasks, sessions and the UI**
- Numeric task priorities (default 5, higher first), inherited by child tasks, and editable in Bulk edit.
- A configurable New Task form (`settings/new-task-form.yml`), filing from templates, and a toast naming the default grants that were left off.
- GitHub issue import: open issues become tasks, unapproved by default.
- Fork PR heads (`owner:branch`) are accepted, and a task's external PR shows on its page.
- Warm interactive sessions (`keep_running`) keep their sandbox between turns, and active console sessions can update permissions and parameters without a config-repo change.
- Director sessions get a writable config-repo checkout, and `propose_config_change` with approve and reject reserved for people.
- Inbox sections are collapsible, with Notifications collapsed by default.

**Agents and capabilities**
- The in-sandbox `grain` CLI replaces most read and introspection tools: `grain log --source/--priority`, reading another task's CI with `--task`/`--ref`, `src://` for core's source, and `grain cap` for sandbox-callable capability tools.
- The generated agent API is served to external agents over MCP/HTTP.
- The capability catalogue (`settings/capabilities.yml`) and capability policy are enforced when filing, and shown in grant pickers.
- Extension seams for editions: `capability.Register`, hostd built-in entry registration so upgrades add an edition's hostd entries, and `pkg/change` for tasks backed by external changelists.
- SSH commit signing for ambient git credentials.

**Deployment**
- A GKE deployment script, overlays and Terraform, plus a migration from a local install to a GKE controller with a local hostd.
- A sandbox-access mTLS acceptor with per-sandbox credentials for `kubernetes-granule`.
