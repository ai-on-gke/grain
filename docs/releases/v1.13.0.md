# v1.13.0

Released 2026-10-18 from commit `82945c620`. Changes since `v1.9.0` (`adea62d8f`):
https://github.com/ai-on-gke/grain/compare/v1.9.0...v1.13.0

## Highlights

- **First release with working single-tenant mode.** A fresh Workstation install (a wrapper distribution's own installer) runs single-tenant: everyone, localhost included, signs in with the deployment's access code (`grain access-code`), with no accounts or passwords. Tenancy stays single across installer re-runs and upgrades (sticky tenancy) (#3981, #4001, #4006, #4120).
- Git connections per team: github.com PATs, GitHub Apps, and GitHub-on-Prem (`git.example.com`) through the host's `forgecli` login. Forge and git traffic for forgecli-only hosts goes server-side, and depot git uses Basic auth (#3899, #3902, #4115, #4126).
- Host-qualified repositories (`git.example.com/owner/name`) work across the UI and API, and the Repos page picker discovers them from your connections (#3980, #4080, #4121).
- Grain CI jobs check out the repository with the team's own git connection (#4132).
- Scheduled workflows fire again on Postgres deployments (#4116).
- An ENOKEY from a `/opt/corp/bin` tool is reported as "corp credentials expired: run corp-login" (#4135).
- Known gaps, fixed on `main` for the next release: per-model usage pauses (#4128) are not included. Over plain `http://<host>:4242` the Models "New connection" button does nothing (use the `*.proxy.corp.example` URL or an ssh tunnel). On a fresh install the default model may not be one the seeded connection serves: pick a model or add a connection.
