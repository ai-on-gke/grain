# v1.7.0

Released 2026-10-04 from commit `a9469b26f`. Changes since `v1.6.0` (`d49c62ef1`):
https://github.com/bwsalmon/grain/compare/v1.6.0...v1.7.0

## Highlights

- **Path triggers and sensitive paths.** A repository can declare a template that runs when a merge or pull request touches given paths, and name paths that need a named approver before a change to them merges. Merged design-doc changes are planned through such a trigger, with an in-repo ledger.
- **Teams own their connections and models.** Provider connections and models are strictly per team, and a team's connections no longer fall back to the deployment's key. A task whose team has no connection says so while it waits, and New task only offers repositories the chosen team's credential can reach.
- **Upgrades can target any branch.** The upgrade dialog lists the standard targets in a drop-down and lets an admin type any other branch, and every branch gets its own image tag.
- **Release notes in the tree.** Every promoted release writes `docs/releases/v1.{X}.0.md`, and the daily cut now counts its cadence in release days, so a late cut no longer skips the next day.
- **Admin and security.** The Admin pane has an Authentication section, operators can widen admin-only capabilities to more teams, a task's security hold links its review, and the git proxy enforces the push ref check in production. Signed identity assertions are verified rather than trusted as plaintext headers.
- **Fixes worth noticing.** Templates and schedules carry `nothing_needed_action` onto what they file. The UI says "Can't reach grain" when it loses the server, asks a browser whose session was revoked to sign in again, keeps an edit when its save is refused, and marks blocked tasks as blocked on the timeline. Re-running `grain init` no longer deletes the admin password and exits 0 once the deployment is up.
