# v3.6.0

Released 2026-11-12 from commit `754e38d70`. Changes since `v3.5.1` (`4e29f7be9`):
https://github.com/ai-on-gke/grain/compare/v3.5.1...v3.6.0

## Highlights

**Upgrade notes**
- Kubernetes sandbox deployments (`-sandbox-backend=k8s` or `k8s-granule`) now refuse external capability grants on open-network sandboxes unless `-k8s-network-policy` is set to confirm that the cluster's CNI enforces `NetworkPolicy`, matching container sandboxes. `deploy/kubernetes/grain.yaml` and `grain-granule.yaml` now embed the `grain-sandbox-egress` `NetworkPolicy` blocking cluster and metadata-server egress, so re-apply the manifest when upgrading a cluster (#1139).
- Plain-text capability-server credentials stored in `env` or `headers` move into the secrets store (`capability-server-<id>/<field>`, rewritten to `$secret:<name>`) when the daemon starts, and `grain state check` now fails configuration pull requests that add or change literal capability-server credentials (#1138).
- Image publishing in `release.yml` now checks that every commit since the previous published image reached `main` or `release/v*` through a reviewed merge — either merged by an account listed in the `GRAIN_MERGE_LOGINS` repository variable or carrying a non-author forge approval — unless `REQUIRE_REVIEWED_MERGE=false` is set (#1099).
- Store migrations advance the schema automatically at startup; downgrading to an earlier build requires `grain upgrade rollback` or a database backed up before the upgrade.

**Upgrades, releases and merge identity**
- In-progress upgrades can be cancelled before cut-over from Settings → Upgrade or with `grain upgrade cancel` (including during a configurable `-upgrade-grace-window` countdown on manual upgrades), and completed upgrades offer a one-click roll-back (`grain upgrade rollback`) to the previous build (#1226).
- Deployments using `autoUpgradeOn: release` now enforce a minimum interval between completed release-triggered upgrades (`autoUpgradeMinIntervalHours`, default 6 hours, under Settings → General → Updates) so frequent releases do not drain a deployment back to back (#1161).
- Host-image and Kubernetes upgrades can verify with `-upgrade-reviewed-merge-repo` (including GitHub Enterprise repositories at `host/owner/name`) that an image's commit reached `main` or `release/v*` through a reviewed merge before running it (#1099, #1179, #1221, #1251, #1258).
- Git connections can configure a dedicated `merge_credential` (such as a GitHub App) so grain merges under its own identity while keeping clone and push on the primary credential; `grain health` warns when `GRAIN_MERGE_LOGINS` names a personal account, and command-backed push credentials refuse silent merge-token fallback (#1215, #1256).
- Inbox release approvals can be signed with a Cloud KMS key via `-release-approval-kms-key` so the private key never leaves KMS (#1134). Release images are signed with cosign `v3.1.4` in legacy bundle format so existing deployments still verify them (#1253), and the Go toolchain was bumped to `go1.26.11` for `GO-2026-6859` (#1252).
- Stage 1 qualification now requires `kvm-sandboxes`, `kvm-route-stress` and `real-kubernetes` (#1238), skips the scheduled `main` nightly when an RC ran Stage 1 in the past 24 hours (#1177), and raises `pipeline.release-loop-idle` when 3 hours pass with releasable changes and no qualifying RC (#1175).

**Hosts and `grain-agentd`**
- Signed static `grain-agentd` binaries and Ed25519 manifests for `linux/amd64` and `linux/arm64` are published with each release and served by the controller for offline host installs (#1159).
- `grain-agentd install` and the new `grain-agentd allow <name>` fetch starter allowlist templates from the controller, and host allowlists now accept `env: ["*"]` (excluding identity and injection variables), `~/` paths, `logins:` maps and `x-*` annotations (#1156, #1157, #1178).
- Host self-upgrades now hand live detached CLI runs over in place instead of draining or killing long runs, runs stopped at a drain cap are recorded as interrupted rather than failed, and hook policy is staged per run so detached runs keep evaluating hooks across daemon restarts (#1158, #1173, #1264, #1287).

**Tasks, reviews, schedules and templates**
- Durable tasks can roll over to a fresh successor (`grain rollover <id>`, or automatically past 500 runs, 2,000 comments or one year), carrying over the current brief, handover, open pull request, notifications and dependents (#1151). Reopening a task delivers comments left while it was closed (`grain comment -reopen` reopens and comments in one step, #1172), and console sessions acting for a verified person can answer a parked question on their behalf with `grain task message <id> --relay` (#1217).
- Runs whose outcome needs a person to act are now instructed to finish with `ask_question` and a step-by-step checklist rather than a closing note, and `comment_on_issue` accepts a one-line `summary` shown in the Inbox and task list (#1218).
- Gating path triggers now file one findings-only review per pull request head and review template (with debounced incremental re-reviews on new pushes) and run at the priority of the change they gate with a priority-7 floor (#1129, #1288). This repository also adds a catch-all gating PR review trigger (#1229).
- Templates can declare default `sandbox:` sizes (`cpus`, `memory-mb`, `disk-gb`), bounded by new deployment and per-role `sandboxShapeLimits` ceilings (#1143, #1269). Schedules can set `skip-when: publishing-held` to hold firings while base-branch publishing is under triage (#1209), and `.grain/` declaration files with fields newer than the running daemon are held back individually with a health and Inbox notice instead of blocking the whole repository's declarations (#1211).

**UI, CI and security**
- A preview of the new Angular UI is served alongside the classic UI at `/next/`, starting with the Inbox (`/next/inbox`), backed by live `/api/events` updates for notifications and host-script approvals and an inline branch diff preview (#1164, #1233).
- Task detail pages load recent comments and runs first and fetch older history on demand ("Show earlier") (#1162). System → Health and the CI pane highlight stale schedules (#1213), and Grain Hub deployments adopt their hub entry's name as their default environment badge (#1150).
- Tasks on GitHub Actions repositories now receive read-only `api:ci-read` on their target repository by default, `request_access` refuses `grain#ci` there in favour of `api:ci-read`, the merge queue re-runs failed Actions jobs after runner DNS outages instead of spending PR repair attempts, and `resume_later` CI holds survive runs that end in an error (#1185, #1194, #1212, #1262).
- Trusted Grain CI jobs on reviewed branches populate the shared Go build cache while task sandboxes are restricted to read-only access (#1230, #1261). Agents holding `tasks:write` or `dispatch:write` can no longer steer, re-brief, compact or roll over sibling tasks with wider grants (#1142, #1276), removed target repositories immediately stop live proxy pushes and pending auto-merges (#1193), and PostgreSQL stores verify the single-writer lease on every write transaction (#899).
