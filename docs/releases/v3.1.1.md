# v3.1.1

Cut 2026-11-03 from commit `0e5f0baf3`. Changes since `v3.1.0` (`8a740f996`):
https://github.com/ai-on-gke/grain/compare/v3.1.0...v3.1.1

## Highlights

- **A patch release of the `trigger:` schedule import fix.** `v3.1.1` is `v3.1.0` plus one
  commit from `main` (#545), cherry-picked unchanged with `-x`, and nothing else. It was cut by
  `scripts/release-patch.sh` as `docs/release-candidate-management.md` section 9 describes.
  - `v3.1.0` could not import a state dump holding a schedule whose cadence is
    `trigger: {github_workflow_run: ...}`. The importer never looked for the `trigger` key, so
    the schedule arrived with no `recurrence_kind` and `grain state check -migrate` (the
    upgrade's schema check) failed with
    `NOT NULL constraint failed: schedule.recurrence_kind`. A deployment with such a schedule
    could not upgrade to `v3.1.0` without first removing or converting it.
  - The keys the exporter writes and the importer reads are now one list, which includes
    `trigger`. A round-trip test now covers every recurrence kind, and a test fails when a kind
    is declared without being added to that list.
- **How this release was qualified.**
  - The pick's range-diff against `65b9f5b0a` is empty apart from the `(cherry picked from
    commit ...)` line.
  - `go test ./pkg/staterepo/... ./pkg/workflows/ ./pkg/model/` passed on the release tree
    `0e5f0baf3` (task 2658), and `scripts/patch-tag-guard.sh v3.1.1` accepts it as cut on
    `release/v3.1.1` from `v3.1.0`.
  - The release workflow (`release.yml`) on `release/v3.1.1` and the long suites are run by a
    person before tagging. The pick touches only `pkg/staterepo/decl.go`,
    `pkg/model/schedule.go`, `pkg/workflows/recurrence.go` and tests.
