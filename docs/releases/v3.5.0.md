# v3.5.0

Released 2026-11-11 from commit `c078507ab`. Changes since `v3.4.0` (`5ff76cf06`):
https://github.com/ai-on-gke/grain/compare/v3.4.0...v3.5.0

## Highlights

**Breaking changes**
- Upgrades now pull container images only from OCI registries; the release-assets image source is gone, along with its selector on the Upgrade pane. Existing units that pass `-upgrade-image-source=release-assets` or `-upgrade-image-fallback=release-assets` still start, with a deprecation warning. A unit still carrying a release-asset-era `-upgrade-image=<edition>/grain` (no registry host) is now refused, and the Upgrade pane warns about it before you press Upgrade: set `-upgrade-image` to a registry-qualified repository, or remove it to use the build's default, and re-run the installer (#1061, #1064, #1125).
- GitHub credentials, repository tokens, the release-approval key and the sandbox-access and package-cache CA bundles move into the secrets store when the daemon starts, and the old files are renamed `<file>.migrated`. To downgrade to an earlier build, set `GRAIN_GITHUB_CREDENTIALS=files` first so they are written back to files. A secrets key wrapped with Cloud KMS has to be unwrapped (`grain state key unwrap`) before a downgrade (#1105, #1108).

**Upgrades and editions**
- The Upgrade pane only offers this edition's images. Moving to another edition's image is now a deliberate "Switch edition…" step, which lists what the switch gives up and asks for confirmation. Editions can also add their own notices to the pane (#1128, #1144).

**Secrets and access**
- The secrets key can be wrapped by a Cloud KMS key (`grain state key wrap -kms <key>`), and terraform/gcp deployments do this by default. Settings → State shows how the key is protected (#1080, #1105).
- `request_secret` can no longer name grain's own credentials (#1108, #1132).
- The daemon can serve its API on a unix socket that records each caller by host account. After signing in through IAP or a proxy, `grain login` now keeps a personal token (#1112).
- A verified admin can change other people's dangerous and deny roles. Role grant ceilings now apply to task edits, access requests, merges, sessions and external `gma_` tokens. This release also closes several credential-exposure and sandbox-to-host gaps found in security reviews (#1054, #1091, #1093, #1098, #1107).

**Grants, reviews and merges**
- Grants are now stored as canonical `api:` and repository references, and existing grants are migrated. `grants:` is accepted as the unified spelling beside `capabilities:` in `.grain` templates and schedules. Repository reads and writes show up in the grants picker (#944, #1051, #1052, #1117).
- A repository declaration's grant set can be accepted once instead of approving every firing (#1101).
- Reviews are now a merge gate separate from Submit (#1073).
- Changes to `grain_config.json` in an external config repository are judged by the columns they change, and `require_verified` is stricter about what counts as verified (#1086).

**Durable tasks, schedules and skills**
- Durable tasks can compact their context on purpose and keep a current brief. Their task pages show Compact, the brief and stale handovers (#1135, #1147, #1149).
- Schedules can share an overlap group across a repository, so related schedules never run at the same time. A workflow schedule can run on grain CI in a `ci_mode: github` repository, and a firing starved in the queue is now reported (#1058, #1074, #1127).
- `SKILL.md` folders in a repository are discovered at run start and indexed. Settings → Repositories gains a Skills column (#1066).
- A deployment can offer grain's API to CI jobs in more repositories through `ci_api_repos` (#1118).

**Release train and images**
- The release train now runs as a continuous loop. Every rc that passes Stage 1 is released and the next rc is cut straight away; a red rc is dropped and replaced from a newer known-good commit. A red Stage 1 files exactly one priority-9 repair task (#1045, #1154).
- Release images are blocked when they have fixable critical or high vulnerabilities, and the guest's packed root filesystem is scanned too. The bundled tools, cosign and the docker CLI were bumped past known CVEs (#1059, #1109, #1114, #1116, #1131).
- The Grain Registry is now called the Grain Hub. Settings → Hub saves under `hub` and still accepts `registry` with a warning. Hub errors now blame the hub, not the daemon, when the hub is unreachable (#1007, #1049, #1095, #1100).

**UI and CLI**
- Links straight to a single task comment (`/tasks/<id>#comment=<id>`) now work, and Inbox question rows open on the comment they are parked on (#1053, #1084, #1097).
- Paged lists in the UI, the agent API and `grain mcp` no longer drift or repeat rows (#1102, #1120, #1121).
