# v2.1.0

Released 2026-10-22 from commit `19c5923e6`. Changes since `v2.0.0` (`cf5f64900`):
https://github.com/ai-on-gke/grain/compare/v2.0.0...v2.1.0

## Highlights

- **Two daemon images.** Each release now publishes `ghcr.io/bwsalmon/grain/grain` (the core
  build, `./cmd/grain`, for the `oss` install track) and `ghcr.io/bwsalmon/grain/google-grain`
  (the wrapper distribution's build, a wrapper distribution's `cmd/grain`, for the `google` track). They are built from the same
  commit and share the `guest` and `k8s-sandbox` images. The release stops before building if
  its ghcr.io token can't write packages.
- **Agents can wait on other tasks.** A running agent can wait for another task to finish with
  the new `wait_for_task` MCP tool.
- **grain/config mirroring is back.** The state repository can again be mirrored to an external
  Git repository.
- **Live Go test progress in CI.** Go test runs stream their progress and heartbeats while they
  run.
- **Fixes from main, ported to candidate before the release** (approved by the owner):
  - `/etc/grain/image.env` is kept in sync on host-mode upgrades (5961826e7, ported as
    e7c4a6dfc in #4383).
  - Page headers get their padding, typography and section icons back (c14fc7047, ported as
    f61b5e78d in #4383).
  - Board and tree UI fixes: un-sectioned report boards no longer show move handles or empty
    section notices, single-card columns have no no-op handles, and deep task trees scroll on
    phones (ea3ec549a, ported as af122a620 in #4373).
  - The UI e2e daemons use ephemeral sandbox ports, so parallel Playwright workers no longer
    collide (bbbca5c9b, ported as e3a399144 in #4325).
- **Other fixes.** Several board, Kanban, tree and inbox UI fixes. Handover and resumed-prompt
  trimming. Tasks held back by quota now show why they are waiting. Branch salvage in repair
  runs is guarded. Per-repo CI git credentials are honoured. Merges fall back to squash or
  rebase when the repository disallows merge commits. The default branch is created on the first
  push to an empty repository.
- **How this release was qualified.**
  - The pull-request suite (`tests.yml`) passed at `19c5923e6` in run `4e7394e1b21afc09`:
    frontend, go, go model, go orchestrator, go unit, installer (bookworm, hostmode, trixie),
    lint, package cache, postgres, run host, terraform, ui e2e and ui e2e webkit.
  - The release workflow passed at the same commit in run `f0888d6d807e32ed`. Its container e2e
    and installer suites ran before it published `sha-19c5923` of both daemon images.
  - **The candidate gate was skipped (`CANDIDATE_GATE=off`).** `nightly`, `gcp-smoke`,
    `live-agent`, `live-frameworks`, `live-secrets-repo` and `post-reset-e2e` did not run on this
    candidate. Scheduled runs don't fire on the deployment that cut it, and the cutting agent
    could not dispatch them: its sandbox has no `grain` CLI, and its CI tools run only the push
    workflow's jobs. With no runs, the gate read `missing` for every suite and held on the
    required `nightly`. The owner set the condition for skipping the gate: a suite could not run
    for want of a capability, and every suite that did run was green. Both held here.
