# v3.8.0

Released 2026-11-14 from commit `2c9fff5d0`. Changes since `v3.7.0` (`40b9807f7`):
https://github.com/ai-on-gke/grain/compare/v3.7.0...v3.8.0

## Highlights

A small release, mostly fixes. Nothing needs action on upgrade, but hosts benefit from one optional step below.

**Upgrade note: hosts**
- `grain-agentd install` now writes its systemd unit with `KillMode=mixed`. Stopping or restarting a host now signals `grain-agentd` alone, so it marks in-flight runs as interrupted ("the host agent stopped or restarted while the run was going") and puts them back on the queue. Anything left over is then killed, so a stopped or uninstalled host no longer leaks agent CLIs. Existing units keep the old behaviour until you re-run `grain-agentd install -server <url>` without `-join`, with the same `-name` and `-iap-audience` you installed with. The re-run keeps your allowlist, credential and key file (#1469).

**Pull request reviews**
- Each review of a pull request now sees the reviews before it. A re-review of a new head lists the earlier reviews with their verdicts, pushed commits and open questions. Reviews of the same head, such as pr-review running beside the security review, see each other too. This cuts duplicate work and duplicate questions on the same lines (#1474).

**The new UI at `/next/`**
- Destructive actions now ask first. Deleting a saved board, which is shared by everyone on the deployment, needs a confirmation, and same-named boards are told apart. Settings → Upgrade confirms before it restarts grain onto another build (#1486, #1485).
- The Boards menu shows board names in full and stays on screen at phone width. CI Re-run opens the run it started. Links to classic System pages, tab history and restart refusals now work, and more walkthrough defects are fixed (#1486, #1485, #1479).

**Releases and configuration**
- When the release approval KMS key can be read but not used to sign, Approve, Reject and Rollback now return a 502 naming `-release-approval-kms-key`, not a bare 500 (#1461).
- The grain/config export now writes template and schedule repository access as `repo#read`/`repo#write` entries under `grants:`, and still writes `reads:`/`writes:` beside them. Importing the export gives back the same settings (#1447).
