# v3.2.0

Released 2026-11-09 from commit `cba7d44bb`. Changes since `v3.1.1` (`0e5f0baf3`):
https://github.com/ai-on-gke/grain/compare/v3.1.1...v3.2.0

## Highlights

**Breaking changes and upgrade notes**
- Custom command agent connections (`framework: "custom"`) are removed (#645). Stored custom connections are disabled and kept with a `disabledReason` until deleted, and tasks pinned to them fall back to the default model selection; replace them with Antigravity, Claude, or Codex connections (whose CLI path can still point at a custom build).
- Fresh installs now provision and default to a local PostgreSQL database (`grain backup` runs `pg_dump`), while existing SQLite deployments stay on SQLite (#679). PostgreSQL deployments acquire a single-writer lock (#740).
- Remaining legacy capabilities are retired onto capability servers and task settings: `gcp-key` → `gcp#gcp-key {permission_set}` (#493, #662), `gemini-key` → `gcp#gemini-key` (#625), `<vendor>-proxy` → in-process `model-proxy` (#613), `image-signing`/`registry-push`/`package-publish` → in-process `release` server (#614), `local-scripts` → `host-script` with optional per-call approval (#692, #721), `self-debug` → `api:self-debug` + `grain#source` (#767), `bootstrap-playbooks` → `config-map` `bootstrap` (#770), and `console`/`priority-dispatch`/`durable` move onto task `hosting` and `admission` settings (#728).
- `-ui-require-iap` generalises to `-ui-require-verifier` (#742), and open-source container images publish to Docker Hub under `grainai/*` (#739).

**Continuous releases and deployment upgrades**
- Release candidates now qualify through active two-stage suites (`nightly.yml` and `grain/release-qualification`) and promote automatically from `main` without a 24-hour staging soak (#536, #537, #611, #646, #680).
- Releases with breaking changes or major bumps stage for human approval in the Inbox (#526, #607); red RCs hold `rc.(N+1)` on `[rc-blocker]` tasks (#638, #655); operators can retract bad releases and re-point `latest` with Upgrade UI warnings (#610, #664).
- Deployments can opt in to automatic upgrades when a new release is published (#605) and load release-asset image tarballs with registry fallback (#661).

**Hosts, sandboxes, and registry**
- Host management ("hosts" across the UI, CLI, and docs, #759): identity-bound host tokens, enrollment and pairing join requests, `/api/hostd/install.sh`, rootless `grain-agentd`, task/template/repo host defaults, and live CLI detachment/reattachment across reconnects (#473, #540, #541, #542, #549, #550, #551, #598, #754, #768).
- Standalone `grain-registry` catalog, subdomain reverse proxy, and `-registry-connect` outbound tunnels with delegated identity (#736, #741, #755, #762, #792, #793, #798, #803, #805).
- Network fencing for open-network Kubernetes sandbox pods and nftables-fenced container sandboxes (#442, #691), plus Secret Manager and GCS object-store backends (#737, #738).

**Access, CLI, and orchestration**
- Database-backed principal allowlists (including service accounts with recorded reasons), role-gated UI write controls, Settings → Audit, `GET /api/whoami`, delegated GitHub login, and `gma_` external-agent owner trust (#512, #531, #580, #629, #635, #652, #822).
- Named CLI contexts (`grain login`/`logout`/`whoami`), external `grain wait`/`reply`/`inbox`/`logs`, `grain ci wait`/`retrigger`/`test-history`, `grain merge-queue`, single `/api/mcp` controller endpoint, and SSE `/api/events` (#511, #627, #683, #685, #687, #731).
- Runtime `request_access` for repositories, grants, and network (#648), `request_human_review` holds (#758), PR adoption in review-only or finish mode (#682), cross-repo `git_ref` schedule triggers (#624), and higher default merge-lane throughput (#413).

## Breaking changes

- refactor(models)!: remove the custom command connection type (#645)
  - custom command connections (framework "custom") are removed. Stored ones are disabled and kept with a disabledReason until deleted, and tasks pinned to them take the default model selection. Replace each with an Antigravity, Claude or Codex connection; a connection's CLI path can point at your own build of that CLI.
